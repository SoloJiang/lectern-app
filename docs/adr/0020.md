# ADR 0020：token 用量按 MR 和项目两级统计

- 状态：已接受
- 日期：2026-10-16
- 修订：[ADR 0014](0014.md)（统计单位与界面位置）

## 背景

[ADR 0014](0014.md) 按会话和轮次统计 token。2026-10-16 人确认，比起每个会话花了多少，更关心两个数：每个 MR 花了多少（一个改动从开始到合并一共用了多少 token、折合多少费用），以及每个项目花了多少。

会话和 MR 不是一一对应的。一个 MR 通常由多个会话完成：第一次实现、审阅意见发回后的修改、并行 agent 各做一部分。一个会话也可能改到多个分支：agent 的工作目录是一个 worktree，却通过绝对路径修改另一个 worktree 里的文件。所以 MR 级别的统计不能简单地把会话加起来。

## 决策

**统计单位**

统计分两级：项目和 MR。会话和轮次保留为 MR 之下的明细，不再作为主要的汇总单位。

- 项目指 Lectern 里打开的一个项目（[ADR 0006](0006.md)、[ADR 0012](0012.md)）。git 仓库以仓库为准：项目标识是 git 公共目录的规范绝对路径，同一仓库的所有 worktree 属于同一个项目，即使在不同窗口里分别打开，用量也只计一次。不是 git 仓库的普通文件夹以打开的根目录为准，同样是项目，它的用量全部计入项目合计，只是没有分支和 MR 这一级。项目的用量是归属到这个项目的全部用量：它的所有 MR、未开 MR 的分支、「不属于任何 MR」的部分，以及 Lectern 自己发起的分析。有改动的轮次按改动所在的项目归属，改动跨了几个项目时按改动权重（见「归属规则」）分摊到这些项目，不看 cwd；没有改动的轮次跟随同一会话里最近的有改动轮次，项目和分支一起跟随（见「归属规则」），会话里没有任何改动时才按 cwd 所在的项目归属。会话的 cwd 和改动都不在任何已打开项目里时，暂时归入「其他」；之后打开了包含它们的项目，这些用量自动归入该项目。已打开的项目互相包含时（一个普通文件夹里有另一个已打开的文件夹或仓库），每条记录只归一个项目：取包含它的最内层项目，git 仓库优先于包含它的普通文件夹。
- 项目级别按时间窗口统计（7 天 / 14 天 / 30 天），可以按 MR、按 agent、按模型拆分；按 MR 拆分时，每行是这个 MR 在所选时间窗口内的用量；共用同一分支的几个 MR 合为一行，列出这些 MR；「不属于任何 MR」单独一行；各行相加等于项目合计。时间窗口按每条用量记录自己的时间（agent 回复的时间戳）划分，不按会话开始或导入的时间；「最近 7 天」指用户本地时区的今天和之前 6 个自然日，14 天、30 天同理。MR 级别（worktree 列表、简报、MR 视图）显示这个 MR 从开始到合并的累计值，两者在界面上分别标明。
- MR 指一个分支上准备合并的一组改动。已经在 GitHub 或 GitLab 上开了 PR / MR 的，以代码平台上的那个 MR 为准；还没有开的，按分支显示为「未开 MR」，开了之后自动关联。
- 默认分支上的直接改动、detached HEAD、无法确定分支的用量，归入「不属于任何 MR」。默认分支本身是某个 MR 的源分支时（例如 fork 的默认分支向上游仓库开 MR），以 `forge` 报告的 MR 为准，只有 `forge` 没有对应 MR 时才按这一条处理。

**归属规则**

- 有改动的轮次按改动归属：这一轮改了哪些文件，就归到这些文件所在 worktree 当时的分支。一轮改了多个分支时，按权重分摊这一轮的 token，每个分支的权重是改动行数加上改动文件数，所以只换了二进制文件、只改了文件模式或只重命名的分支也分到用量。改动来自 `review` 对轮次的归因结果。
- 没有改动的轮次（阅读、讨论、跑测试、回答问题）跟随同一会话里最近的有改动轮次：先找它之前最近的一个，没有再找之后最近的一个，按那一轮的分支和权重归属。会话里没有任何改动时，按每一轮自己的分支：Lectern 正在跟踪的会话，每一轮结束时（以及每个可能切换分支的工具调用之后）记下 cwd 所在 worktree 的分支和 HEAD，与有改动的观察一起保存，所以 Codex 会话中途切到功能分支后只读代码、跑测试，也归到功能分支；导入的旧会话没有这些观察，用日志里记录的分支（Claude Code 每条记录带 `gitBranch`，Codex 只有会话开头 `session_meta` 里的 `git.branch`）；记录的是默认分支（且 `forge` 没有对应 MR）或没有记录时，归入「不属于任何 MR」。
- 子 agent 会话先按它自己的改动和以上规则归属，再把用量计入父会话的合计（ADR 0014）。子 agent 里没有改动的轮次跟随启动它的那一轮父会话轮次。所以几个子 agent 分别改不同分支时，各自的用量落在各自的分支上。父会话里只负责派出子 agent、自己没有改动的轮次，按它派出的子 agent 的改动权重分摊到这些分支上，不按父会话记录的分支归属。父轮次和它派出的所有子 agent 都没有改动时，整棵子树按普通的没有改动的轮次处理（跟随父会话里最近的有改动轮次，会话里没有改动时用日志记录的分支）。
- 分支按「一次使用」区分，不只看分支名：一次使用从 Lectern 第一次观察到这个分支开始。以下两种情况算新的一次使用，之前那次的用量不并入新的：没有开着的 MR 时，分支被删除后重新创建（reflog 里有新的创建记录，或两次观察之间分支不存在）；没有开着的 MR 时，分支被重置、丢弃了上一次观察到的分支独有的提交（新的历史里既没有这些提交，也没有内容相同的 rebase 后的提交）。还没有提交、只有未提交改动的分支，被观察到回到起点（没有分支独有的提交）而且工作区没有改动时（如 `git reset --hard`、`git restore` 丢弃了全部改动），这次使用结束，之后的改动算新的一次使用。`forge` 仍把这个分支对应到一个开着的 MR 时，本地删除重建也留在同一次使用里。合并默认分支、rebase、强制推送这类日常更新都留在同一次使用里，分支开着 MR 时更是如此。
- MR 的统计区间：在同一次使用之内，从上一个 MR 最终合并或关闭之后（没有上一个就从这次使用开始），到这个 MR 最终合并或关闭为止。MR 关闭后又重新打开时，以最后一次合并或关闭为准：关闭期间分支上的工作与开 MR 之前的工作同样对待，重新打开后并入这个 MR；一直没有重新打开时，关闭之后的用量留在分支上，显示为未开 MR 的分支。MR 的状态变化（打开、关闭、重新打开、合并及其时间）由 `forge` 提供，汇总时按最新状态重新计算。开 MR 之前在分支上的工作也计入，未开 MR 的分支在 MR 开出后整体并入；被放弃的分支（删除后没有开 MR）的用量留在它自己那次使用里，显示为未开 MR 的分支，不并入之后同名的 MR。同一次使用同时开着多个 MR（如向不同的目标分支各开一个）时，用量只计一次。每个 MR 的详情（worktree 列表、简报、MR 视图）显示它自己区间内的用量：几个 MR 同时开着的那段时间的用量在每个 MR 里都出现，并注明与哪些 MR 共用；其中一个合并或关闭后，之后的用量只计入还开着的 MR。Usage 页把共用同一次使用的 MR 合为一行，这一行是这次使用在时间窗口内的用量，项目合计不重复计算。
- Lectern 自己发起的模型调用（如会话简报的分析）归到被分析的改动所属的 MR，标为「审阅」，与 agent 写代码的「编写」分开显示。「审阅」不受 MR 统计区间限制：MR 合并或关闭之后再分析它，用量仍计入这个 MR 的累计值；项目合计照常按调用的时间落在时间窗口里。一次分析覆盖多个分支（如简报分析了改动多个分支的整个会话）时，按被分析的改动在各分支的权重（改动行数加改动文件数）分摊。被分析的会话没有任何改动时，按这个会话没有改动时的规则归属（日志记录的分支，默认分支则归入「不属于任何 MR」）。
- 观察结果在一轮结束后记录：一轮在下一条用户输入出现、或会话结束时视为结束，结束之前读到的部分只作为临时结果，随着日志追加继续更新。每个产生改动的工具调用执行之后（读到它的工具结果时），Lectern 记下那一刻该 worktree 的分支和 HEAD，所以 `git switch feature && 改文件` 这样的命令记到的是执行后的分支。一次调用里分支切换了不止一次（如 `git switch B && 改文件 && git commit && git switch A`）时，Lectern 同时读取这次调用期间各分支 reflog 新增的条目：调用期间新增的提交归到 reflog 里记下它们的那个分支，调用结束时仍未提交的改动归到调用结束时检出的分支（切换分支时未提交的改动随工作区一起带过去）；一轮里切换了分支、改了几个分支时各自记录；每条观察同时记下仓库的稳定标识（git 公共目录的规范绝对路径，以及 `forge` 可用时的代码平台仓库标识），所以 worktree 删除、分支删除之后，重建仍能把这些记录对应到项目和 MR。一轮结束时，这些观察连同会话的 cwd、改动文件的路径、每个改动文件的改动行数（分支和项目的权重都由它算出，普通文件夹没有分支也能按项目分摊），以及各分支当时是否为默认分支，写入 Lectern 的 SQLite，之后不再修改（默认分支改名后，旧的记录仍按当时的分类处理），汇总和重建都以这份记录为准。项目和 MR 的归属在汇总时由这份记录计算，所以之后打开的项目、之后开出的 MR 都能拿到以前的用量。导入较早的会话时，如果改动所在的 worktree 已经删除或换了分支、无法确定当时的分支，这些轮次归入「不属于任何 MR」，并标为「无法归属」。

**分阶段**

- P1、P2：按项目和分支汇总，界面上（包括 P2 的 Usage 页）标为「分支用量」，不称为 MR。`forge` 就绪后（P3）关联到代码平台上的 MR，显示 MR 编号和标题，统计区间按上面的规则切分。
- 离线或代码平台不可用时，按分支显示，不影响统计。

**界面位置**（取代 ADR 0014 的「界面位置」表）

| 位置 | 内容 | 阶段 |
|---|---|---|
| 项目侧栏底部 | Usage 入口显示本项目最近 7 天的 token 与 API-equivalent 费用，以及最紧张的额度窗口进度条（快到上限时变色） | P1（额度条 P2） |
| 并行 worktree 列表与检查器 | 当前分支的累计 token 与 API-equivalent 费用；P1 标为分支用量，P3 起为所属 MR 的用量 | P1 |
| 审阅页会话简报 | 本会话改到的每个分支（P3 起为 MR）各一行：该分支的累计 token，以及本会话在其中的占比；当前审阅的改动所在的分支排第一 | P1 |
| 审阅页每轮标题 | 该轮 token 数（不分摊）；MR 和 Usage 页的明细里，一轮被分摊到多个分支时显示分到该分支的那一份 | P1 |
| 项目主页会话卡片 | 不显示 token | P1 |
| Conversation 面板 | 上下文窗口占用 | P2 |
| Usage 页（按需层） | 额度卡片、每日 token 柱状图（按 agent 堆叠）。当前项目：项目合计，按分支（P3 起按 MR，未开 MR 的分支一并列出）、按模型的明细，均为所选时间窗口内的用量；「不属于任何 MR」（P2 标为「默认分支与无法归属」）单独一行，各行相加等于项目合计；普通文件夹只显示合计。所有项目：各项目的合计与占比，加上「其他」一行（还没有打开对应项目的用量），各行相加等于全部用量；点进某个项目即切到它的明细 | P2 |
| MR 视图 | MR 累计 token 与费用，按会话、按轮次的明细，「编写」与「审阅」分开 | P3 |

数据来源、去重规则、费用计算和额度窗口仍按 ADR 0014。

## 影响

- `agents`：除了原始用量记录，按顺序交出每个产生改动的工具调用的结果事件（时间戳、所在会话与轮次、目标路径），`usage` 据此在每次调用之后采样分支和 HEAD。
- `usage`：在去重和聚合之外增加归属：输入是每轮的用量、`review` 给出的每轮改动、`project` 给出的 worktree 与分支，以及 `forge` 给出的 MR 列表（可选）；读到日志时把每轮的 worktree、分支和 HEAD 一并保存；输出按项目和 MR 两级汇总的快照，会话和轮次作为明细。
- `project_home`：侧栏底部的 Usage 入口显示本项目合计，会话卡片不再显示 token。
- `worktrees`、`review_view`、`usage_view`：按上表调整显示位置。
- `forge`（P3）：提供分支与 MR 的对应关系，以及每个 MR 的状态变化（打开、关闭、重新打开、合并）和时间。
- 交互规范「用量」、路线图、README 同步修改。
