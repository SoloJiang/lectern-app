# ADR 0020：token 用量按 MR 和项目两级统计

- 状态：已接受
- 日期：2026-10-16
- 修订：[ADR 0014](0014.md)（统计单位与界面位置）

## 背景

[ADR 0014](0014.md) 按会话和轮次统计 token。2026-10-16 人确认，比起每个会话花了多少，更关心两个数：每个 MR 花了多少（一个改动从开始到合并一共用了多少 token、折合多少费用），以及每个项目花了多少。

会话和 MR 不是一一对应的。一个 MR 通常由多个会话完成：第一次实现、审阅意见发回后的修改、并行 agent 各做一部分。一个会话也可能改到多个分支：agent 的工作目录是一个 worktree，却通过绝对路径修改另一个 worktree 里的文件。所以 MR 级别的统计不能简单地把会话加起来。

## 决策

**统计单位**

统计分两级：项目和 MR。会话和轮次保留为 MR 之下的明细，不再作为主要的汇总单位。

- 项目指 Lectern 里打开的一个项目，以打开的根目录为准（[ADR 0006](0006.md)、[ADR 0012](0012.md)）。根目录是 git 仓库时，项目包含它的全部 worktree；不是 git 仓库的普通文件夹同样是项目，它的用量全部计入项目合计，只是没有分支和 MR 这一级。项目的用量是归属到这个项目的全部用量：它的所有 MR、未开 MR 的分支、「不属于任何 MR」的部分，以及 Lectern 自己发起的分析。会话的 cwd 不在任何已打开项目里时，归入「其他」。
- 项目级别按时间窗口统计（7 天 / 14 天 / 30 天），可以按 MR、按 agent、按模型拆分；MR 级别统计这个 MR 从开始到合并的累计值。
- MR 指一个分支上准备合并的一组改动。已经在 GitHub 或 GitLab 上开了 PR / MR 的，以代码平台上的那个 MR 为准；还没有开的，按分支显示为「未开 MR」，开了之后自动关联。
- 默认分支上的直接改动、detached HEAD、无法确定分支的用量，归入「不属于任何 MR」。默认分支本身是某个 MR 的源分支时（例如 fork 的默认分支向上游仓库开 MR），以 `forge` 报告的 MR 为准，只有 `forge` 没有对应 MR 时才按这一条处理。

**归属规则**

- 有改动的轮次按改动归属：这一轮改了哪些文件，就归到这些文件所在 worktree 当时的分支。一轮改了多个分支时，按权重分摊这一轮的 token，每个分支的权重是改动行数加上改动文件数，所以只换了二进制文件、只改了文件模式或只重命名的分支也分到用量。改动来自 `review` 对轮次的归因结果。
- 没有改动的轮次（阅读、讨论、跑测试、回答问题）跟随同一会话里最近的有改动轮次：先找它之前最近的一个，没有再找之后最近的一个，按那一轮的分支和权重归属。会话里没有任何改动时，用日志里记录的分支（Claude Code 每条记录带 `gitBranch`，Codex 取会话开头 `session_meta` 里的 `git.branch`）；记录的是默认分支（且 `forge` 没有对应 MR）或没有记录时，归入「不属于任何 MR」。
- 子 agent 会话先按它自己的改动和以上规则归属，再把用量计入父会话的合计（ADR 0014）。子 agent 里没有改动的轮次跟随启动它的那一轮父会话轮次。所以几个子 agent 分别改不同分支时，各自的用量落在各自的分支上。
- 分支按「一次使用」区分，不只看分支名：一次使用从 Lectern 第一次观察到这个分支开始，记下它与默认分支的分叉点。之后观察到的 HEAD 不是上一次 HEAD 的后代（分支被删除后重建、或被重置到无关的提交），或者分叉点变了，就算新的一次使用；之前那次的用量不并入新的。
- MR 的统计区间：在同一次使用之内，从上一个 MR 合并或关闭之后（没有上一个就从这次使用开始），到这个 MR 合并或关闭为止。开 MR 之前在分支上的工作也计入，未开 MR 的分支在 MR 开出后整体并入；被放弃的分支（删除后没有开 MR）的用量留在它自己那次使用里，显示为未开 MR 的分支，不并入之后同名的 MR。
- Lectern 自己发起的模型调用（如会话简报的分析）归到被分析的改动所属的 MR，标为「审阅」，与 agent 写代码的「编写」分开显示。一次分析覆盖多个分支（如简报分析了改动多个分支的整个会话）时，按被分析的改动在各分支的权重（改动行数加改动文件数）分摊。
- 归属在 Lectern 读到日志时确定：每一轮改动所在的 worktree、分支和 HEAD 随归属结果一起写入 Lectern 的 SQLite，之后的汇总和重建都以这份记录为准，不重新推断。导入较早的会话时，如果改动所在的 worktree 已经删除或换了分支、无法确定当时的分支，这些轮次归入「不属于任何 MR」，并标为「无法归属」。

**分阶段**

- P1：按分支汇总，界面上标为「分支用量」，不称为 MR。`forge` 就绪后（P3）关联到代码平台上的 MR，显示 MR 编号和标题，统计区间按上面的规则切分。
- 离线或代码平台不可用时，按分支显示，不影响统计。

**界面位置**（取代 ADR 0014 的「界面位置」表）

| 位置 | 内容 | 阶段 |
|---|---|---|
| 项目侧栏底部 | Usage 入口显示本项目最近 7 天的 token 与 API-equivalent 费用，以及最紧张的额度窗口进度条（快到上限时变色） | P1（额度条 P2） |
| 并行 worktree 列表与检查器 | 当前分支的累计 token 与 API-equivalent 费用；P1 标为分支用量，P3 起为所属 MR 的用量 | P1 |
| 审阅页会话简报 | 本会话改到的每个分支（P3 起为 MR）各一行：该分支的累计 token，以及本会话在其中的占比；当前审阅的改动所在的分支排第一 | P1 |
| 审阅页每轮标题 | 该轮 token 数，作为 MR 明细的最细一级 | P1 |
| 项目主页会话卡片 | 不显示 token | P1 |
| Conversation 面板 | 上下文窗口占用 | P2 |
| Usage 页（按需层） | 额度卡片、每日 token 柱状图（按 agent 堆叠）。当前项目：项目合计，按 MR（未开 MR 的分支一并列出）、按模型的明细。所有项目：各项目的合计与占比，点进某个项目即切到它的明细 | P2 |
| MR 视图 | MR 累计 token 与费用，按会话、按轮次的明细，「编写」与「审阅」分开 | P3 |

数据来源、去重规则、费用计算和额度窗口仍按 ADR 0014。

## 影响

- `usage`：在去重和聚合之外增加归属：输入是每轮的用量、`review` 给出的每轮改动、`project` 给出的 worktree 与分支，以及 `forge` 给出的 MR 列表（可选）；读到日志时把每轮的 worktree、分支和 HEAD 一并保存；输出按项目和 MR 两级汇总的快照，会话和轮次作为明细。
- `project_home`：侧栏底部的 Usage 入口显示本项目合计，会话卡片不再显示 token。
- `worktrees`、`review_view`、`usage_view`：按上表调整显示位置。
- `forge`（P3）：提供分支与 MR 的对应关系和 MR 的存续时间。
- 交互规范「用量」、路线图、README 同步修改。
