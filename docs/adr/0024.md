# ADR 0024：仓库读取用 gix 0.88，行 diff 用 gix 维护的 imara-diff 副本

- 状态：已接受，已被 [ADR 0028](0028.md) 修订
- 日期：2026-10-17

## 背景

[技术调研「技术选型」](../design/tech-research.md#技术选型)选定 gix 读仓库、imara-diff 算 diff（[#14](https://github.com/SoloJiang/lectern-app/issues/14)），但没有定版本、feature 和使用边界。`git` crate 的约束（[crate AGENTS.md](../../crates/git/AGENTS.md)）要求：只读，不写 index 和对象库；不执行仓库配置的任何外部程序；工作区文件只经 `platform` 的安全读取接口读取。gix 默认 feature 带网络、凭据、合并、blame 等审阅用不到的部分，它的部分接口也会按仓库配置启动外部程序（过滤器 driver、外部 diff、textconv、提交签名、编辑器），需要在依赖层面先划清边界。

2026-10-17 实测：gix 0.88.0 加下文的 feature，Linux x86_64 release（thin LTO、strip）的最小程序 3.2 MB；`cargo deny check licenses bans sources advisories` 在本仓库的 `deny.toml` 下全部通过；依赖树里没有 macOS 系统绑定。gix 0.88 起 `gix-diff` 依赖 `gix-imara-diff` 0.3（gitoxide 维护的 imara-diff 修改版，Apache-2.0），通过 `gix::diff::blob` 重新导出。

## 决策

- `gix` 在根 `Cargo.toml` 的 `[workspace.dependencies]` 里用 `=0.88.0` 精确锁定，`default-features = false`，只开 `sha1`、`sha256`、`index`、`revision`、`attributes`、`excludes`、`dirwalk`、`blob-diff`、`pack-cache-lru-static`、`pack-cache-lru-dynamic`。不开网络、凭据、`status`、`worktree-mutation`、`merge`、`blame`。升级单独提 PR，跑完 `lectern-git` 的测试和 git 基准后合并。
- `parallel` 有意关闭：不开 `max-performance-safe`（它经 `max-control` 打开 `parallel`），只取其中的两个 pack 缓存 feature，gix 因此不自己创建线程，后台线程只由 `executor` 管理。0.88 的 zlib（`zlib-rs`）和 SHA 实现（`sha1dc`、`sha2`）不受这些 feature 控制，不变。代价是 gix 的仓库句柄不再是 `Send`（内部用 `Rc` / `RefCell`，2026-10-17 编译验证），所以 `git` 的公开类型不持有 gix 句柄，gix 句柄只在一次调用内、在调用它的线程上打开和使用，不在调用之间保留（见设计文档「数据流与线程」）。
- 行 diff 和词级 diff 都用 `gix::diff::blob` 导出的 imara-diff（`gix-imara-diff`），算法 Histogram。不再单独依赖上游 `imara-diff`：两份实现同时进入二进制没有收益，版本随 gix 一起升级。
- 只有 `lectern-git` 直接依赖 gix；对外的类型（对象 ID、改动、hunk）由 `git` 自己定义，不暴露 gix 的类型，升级 gix 时只改这一个 crate。
- 使用边界（关键约束）：
  - 打开仓库时 `git_binary` 权限保持关闭（gix 不为找安装配置去运行 `git`）；`GIT_*` 环境变量不生效，仓库位置只由 Lectern 传入的路径决定。`git` 不读任何环境变量；需要尊重的 `GIT_CEILING_DIRECTORIES` 由 `project` / `app` 从进程环境读一次、解析后作为参数传给发现函数（[project 设计](../design/project.md)）。
  - 构造过滤和 diff 管线时 driver 列表为空，不调用会按仓库配置装上外部 driver 的便捷接口（`Repository::filter_pipeline`、`Repository::diff_resource_cache` 及以它们为基础的接口）；不调用提交签名、编辑器等会启动程序的接口。
  - 工作区与 index 的比较不用 gix 的 `status`：它按路径打开工作区文件，绕过 `platform` 的安全读取。比较由 `git` 自己实现，gix 只提供 index、属性与忽略规则、内置转换、目录遍历和对象读取。
  - 工作区一侧的内容需要以对象形式交给 gix（如重命名的相似度计算）时，只放进 gix 的内存对象存储（object memory），不写进对象库。

放弃的方案：

- `git2`（libgit2）：C 依赖，构建和体积都更重，同样要自己关掉过滤器和外部 diff。
- 调用 `git` 命令行：每次刷新都启动进程，违反「按需启动、空闲即关」的取向（架构规则 3），还要逐项关闭 fsmonitor、过滤器和外部 diff；只作为以后复杂写操作的后备。
- 上游 `imara-diff` 0.2：与 gix 内部的副本重复。

## 影响

- 根 `Cargo.toml`、`crates/git/Cargo.toml`；接口、比较算法和测试由 [git 设计文档](../design/git.md)负责。
- `platform` 提供与平台无关的安全读取接口（[ADR 0019](0019.md) 已列出），`git` 只调用它。
- 体积约 3 MB，计入 [ADR 0018](0018.md) 的 80 MB 安装包预算；首帧之前不打开任何仓库（[ADR 0017](0017.md)）。
- `just deny` 覆盖新增的传递依赖，均在允许列表内。

## 已知限制

- gix 0.88 不支持 reftable 引用存储（`extensions.refStorage=reftable`），这类仓库按「不支持的仓库格式」处理。
- 部分克隆（partial clone）缺失的 blob 不联网补取，对应文件标为内容缺失。
- 未跟踪文件的遍历和忽略文件的加载用 gix 按路径的遍历，不经 `SafeRoot`：遍历期间目录被换成符号链接（TOCTOU）不在威胁模型内，只有以用户身份运行的进程能做到；符号链接本身作为条目报告、不跟随，文件内容仍经 `SafeRoot` 读取。
