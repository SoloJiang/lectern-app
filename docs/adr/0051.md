# ADR 0051：tool 层 crate 实现 `Plugin` 不算插件 crate，不加 `plugin = true`

- 状态：已接受
- 日期：2026-10-25
- 修订：[ADR 0025](0025.md)「决策」第 1 条中「实现了 `Plugin` 的 crate 必须带标记」的检查范围

## 背景

ADR 0025 规定：插件 crate 是实现 `kernel::Plugin`、由 `app` 放进 `PluginSet` 的 crate，标记 `plugin = true`。架构检查扫描每个 crate 的源码，出现 `impl Plugin for` 而没有标记的 crate 直接失败；只有 `kernel` 本身和各 crate 的测试代码（`tests`、`tests.rs`、`testing`）不扫描。

已合并的 [bench 设计「探针」](../design/bench.md#探针lectern_benchprobeprobe-feature)把 `bench-probe` 插件放在 `bench` crate 里：它只在测量构建里由探针加进插件集合，监听 kernel 的 `Busy` / `Quiescent` 转给运行器，裁剪过的集合还由它提交匹配一切 pattern 的 `WorkspaceFacts`。`bench` 是 tool 层 crate，按 ADR 0025 的检查却必须标成插件 crate。

标成插件 crate 做不到：插件 crate 不得依赖其他插件 crate（dev-dependency 也算），而 `bench` 要为每个插件单独组装 `PluginSet`，以 dev-dependency 依赖 `review`、`review_view`、`agents`、`code_intel`、`project`、`usage` 等插件 crate（ADR 0025 本身允许 tool 层依赖插件 crate）。把 `bench-probe` 挪进 `testing` 或 `tests` 路径来避开扫描，是把测量构建的代码伪装成测试代码，检查就失去了意义。

## 决策

1. tool 层 crate（`layer = "tool"`）里实现 `Plugin` 不使它成为插件 crate，不加 `plugin = true`。架构检查在「实现了 `Plugin` 的 crate 必须带标记」这一条里跳过 tool 层 crate，与跳过 `kernel` 相同。ADR 0025 的其余检查不变：插件 crate 之间不相互依赖，只有 `app` 和 tool 层依赖插件 crate。
2. 关键约束：tool 层里的 `Plugin` 实现只用于测量和测试。
   - 不提供、也不要求任何服务（`Manifest` 的 `provides`、`requires` 为空），所以别的插件不能依赖它，插件之间只经 `services` 耦合的规则不受影响。
   - 只进入测量构建：tool 层 crate 不进入发布构建，已由架构检查保证（[工作区与 crate 划分](../design/cargo-workspace.md)）。`app` 依赖它时只经不在 `default` 里的 `bench-probe` feature（bench 设计）。
3. 目前只有一个：`bench` 的 `bench-probe` 插件。以后的 tool 层插件同样遵守第 2 条，由审阅检查；脚本不检查清单内容。

放弃的方案：

- 把 `bench-probe` 拆成单独的插件 crate（`lectern-bench-probe`，`plugin = true`，只依赖 `kernel`）：多一个 crate、一份设计文档和一次设计文档 PR，换来的只是形式上的合规；它仍然只在测量构建里出现。
- 在 `kernel` 的 `testing` 里提供一个通用的「转发静止信号」插件：kernel 设计写明这个合成插件由 bench 的探针提供、只用 kernel 的公开接口（[kernel 设计「性能」](../design/kernel.md#性能)），测试支持里也不应出现测量构建要用的代码。
- 按名字只豁免 `lectern-bench`：tool 层不进发布构建这一事实对所有 tool crate 成立，按层豁免与 `kernel` 的豁免方式一致，不必在脚本里列名单。

## 影响

- `scripts/check_architecture.py`：「实现了 `Plugin` 的 crate 必须带标记」跳过 tool 层 crate；`scripts/test_check_architecture.py` 加对应的测试。
- [工作区与 crate 划分](../design/cargo-workspace.md)「`plugin` 标记」一句补上 tool 层的例外。
- ADR 0025 的状态行和 [索引](README.md) 写明已被本 ADR 修订。
- `bench` 第 4 步的实现（探针）依赖本 ADR；`bench-probe` 的行为写在 [bench 设计「探针」](../design/bench.md#探针lectern_benchprobeprobe-feature)。
