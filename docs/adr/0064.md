# ADR 0064：「打开文件到首屏高亮」的预算只约束语言的高亮查询已经编译过的打开，每种语言在一次运行里的第一次打开只记录

- 状态：已接受
- 日期：2026-11-20
- 修订：[ADR 0034](0034.md)（「预算」里「打开文件到首屏高亮 < 16 ms」的适用范围）

## 背景

[ADR 0034](0034.md)「预算」要求打开文件到首屏高亮 < 16 ms，对任何大小的文件成立。对进程级基准 `app/open_file`，[ADR 0063](0063.md) 把这一档按「结果画在下一帧」判定，CI 上为中位数 < 37.5 ms。

高亮之前要先编译这种语言的 tree-sitter 高亮查询。编译在一次运行里每种语言只做一次，之后复用。在 Apple M5 Pro 上（release 构建，中位数）的实测：

| 语言 | 编译时间 | 编译期间的内存占用 |
|---|---|---|
| TypeScript | 9.6 ms | 4.4 MB |
| TSX | 10.5 ms | 4.7 MB |
| JavaScript | 4.7 ms | 2.0 MB |
| Rust | 8.3 ms | 3.2 MB |
| JSON | 0.02 ms | 0.03 MB |

编译之后留在堆上的只有约 0.3–0.6 MB；其余是编译用的临时表，页面已写过、不会马上还给系统。CI 的虚拟机比 M5 慢约 3–4 倍，编译要 30–40 ms。

[#396](https://github.com/SoloJiang/lectern-app/pull/396) 在 CI 上的测量（运行 44745534840，每个场景都在一次新运行里第一次打开这种语言的文件）：

| 场景 | 中位数 |
|---|---|
| 普通 Rust 文件 | 65.8 ms |
| 4 MiB TypeScript | 66.8 ms |
| 64 MiB TypeScript | 61.0 ms |
| 压缩成一行的 4 MiB JavaScript | 75.5 ms |
| 4 MiB `package-lock.json` | 32.3 ms |
| Diff 的旧版本 | 32.8 ms |

JSON 的查询几乎不用编译，读数在预算以内；Rust、TypeScript、JavaScript 比预算多出的量与 CI 上的编译时间相当。同一批运行里 `app/files_open`、`app/files_expand`、`app/nav_back` 都在 37.5 ms 以内。打开请求到达时 #396 已经在后台开始编译（不等视图建立），剩下的时间是编译本身。

## 决策

1. **预算的适用范围。** ADR 0034 的「打开文件到首屏高亮」预算（进程级按 ADR 0063 判定）只约束这种语言的高亮查询在本次运行里已经编译过的打开。产品负责人在 2026-11-20 选定这一点。ADR 0034 的其他条件（字节偏移、检查点、文件开头）照旧。
2. **第一次打开只记录。** 每种语言在一次运行里的第一次打开不判定预算，基准报告里单独记录它的读数，不让 CI 失败。
3. **基准的做法。** `app/open_file` 的每个场景先在同一次运行里打开一个同语言的小文件，关掉阅读视图后再计时，使计时的打开走与正常打开相同的路径（包括请求到达时就开始的后台工作）。第一次打开另作一个只记录的基准。
4. **仍要守住的约束。** 查询编译不在 UI 线程上（AGENTS.md「禁止事项」）；首屏窗口超过 8 ms 截止时间时先画文本（ADR 0034）。第一次打开因此只是高亮晚到，不卡界面。

放弃的方案：

| 方案 | 原因 |
|---|---|
| 预算照旧约束第一次打开 | CI 上编译就要 30–40 ms，加上「下一帧」的约 25 ms，任何实现都超标 |
| 首帧之后在后台预先编译常用语言 | 先编译 TypeScript、TSX、JavaScript、Rust 要多占约 14 MB，打到空闲内存里，而且这些语言不一定会用到；只是把成本挪到别处 |
| 构建时把查询编译好，启动时载入 | tree-sitter 没有序列化已编译查询的接口 |
| 把所有打开的预算放宽到能容纳编译 | 已编译时的打开慢到原来的 3 倍也不会超标，预算失去作用 |

## 影响

- `bench`：`app/open_file` 先用同语言的文件预热；新增只记录的第一次打开基准；[bench 设计](../design/bench.md)的场景说明和预算表。随 #396 修改。

- ADR 0034 的状态行和索引（本 PR）。

## 已知限制

- 每种语言在一次运行里的第一次打开，高亮比文本晚到一次编译的时间（M5 上 5–11 ms，CI 上 30–40 ms）。
- 第一次打开只记录：编译变慢只出现在基准报告里，不让 CI 失败。
