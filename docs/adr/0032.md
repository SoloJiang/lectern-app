# ADR 0032：建索引不区分电源，用电池时同样覆盖整个仓库

- 状态：已接受
- 日期：2026-10-18
- 修订：[ADR 0029](0029.md)（「电池供电」：不再按电源缩小自动建索引的范围）

## 背景

[ADR 0029](0029.md) 的「电池供电」一条是待产品确认的默认值：用电池时只自动做第 3 层（当前子项目），第 4、5 层等接上电源，或用户跳转、打开 ⌘K 时再继续。它对应[代码导航调研「决定」](../research/code-navigation.md#决定)第 6 条和 [code_intel 设计「未决问题」](../design/code_intel.md#未决问题)第 3 条。code_intel 第 3 步（[#117](https://github.com/SoloJiang/lectern-app/pull/117)）已经按这个默认值实现。

2026-10-18 产品负责人决定：省电模式暂不做；建索引不看电源，始终覆盖整个仓库，即 code_intel 设计「未决问题」3 的选项 (b)。

## 决策

- 第 1–5 层不论接电源还是用电池都照常运行。守卫、线程组、批次、暂停开关和测量按 ADR 0029 不变。
- 不再有电池专属的行为：没有按电源暂缓的层，`coverage` 没有「电池供电时暂缓」的状态，用户的跳转和 ⌘K 也不再负责让暂缓的层继续。`code_intel` 不读电源状态，`platform` 不为建索引提供电源接口。
- 后台索引的能耗只由 ADR 0029 的其余约束控制：批量线程是 utility QoS，线程数 `clamp(available_parallelism / 4, 1, 3)`；结果按 OID 持久化，重新打开时只做缺的。用电池或低电量模式时系统怎样调度 utility QoS 的线程，由系统决定，Lectern 不另外处理。
- 以后要做省电模式（按电源或低电量模式缩小范围、推迟第 3–5 层），另写一条 ADR，重新决定范围和恢复条件，不直接恢复 ADR 0029 的电池一条。
- 索引覆盖范围的时间目标（[ADR 0030](0030.md)、[技术调研「性能预算」](../design/tech-research.md#性能预算)）里的「接电源」是测量条件：用电池时同样的层照常运行，完成时间不设预算。

放弃的方案：

| 方案 | 原因 |
|---|---|
| (a) 保留 ADR 0029 的默认值 | 产品负责人决定省电模式暂不做；电池供电时第 4、5 层要等用户先跳转一次，这一次只能靠限时搜索 |
| (c) 用电池时只索引审阅集合 | 同上，当前子项目也要等，范围比 (a) 更小 |

## 影响

- [ADR 0029](0029.md)：「电池供电」一条由本 ADR 取代，其余部分不变。它在「放弃 background QoS」里写的「省电由下文的电池策略缩小范围来做」不再成立；不用 background QoS 的理由（整仓索引约一分钟，与 utility 的时长相符）不变。
- `platform`：ADR 0029「影响」里的「电源状态和变化通知」取消。
- `code_intel`（[#17](https://github.com/SoloJiang/lectern-app/issues/17)）：设计文档的「范围」「建索引的分层」「未决问题」按本 ADR 改写。第 3 步已有的电池代码（`PowerSource`、`AlwaysOnAc`、`testing::FakePower`、按电源暂缓第 4、5 层和 `demand` 恢复的逻辑、`battery_*` 测试）在第 4 步之后由单独的代码 PR 删除。`platform` 没有电源接口，删除之前能传入的只有 `AlwaysOnAc`，行为已经等于本 ADR。
- `services`：`TierState::Deferred` 随同一个代码 PR 删除。
- `bench`：不变，`app/index_*` 仍在接电源时测量。
