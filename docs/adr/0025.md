# ADR 0025：插件 crate 用 `plugin = true` 标记，只与 kernel 层和非插件的库 crate 相连

- 状态：已接受
- 日期：2026-10-17

## 背景

[ADR 0010](0010.md) 把审阅台、终端、语言支持、会话来源做成插件，插件之间禁止直接依赖。AGENTS.md 架构规则 7 写的是「插件 crate 只依赖 `kernel` 和接口 crate」。工作区的 crate 却按层划分（[工作区与 crate 划分](../design/cargo-workspace.md)），规则 7 没有说明哪些 crate 是插件：`project` 要用 `git` 读仓库、用 `executor` 跑后台任务，按字面读法这都违反规则 7，而 `git`、`executor` 本身不提供任何插件。`scripts/check_architecture.py` 也还不检查规则 7（[#47](https://github.com/SoloJiang/lectern-app/issues/47)）。

规则 7 要守住两件事：插件可以单独激活、停用和替换；插件之间的耦合只经过 `services` 里的接口，kernel 能看到。

## 决策

- 插件 crate 是实现 `kernel::Plugin`、由 `app` 放进 `PluginSet` 的 crate，在 `Cargo.toml` 里标记：

  ```toml
  [package.metadata.lectern]
  layer = "domain"
  plugin = true
  ```

  crate 在第一个实现 `Plugin` 的 PR 里加上标记。其余 crate 是库 crate。架构检查扫描每个 crate 的源码，出现 `impl Plugin for`（含带路径的写法）而没有标记的 crate 直接失败，标记不靠自觉。测试用的实现不算：`kernel` 本身，以及各 crate 的 `tests` 目录、`tests.rs`、`testing` 模块（`test-support` 的模拟插件）都不扫描。
- 插件 crate 可以依赖 kernel 层（`kernel`、`services`）和库 crate（如 `git`、`cache`、`executor`、`fs_watch`、`i18n`），仍受规则 1 的层次约束。
- 插件 crate 之间不得有任何依赖，dev-dependency 也算。插件之间的数据和调用只经过 `services` 定义的接口和快照类型。
- 只有 `app` 和 tool 层 crate 可以依赖插件 crate。tool 层不进入发布构建（[工作区与 crate 划分](../design/cargo-workspace.md)），`bench` 要为每个插件单独组装 `PluginSet` 测激活耗时和内存，需要直接依赖插件 crate。视图层 crate 读插件的状态时用 `services` 里的快照类型，不直接依赖插件 crate。
- 进程级的共享资源（`executor` 的线程池、`cache` 的数据库连接、`fs_watch` 的监听）由 `app` 各创建一份，在构造插件时传入，插件不自建实例。
- 库 crate 不持有跨插件共享的可变状态。多个插件要共享同一份状态（如打开的仓库模型）时，由一个插件持有，以服务的形式提供。

放弃的方案：

- 按字面执行规则 7，把 `git`、`executor`、`fs_watch` 也包成 `services` 里的 trait：每个调用多一层动态分发，接口要在 `services` 里重复一遍，换来的只是形式上的合规；这些库本身不激活、不停用，不需要插件的生命周期。
- 每个插件拆成一个薄包装 crate 加一个库 crate：crate 数量翻倍，包装 crate 里只有几十行激活代码。

## 影响

- AGENTS.md 规则 7 改为本 ADR 的表述；[工作区与 crate 划分](../design/cargo-workspace.md)补上 `plugin` 标记。
- `scripts/check_architecture.py` 增加检查：标记 `plugin = true` 的 crate 不依赖其他插件 crate；除 `app` 和 tool 层外没有 crate 依赖插件 crate；实现了 `Plugin` 的 crate 必须带标记。由 [#47](https://github.com/SoloJiang/lectern-app/issues/47) 的后续 PR 实现。
- 各插件 crate 的设计文档写明它依赖的库 crate 和它通过 `services` 提供或使用的接口；`project`、`agents` 的设计按此编写。
