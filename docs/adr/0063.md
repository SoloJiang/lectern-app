# ADR 0063：「一帧」一档的进程级预算按「结果画在输入之后的下一帧」判定，CI 上为中位数 < 2 个帧周期

- 状态：已接受
- 日期：2026-11-20
- 修订：[技术调研「性能预算」](../design/tech-research.md#性能预算)（「打开文件到首屏高亮」「打开 ⌘K」「⌘K 每次按键到结果更新」的 20 万条一档、「打开 Files、展开目录」「后退、前进」的 < 16 ms / ≤ 16 ms 在进程级基准上的判定方式）

## 背景

技术调研「性能预算」把打开文件、打开 ⌘K、20 万条以内的 ⌘K 按键、打开 Files 与展开目录、后退与前进定为 < 16 ms（一帧）。它们的进程级基准（[bench 设计「进程级基准」](../design/bench.md)）从运行器发出请求开始，到「画出结果的那一帧之后的第一个帧回调」结束（[#394](https://github.com/SoloJiang/lectern-app/pull/394) 之后只等这一帧）。

按这个终点，一个样本至少包含两段：

1. 请求到达时，离下一次显示回调还有 0 到 1 个帧周期，画结果的那一帧要等它；
2. 结果画出之后，终点是下一个帧回调，正好再过 1 个帧周期。

所以即使应用在下一帧就画出结果、计算本身不花时间，样本在 60 Hz 的显示器上也落在 16.7–33.3 ms，平均约 25 ms。任何实现都达不到中位数 < 16 ms。

[#396](https://github.com/SoloJiang/lectern-app/pull/396) 在 CI（GitHub 托管的 `macos-15` runner，Apple M1 虚拟机，3 个 CPU，运行 44724771536）上的第一次测量与此相符：

| 基准 | 中位数 | 样本 |
|---|---|---|
| `app/files_expand` | 26.1 / 25.8 ms | 20.3–33.2 ms |
| `app/files_open` | 33.3 / 29.8 ms | — |
| `app/nav_back` | 27.5 / 35.2 ms | 25.7–55.7 ms |
| `app/open_file` | 65.1 / 94.0 ms | 37.4–100.3 ms |

前三项在下限附近。`app/open_file` 比下限多 2–5 帧，原因在产品里（第一次打开时视图在一次绘制里建立、引擎工作要等视图；语言的高亮查询在首屏的关键路径上编译，TypeScript 10–18 ms），由 `file_reader` 修，不是本 ADR 的范围。

## 决策

1. **「一帧」的含义。** 这一档的预算是「结果画在输入到达应用之后的下一帧」。数字 16 ms 是 60 Hz 下一个帧周期的写法，不是端到端读数的上限。
2. **CI 的判定。** 下列进程级预算的判定改为「中位数 < 2 个帧周期」，帧周期按 60 Hz 计，即中位数 < 33.3 ms：`app/open_file`、`app/palette_open`、`app/palette_key_200k`（原为 ≤ 16 ms，改为 < 33.3 ms）、`app/files_open`、`app/files_expand`、`app/nav_back`。终点、样本数、采样规则不变。
3. **不受影响的预算。** 进程内基准（`time`、`memory` 目标）里的 16 ms 数字是计算时间，不经过显示，不改。其他档（< 50 ms、< 100 ms 等）不改：它们的数字远大于两段等待，不按帧计。冷启动、空闲内存和安装包三项顶层预算不受本 ADR 影响。
4. **以后的机器。** 120 Hz 的判定机器（[ADR 0052](0052.md)）上帧周期是 8.3 ms，同一条规则给出 < 16.7 ms。帧周期在基准报告里写出之后，按实际的帧周期判定；在那之前 CI 按 60 Hz 计。
5. **不是放宽。** 这一档要求的仍是「下一帧」：多一帧（60 Hz 下中位数约 41.7 ms 以上）就超标。`app/open_file` 现在的读数仍超标，修复由 `file_reader` 负责，不能靠改预算通过。

放弃的方案：

- 保持 < 16 ms，只在 120 Hz 的实体判定机器上判定：机器还没有注册，期间 CI 对这一档没有判定。
- 改为数帧：在 `workspace` 和 `bench` 里记录从输入到结果之间画了几帧，预算为 1 帧。最准确，但要新的帧记录（与 [#393](https://github.com/SoloJiang/lectern-app/issues/393) 的帧记录同一类工作），现在没有。帧记录接上之后可以再改为数帧，那时另写 ADR。

## 影响

- `bench`：`crates/bench/src/budgets.rs` 里上面六条预算的数字和来源；[bench 设计「预算表」](../design/bench.md)的对应行。随 #396 修改。
- [技术调研「性能预算」](../design/tech-research.md#性能预算)：这几行加注「进程级基准按下一帧判定（ADR 0063）」。
- `file_reader`：`app/open_file` 要做到下一帧，修复写进 [file_reader 设计](../design/file_reader.md)「性能」。

## 已知限制

- 60 Hz 是假定的 CI 显示器帧率，没有从 runner 读出；runner 的帧率改变时数字要跟着改。
- 「中位数 < 2 个帧周期」允许个别样本落到第三帧，只要中位数在下一帧以内。
