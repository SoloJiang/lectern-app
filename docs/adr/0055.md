# ADR 0055：产品能力完成之前，CI 上超标的分项预算按实测放宽；第一项是 `log/contended_call`

- 状态：已接受
- 日期：2026-10-28
- 修订：[ADR 0046](0046.md)（`log/contended_call` 的预算，原来随 [logging 设计「性能」](../design/logging.md#性能)为 p99 ≤ 5 µs）

## 背景

[ADR 0054](0054.md) 放宽了两项在托管 runner 上反复超标的份额预算。之后又有一项超标：`log/contended_call`（`Tier::Share`）在 #299 上 10 000 次调用里超过 5 µs 的是 121、124 次，预算 ≤ 100 次。#299 只升级 `doc_check` 用的 pulldown-cmark，不碰日志。这一项的波动早有记录：本机 185、174、210、232 次，macOS CI 在 logging 第 1 步的调优之前 165、220 次（[bench 设计「实际验证」](../design/bench.md#实际验证)、[logging 设计「实际验证」](../design/logging.md#实际验证)）。

每次超标都要人工重跑，挡住合并。产品负责人的决定（2026-10-28）：「你可以尽量放宽预算，我要先完成产品，再来核性能预算」。

## 决策

- `log/contended_call`：10 000 次里超过 5 µs 的不超过 100 次（p99 ≤ 5 µs）改为不超过 300 次（p97 ≤ 5 µs）。有记录的最大一次是 232 次，300 次留约 30% 的余量。其余不变：线程数、计时方式、不丢记录。
- 产品能力完成之前的规则：一项分项预算（`Tier::Share`）在 CI 上超标，而且这个 PR 没有改动它测量的代码，就按实测放宽到有记录的最差值加约 20–30% 的余量。不再重跑和等待确认。每次放宽写一条 ADR，或者在本 ADR 的表格里加一行，在同一个 PR 里改 `budgets.rs` 和出处设计文档的「性能」。
- 顶层预算不在这条规则里：冷启动 20 ms、空闲内存 60 MB、安装包 80 MB（ADR 0017、0018）。冷启动的条目（`app/cold_start`、`app/cold_start_purged`、两个 `baseline/*`）只在实体 Mac 上判定（[ADR 0052](0052.md)）；空闲内存（`app/idle_*`）和安装包（`app/bundle_size`、`app/dmg_size`）仍由托管 runner 判定，超标时会挡住合并。它们超标时先查原因，并把数字告诉产品负责人；要改，另写 ADR，由产品负责人决定。
- 改动了被测代码的 PR 让对应的预算超标时，仍然先查原因，不按这条规则放宽。
- 产品能力完成之后，按实体 Mac 上的实测逐项核对，改回原来的值或另写 ADR。

| 预算 | 原来的值 | 新的值 | 依据 |
|---|---|---|---|
| `log/contended_call` | 超过 5 µs 的 ≤ 100 次 | ≤ 300 次 | 有记录的最大一次 232 次 |
| `usage/archive_month` | 每段中位数 < 150 ms | < 240 ms | #309（只改 `welcome`）上 192 ms、176 ms；之前 14 次 CI 在 81–169 ms 之间（2026-10-29） |
| `terminal/parse_plain` | 中位数 ≤ 10 ms | ≤ 14 ms | #336（不碰 `terminal`）上 10.7 ms、10.3 ms；之前 5 次 CI 在 3.46–8.46 ms 之间（2026-10-31） |
| `project_home/build_1000` | 中位数 < 2 ms | < 3 ms | #338（不碰 `project_home`）上 2.31 ms、2.34 ms（2026-10-31） |
| `terminal/open` | 中位数 ≤ 150 µs（ADR 0058） | ≤ 240 µs | #348（不碰 `terminal`）上 187 µs、185 µs；之前 CI 上 77.5–108 µs（2026-10-31） |

放弃的方案：

- 每次超标都重跑：ADR 0054 之前已经做了五次，每次挡住合并一到两个小时。
- 放宽所有分项预算：没有超标的预算不改，以后的回归仍然看得出来。

## 影响

- `lectern-bench` 的 `budgets.rs`：`log/contended_call` 的 `Limit::CountAtMost`。
- `docs/design/bench.md`、`docs/design/logging.md` 里写这个数的地方。
- ADR 0046 的状态行和索引。
