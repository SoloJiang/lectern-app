# ADR 0027：本地数据库用 rusqlite 0.40，静态链接自带的 SQLite

- 状态：已接受
- 日期：2026-10-17

## 背景

[技术调研](../design/tech-research.md#性能要点)、[ADR 0006](0006.md)、[ADR 0014](0014.md) 和 [ADR 0026](0026.md) 规定派生数据缓存和用量聚合都存进本地 SQLite，但没有一条 ADR 选定 SQLite 的绑定、链接方式和使用边界。Cargo.lock 里还没有任何 SQLite 相关的 crate。`cache` 的设计（[cache 设计](../design/cache.md)）和 `usage` 的设计都要用它。

约束：

- 首帧之前不打开 SQLite（[ADR 0017](0017.md)）；SQLite 页缓存上限 8 MB（ADR 0017「内存的具体约束」）。
- 安装包 ≤ 80 MB（[ADR 0018](0018.md)）。
- 后台线程只由 `executor` 管理，任务里直接做阻塞调用（[executor 设计](../design/executor.md)），不引入异步运行时。唯一的例外是 `git` 工作区比较的 stat 一遍，见 [ADR 0038](0038.md)。
- 只允许宽松许可证（`deny.toml`）。

2026-10-17 实测：`rusqlite` 0.40.2（`default-features = false`，`bundled` + `cache`）链接的 SQLite 是 3.53.2。Linux x86_64 release（thin LTO、`codegen-units = 1`、strip）的最小程序 2.33 MB，同样设置的空程序 0.34 MB，增量约 2.0 MB。新增的 crate 是 `rusqlite`（MIT）、`libsqlite3-sys`（MIT，内含的 SQLite 源码属于公有领域）、`fallible-iterator`、`fallible-streaming-iterator`、`hashlink`（都是 MIT OR Apache-2.0）；构建依赖 `cc`、`pkg-config` 已在 Cargo.lock，`vcpkg` 只在 Windows 上使用。用本仓库的 `deny.toml` 检查 licenses、bans、sources、advisories 都通过。

## 决策

- 根 `Cargo.toml` 的 `[workspace.dependencies]` 加入 `rusqlite = { version = "=0.40.2", default-features = false, features = ["bundled", "cache"] }`，精确锁定。升级单独提 PR，跑完 `lectern-cache` 的测试和缓存基准后合并。
- 用 `bundled`：编译并静态链接 `libsqlite3-sys` 自带的 SQLite 源码，不链接系统的 `libsqlite3.dylib`。SQLite 版本随 rusqlite 版本固定，Linux CI 和 macOS 跑的是同一个版本。
- 只开 `cache`（预编译语句缓存）。不开 `load_extension`、`functions`、`hooks`、`backup`、`serde_json`、`chrono`、`time` 等：不加载扩展，不在 SQL 里调用 Rust 函数，时间和 JSON 由调用方自己编码。
- 直接依赖 rusqlite 的只有两个 crate，两种数据库的规则不同：
  - `cache`：派生数据，任何时候都可以删除重建，放在应用缓存目录下；连接数和每个连接的页缓存由 `cache` 限制，合计 ≤ 6 MB。
  - `usage`：用量记录和游标，会话日志被删除后只有这里还有，不能删除重建，放在应用数据目录下，不在缓存目录里；页缓存 ≤ 2 MB。数据库结构和损坏时的处理由 usage 的设计文档规定。
  - 两者合计 ≤ 8 MB，与 ADR 0017 一致。其他 crate 需要持久化派生数据时经 `cache` 的接口，不直接打开 SQLite。
- 关键约束：只在 executor 的任务里打开和调用，UI 线程上不做任何 SQLite 调用；日志模式为 WAL；不使用共享缓存模式和内存映射 IO（`mmap_size = 0`）。

放弃的方案：

- 链接系统的 `libsqlite3.dylib`：省约 2 MB，但版本随 macOS 版本变化，编译选项由 Apple 决定，Linux CI 测到的是另一个版本；SQLite 的问题修复要等系统升级。
- `sqlx`：异步接口，需要 tokio 或 async-std 运行时，与 executor 的阻塞任务模型不符，依赖也更多。
- 纯 Rust 的 SQLite 重写（如 Limbo / Turso）：文件格式兼容和稳定性还不足以承载用量这种不能丢的数据。
- 嵌入式键值库（redb、sled、LMDB）：`cache` 本身只要键值，但 `code_intel` 的符号索引（[#17](https://github.com/SoloJiang/lectern-app/issues/17)）要按名字查询，`usage` 要做聚合查询，只用一种存储引擎更简单。
- 每个缓存条目一个文件：大量小文件，没有多条写入的事务，按字节 LRU 要遍历目录。

## 影响

- 根 `Cargo.toml`、`crates/cache/Cargo.toml`，以后的 `crates/usage/Cargo.toml`。
- `cache` 的文件布局、表结构、淘汰、并发和损坏处理由 [cache 设计](../design/cache.md)负责；`usage` 的数据库由 usage 的设计文档负责。
- 体积约 2 MB，计入 ADR 0018 的 80 MB 预算；macOS 上的实际增量由 [#38](https://github.com/SoloJiang/lectern-app/issues/38) 的安装包检查测量。
- `just deny` 覆盖新增的传递依赖。
- [技术调研「技术选型」](../design/tech-research.md#技术选型)增加「本地存储」一行。

## 已知限制

- SQLite 的问题修复要升级 rusqlite 才能拿到。
- `bundled` 要在构建时编译 SQLite 的 C 源码，需要 C 编译器；macOS 的 Xcode 命令行工具和 Linux CI 的镜像都有。
