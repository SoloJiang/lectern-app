# ADR 0017：性能预算收紧：冷启动 20ms，空闲内存 60MB

- 状态：已接受
- 日期：2026-10-16
- 修订：[技术调研「性能预算」](../design/tech-research.md#性能预算)中冷启动 150ms、空闲内存 150MB 的目标

## 背景

产品负责人要求冷启动在 20ms 内，内存占用更低。原预算（冷启动 150ms、空闲 150MB）对标的是 Zed 这类编辑器；Lectern 以阅读为主，首帧需要的东西更少，可以定得更紧。

## 决策

| 指标 | 原预算 | 新预算 | 测量方式 |
|---|---|---|---|
| 冷启动到首帧 | < 150 ms | **< 20 ms** | 发布构建，M 系列 Mac，进程未驻留内存、系统文件缓存已预热；从进程创建（内核记录的启动时间）到第一帧提交到屏幕（`CAMetalLayer` present），取 20 次的 p50，p95 不超过 30 ms |
| 空闲内存（空窗口） | < 150 MB | **< 60 MB** | 首帧后 5 秒的 `phys_footprint`（活动监视器里的「内存」） |
| 空闲内存（打开一个 monorepo） | — | **< 100 MB** | 打开 cloudprint-miniapps 量级的仓库（11 个 worktree），首页加载完成后 5 秒 |

其余指标不变。

**首帧之前只做三件事**：创建窗口、读取上次的窗口快照（mmap，不解析 JSON）、画出骨架。以下全部推迟到首帧之后，在后台线程进行：

- 插件激活（只有窗口骨架和 `ui` 在首帧前就绪）
- 打开 SQLite、启动 FSEvents 监听、扫描会话目录、读 git
- 加载非当前语言的文案；当前语言的 Fluent 资源在编译期预解析并内嵌

**为首帧做的具体约束**：

- Metal shader 预编译为 metallib 内嵌进二进制，不开 `runtime_shaders`；渲染管线用 Metal binary archive 缓存。
- 字体只按名字取 SF Pro / SF Mono，不枚举系统字体目录；字形图集按需填充。
- 二进制静态链接本仓库代码，控制链接的系统框架和 ObjC 类数量，减少 dyld 时间；必要时提供 order file。
- 首帧不起子进程、不访问网络、不做同步磁盘遍历。

**内存的具体约束**：

- 不常驻语言服务器（已有）；jdtls 等外部进程不计入 Lectern 的内存，但空闲即关。
- SQLite 页缓存上限 8 MB；派生数据缓存按字节数做 LRU，有总上限。
- 会话 JSONL 流式读取，只保留摘要与当前审阅会话的改动；非活动 worktree 只留元数据。
- 字形图集与 Metal 缓冲区按可见内容分配，窗口隐藏时释放。

## 影响

- `bench` crate 增加启动与内存基准：启动用 release 构建跑 20 次，读取进程启动时间与首帧时间；内存在首帧后 5 秒读 `phys_footprint`。超过预算 CI 失败。
- P0 的原型（[#5](https://github.com/SoloJiang/lectern-app/issues/5)、[#7](https://github.com/SoloJiang/lectern-app/issues/7)）要先测出空 GPUI 窗口的冷启动与内存基线。如果 AppKit 与 WindowServer 本身的开销就接近或超过 20ms，把实测数据记录在本 ADR 下，再决定是优化测量起点还是调整预算，不默默放宽。
- 新增功能必须说明它在首帧之前做了什么；默认答案是「什么都不做」。
