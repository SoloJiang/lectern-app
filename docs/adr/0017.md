# ADR 0017：性能预算收紧：冷启动 20ms，空闲内存 60MB

- 状态：已接受，空闲内存的测量方式已被 [ADR 0029](0029.md) 修订
- 日期：2026-10-16
- 修订：[技术调研「性能预算」](../design/tech-research.md#性能预算)中冷启动 150ms、空闲内存 150MB 的目标

## 背景

产品负责人要求冷启动在 20ms 内，内存占用更低。原预算（冷启动 150ms、空闲 150MB）对标的是 Zed 这类编辑器；Lectern 以阅读为主，首帧需要的东西更少，可以定得更紧。

## 决策

| 指标 | 原预算 | 新预算 | 测量方式 |
|---|---|---|---|
| 冷启动到首帧 | < 150 ms | **< 20 ms** | 发布构建，M 系列 Mac，进程未驻留内存、系统文件缓存已预热；从进程创建（内核记录的启动时间）到第一帧真正显示在屏幕上（第一个 `MTLDrawable` 的 `presentedTime`，通过 `addPresentedHandler` 读取；调用 `present` 只表示已安排显示，不能作为终点），跑 20 次，p95 必须低于 20 ms（20 次里最多 1 次超过），任何一次都不超过 30 ms |
| 空闲内存（空窗口） | < 150 MB | **< 60 MB** | 后台初始化全部完成（kernel 发出「已静止」信号：首帧后的任务队列清空、各插件激活完毕）后再等 5 秒，读 `phys_footprint`（活动监视器里的「内存」）；首帧后 30 秒内没有静止视为失败。已被 [ADR 0029](0029.md) 修订：可暂停的后台工作不计入静止，采样前先暂停它；另测后台工作全部完成后的内存 |
| 空闲内存（打开一个 monorepo） | — | **< 100 MB** | 打开 cloudprint-miniapps 量级的仓库（11 个 worktree），首页加载完成并静止后 5 秒，同上 |

其余指标不变。

**首帧之前只做两件事**：创建窗口、画出骨架。首帧之前，进程（包括后台线程）不读取 Lectern 自己的任何文件，唯一的例外是下文「为首帧做的具体约束」里的 Metal binary archive 缓存：

- 窗口位置与大小用 AppKit 的 frame autosave（随应用偏好设置由系统读取），不读取 Lectern 自己的文件。
- 上次的窗口快照（选中的项目、侧栏状态）在第一帧显示（`presentedTime` 回调）之后才由后台线程读取，读完后填入骨架。首帧始终是中性的骨架，读取快照不占用首帧所需的 CPU 与磁盘。

以下全部推迟到首帧之后，在后台线程进行：

- 插件激活（只有窗口骨架和 `ui` 在首帧前就绪）
- 打开 SQLite、启动 FSEvents 监听、扫描会话目录、读 git
- 加载非当前语言的文案；当前语言的 Fluent 资源在编译期预解析并内嵌

**为首帧做的具体约束**：

- Metal shader 预编译为 metallib 内嵌进二进制，不开 `runtime_shaders`。
- 渲染管线用构建期 `metal-tt` 生成的 binary archive，覆盖每一个支持的 Apple GPU 家族；新增支持的芯片时必须先补上对应的 slice。启动基准创建管线时带 `failOnBinaryArchiveMiss`，缺 slice 即失败。
- 系统升级可能让 archive 失效：运行时遇到未命中，照常编译管线（这一次首帧会变慢），并在后台把结果写入本机的 archive 缓存。这个缓存是首帧前唯一允许读取的本地文件：只在内置 slice 未命中时由 Metal 映射读取，冷文件缓存基准里单独计时。下一个版本更新时把对应 slice 补进安装包。
- 字体通过系统字体 API 获取（AppKit 的 system font / monospaced system font，或 Core Text 的 UI font），不按名字查找，也不枚举系统字体目录；字形图集按需填充。
- 二进制静态链接本仓库代码，控制链接的系统框架和 ObjC 类数量，减少 dyld 时间；必要时提供 order file。
- 首帧之前不启动子进程、不访问网络、不做同步磁盘遍历。

**内存的具体约束**：

- 不常驻语言服务器（已有）；jdtls 等外部进程不计入 Lectern 的内存，但空闲即关。
- SQLite 页缓存上限 8 MB；派生数据缓存按字节数做 LRU，有总上限。
- 会话 JSONL 流式读取，只保留摘要与当前审阅会话的改动；非活动 worktree 只留元数据。
- 字形图集与 Metal 缓冲区按可见内容分配，窗口隐藏时释放。

## 影响

- `bench` crate 增加启动与内存基准：启动基准用 release 构建运行 20 次，读取进程启动时间与首帧时间；内存基准在 kernel 发出静止信号后再等 5 秒读取 `phys_footprint`。超过预算则 CI 失败。基准另在冷文件缓存下（`purge` 后）运行一次，只记录不判定，用于发现首帧前隐藏的磁盘读取。
- P0 的原型（[#5](https://github.com/SoloJiang/lectern-app/issues/5)、[#7](https://github.com/SoloJiang/lectern-app/issues/7)）要先测出空 GPUI 窗口的冷启动与内存基线。测量起点固定为内核记录的进程创建时间，不因为基线超标而后移。如果 AppKit 与 WindowServer 本身的开销就接近或超过 20ms，把实测数据记录在本 ADR 下，交给产品负责人决定是否调整预算（20ms 是产品要求），不得擅自放宽。
- 新增功能必须说明它在首帧之前做了什么；默认答案是「什么都不做」。
- `kernel` 提供「已静止」信号：首帧后的后台初始化任务全部完成时发出一次，供内存基准与 UI 探针使用。
