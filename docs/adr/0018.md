# ADR 0018：安装包 80MB 以内，非核心插件从插件市场按需下载

- 状态：已接受
- 日期：2026-10-16
- 修订：[ADR 0010](0010.md)（内置插件全部编译期链接）

## 背景

产品负责人要求包体积控制在 50–80MB，不必要的插件通过插件市场按需下载。ADR 0010 规定内置插件全部编译进主程序，所有语言支持、代码平台、agent 适配都会进安装包，体积和内存都会随功能线性增长。

## 决策

**体积预算**

| 指标 | 预算 | 测量方式 |
|---|---|---|
| 安装后的 `Lectern.app` | ≤ 80 MB，目标 50 MB | release 构建、strip 后的 `.app` 目录大小（`du -sk`） |
| 下载的 `.dmg` | ≤ 40 MB | 压缩后 |

macOS 的 CI 任务每次构建都测量；超过预算即失败。

**核心与可选的划分**

核心（随安装包）只包含审阅闭环需要的东西：kernel、ui、窗口骨架、项目主页与审阅视图、git 与 diff、Claude Code / Codex 会话解析、终端、i18n（en、zh-CN）、usage，以及常用语言的语法高亮（TypeScript / JavaScript、Rust、Java、Python、Go、JSON、YAML、TOML、Markdown）。

可选（从插件市场下载）：

| 类型 | 例子 | 形式 |
|---|---|---|
| 语言包 | Kotlin、Swift、C/C++、PHP 等的语法与符号导航 | tree-sitter grammar 动态库（C ABI，在主进程内加载）+ 声明式查询文件 |
| 精确语义 | jdtls、SCIP 导入 | 独立进程插件 |
| 代码平台 | GitLab 自部署的扩展能力、其他平台 | 独立进程插件 |
| agent 适配 | ACP 适配器、其他 agent 的会话来源 | 独立进程插件 |
| 数据包 | 价格表更新、额外界面语言 | 数据文件 |

可下载的代码只有两种形式：
- **独立进程插件**：沿用 ADR 0010 第三方插件的方式，通过 stdio JSON-RPC 实现服务接口，Seatbelt 沙箱运行。Rust 没有稳定 ABI，不做 Rust 动态库插件。
- **tree-sitter grammar 动态库**：tree-sitter 的语言接口是 C ABI，在主进程内 `dlopen`，不在沙箱里。因此：
  - 只有官方构建的 grammar：由我们的发布流程从源码构建，用与 Lectern 相同的 Team ID 做代码签名并公证。开启 Hardened Runtime 的发布版只接受 Apple 或同一 Team ID 签名的库，我们不加 `com.apple.security.cs.disable-library-validation`。第三方的 grammar 提交到官方仓库由我们构建，不接受直接分发的二进制。
  - grammar 按原生代码对待，信任边界与 Lectern 自己的代码相同：生成的解析表之外，grammar 可以带手写 C 的 external scanner，在词法分析时以 Lectern 的权限运行。签名只证明产物来自我们，不证明代码安全，所以进入官方仓库的每个 grammar（含版本更新）都要经过与本仓库代码相同的人工审查，重点审 scanner：只许纯计算，不许系统调用、文件、网络和全局状态。构建锁定到审查过的上游 commit。
  - 只有审查过的官方 grammar 会被自动安装；没有审查过的 grammar 不进索引，没有「第三方 grammar 只提示」这一档。
  - 不放到独立进程：高亮在每次滚动和打开文件时同步运行，跨进程会超出一帧的预算（技术调研「性能预算」）。
  - 加载前同时校验代码签名、索引里的 sha256 和 tree-sitter ABI 版本。

**插件市场**

- 索引是一份签名过的静态 JSON（插件 id、版本、类型、平台、大小、sha256、签名、所需服务、激活条件、兼容的宿主版本范围），托管在 GitHub Releases。
- 能力声明：进程插件的索引条目带签名的能力清单，按最小权限写：可读的路径（当前项目只读、指定的会话目录如 `~/.claude/projects`）、可写的路径（默认只有自己的数据目录）、可访问的网络主机（逐个列出，默认无网络；自部署的代码平台用「用户配置的平台地址」这一项能力，具体主机名在用户填写地址时单独确认）、可启动的子进程。`platform` 只按清单生成该插件的 Seatbelt 配置，清单外一律拒绝，不存在通用的宽松配置。
  - 网络：Seatbelt 不能按主机名放行出站连接，所以插件的 Seatbelt 配置只允许连本机回环上的一个端口。Lectern 主进程在这个端口上提供 HTTP(S) CONNECT 代理，只放行清单里的主机（以及用户确认过的自部署地址），其余连接直接拒绝并记录。
  - 运行时限额：进程插件宿主强制执行，不靠插件自觉。单个插件内存超过上限（默认 50 MB，按 `phys_footprint` 每秒采样）或空闲时持续占满 CPU 超过 10 秒即终止；JSON-RPC 单条消息不超过 4 MB，请求默认 5 秒超时并取消，待处理队列有上限，满了就对插件施加背压；数据目录有配额（默认 100 MB）。插件 10 分钟内崩溃或被终止 3 次即隔离：停用到用户手动重新启用，界面说明原因。
  - 环境变量：启动插件进程时先清空继承的环境变量，只注入固定的非敏感白名单（`PATH`、`HOME`、`LANG`、`TMPDIR` 以及代理地址）。`GITHUB_TOKEN` 这类凭据不会传给插件；插件需要访问代码平台时，凭据由主进程按能力清单通过 JSON-RPC 发给它，范围限定在已确认的主机。安装确认里列出这些能力；更新时能力变多，需要用户重新确认，否则保持旧版本。
- 撤销：索引带签名的撤销列表（插件 id + 版本或 sha256 + 原因）。客户端持久保存接受过的撤销，匹配的已装版本立即停用（grammar 不再加载，进程插件不再启动），界面说明原因；有修复版本时自动换成修复版本（进程插件仍按上面的规则确认）。版本从索引里消失只表示下架，不等于撤销。
- 防回放与冻结：索引的签名内容带单调递增的序号和过期时间（发布后 30 天，期间至少每周重签一次）。客户端保存接受过的最高序号，序号更低的索引一律拒绝；过期的索引不用于安装或更新，已装的插件照常使用，界面提示「插件目录已过期」。做法参照 TUF 的 timestamp 与 snapshot 角色。
- grammar 条目另外写明 tree-sitter 语言 ABI 版本。语言二进制不向前兼容，解析器只选 ABI 落在本机 tree-sitter 支持范围（`TREE_SITTER_MIN_COMPATIBLE_LANGUAGE_VERSION` 到 `TREE_SITTER_LANGUAGE_VERSION`）内的版本；没有可用版本时显示为「需要更新 Lectern」。进程插件按 JSON-RPC 协议版本做同样的匹配。
- 「扫到就下载」：项目模型识别出文件类型和清单（如出现 `.kt`、`build.gradle.kts`）时，与索引里插件的激活条件匹配。
  - 官方的 grammar 与数据包（没有额外权限）：后台下载，装好后在侧栏底部提示一次。
  - 所有进程插件（官方与第三方）：先提示并列出能力清单，用户确认后才安装和启动。
  - 设置里可以改成全部手动。
- 下载、校验、解压都在后台线程，不阻塞界面，不影响冷启动（ADR 0017）。
- 已装插件放在 `~/Library/Application Support/Lectern/plugins/<id>/<version>/`；更新时先下载新版本，切换后保留上一个可用版本：新版本加载成功并完成激活（进程插件完成 JSON-RPC 握手，grammar 导出预期的语言符号）后才删除旧版本；失败就回滚到旧版本并报告原因。
- 离线时用已装版本；从未装过的能力显示为「可安装」，不报错。

**插件接口**

ADR 0010 的服务接口（`SessionSource`、`ForgeProvider`、`NavigationProvider`、`ProjectDetector`）同时用于内置插件和独立进程插件。审阅台等核心视图不区分插件来自哪里。

## 影响

- `kernel` 增加两类插件宿主：进程插件宿主（启动、JSON-RPC、空闲退出）和 grammar 加载器（ABI 与 sha256 校验、按需加载）。二者只编排生命周期和协议；与 macOS 相关的部分（Seatbelt 沙箱启动子进程、代码签名校验、`dlopen`）由 `platform` 实现 kernel 定义的接口，`app` 装配时注入，kernel 不依赖 `platform`（架构规则 6）。
- 新增 `marketplace` 模块：索引拉取与签名校验、下载、安装、更新、卸载。
- 打包：可执行的插件都装在可以附加公证票据的 bundle 里，不分发裸的可执行文件或 `.dylib`（Apple 不支持把票据附加到单独的二进制上）。grammar 是 loadable bundle（`.bundle`，内含 dylib），进程插件是 `Contents/MacOS/` 下带可执行文件的 bundle。安装时整个 bundle 原样放进插件目录，不拆出里面的文件；安装后用 `stapler validate` 和代码签名校验检查一次。
- 发布流程：每个可选插件单独构建、签名、公证（票据附加在 bundle 上，离线也能校验）、上传，索引在发布时重新生成并签名。第三方进程插件同样必须用开发者自己的 Developer ID 签名并公证；`platform` 在首次启动前校验签名与公证状态，不通过的不运行。grammar 的源码审查是发布前的必需步骤。
- 每个插件的激活耗时和常驻内存仍按 ADR 0010 的预算检查。内存基准量整个 Lectern 进程树：主进程按 ADR 0017 的预算（空窗口 60 MB、monorepo 100 MB）；所有进程插件合计空闲时另有 50 MB 的总预算，几个插件同时运行也不能超过。jdtls 这类用户主动启用的语言服务器不计入总预算，但单独报告，空闲 10 分钟即退出。
- 交互：侧栏底部的「插件已安装」提示，设置里的插件列表（已装、可用、自动安装开关）。
