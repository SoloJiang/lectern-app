# ADR 0018：安装包 80MB 以内，非核心插件从插件市场按需下载

- 状态：已接受
- 日期：2026-10-16
- 修订：[ADR 0010](0010.md)（内置插件全部编译期链接）

## 背景

产品负责人要求包体积控制在 50–80MB，不必要的插件通过插件市场按需下载。ADR 0010 规定内置插件全部编译进主程序，所有语言支持、代码平台、agent 适配都会进安装包，体积和内存都会随功能线性增长。

## 决策

**体积预算**

| 指标 | 预算 | 测量方式 |
|---|---|---|
| 安装后的 `Lectern.app` | ≤ 80 MB，目标 50 MB | release 构建、strip 后的 `.app` 目录大小（`du -sk`） |
| 下载的 `.dmg` | ≤ 40 MB | 压缩后 |

macOS 的 CI 任务每次构建都测量；超过预算即失败。

**核心与可选的划分**

核心（随安装包）只包含审阅闭环需要的东西：kernel、ui、窗口骨架、项目主页与审阅视图、git 与 diff、Claude Code / Codex 会话解析、终端、i18n（en、zh-CN）、usage，以及常用语言的语法高亮（TypeScript / JavaScript、Rust、Java、Python、Go、JSON、YAML、TOML、Markdown）。

可选（从插件市场下载）：

| 类型 | 例子 | 形式 |
|---|---|---|
| 语言包 | Kotlin、Swift、C/C++、PHP 等的语法与符号导航 | tree-sitter grammar 动态库（C ABI，在主进程内加载）+ 声明式查询文件 |
| 精确语义 | jdtls、SCIP 导入 | 独立进程插件 |
| 代码平台 | GitLab 自部署的扩展能力、其他平台 | 独立进程插件 |
| agent 适配 | ACP 适配器、其他 agent 的会话来源 | 独立进程插件 |
| 数据包 | 价格表更新、额外界面语言 | 数据文件 |

可下载的代码只有两种形式：
- **独立进程插件**：沿用 ADR 0010 第三方插件的方式，通过 stdio JSON-RPC 实现服务接口，Seatbelt 沙箱运行。Rust 没有稳定 ABI，不做 Rust 动态库插件。
- **tree-sitter grammar 动态库**：tree-sitter 的语言接口是 C ABI，在主进程内 `dlopen`，不在沙箱里。因此：
  - 只有官方构建的 grammar：由我们的发布流程从源码构建，用与 Lectern 相同的 Team ID 做代码签名并公证。开启 Hardened Runtime 的发布版只接受 Apple 或同一 Team ID 签名的库，我们不加 `com.apple.security.cs.disable-library-validation`。第三方的 grammar 提交到官方仓库由我们构建，不接受直接分发的二进制。
  - grammar 只含解析表，不执行任意逻辑；加载前同时校验代码签名、索引里的 sha256 和 tree-sitter ABI 版本。

**插件市场**

- 索引是一份签名过的静态 JSON（插件 id、版本、类型、平台、大小、sha256、签名、所需服务、激活条件、兼容的宿主版本范围），托管在 GitHub Releases。
- grammar 条目另外写明 tree-sitter 语言 ABI 版本。语言二进制不向前兼容，解析器只选 ABI 落在本机 tree-sitter 支持范围（`TREE_SITTER_MIN_COMPATIBLE_LANGUAGE_VERSION` 到 `TREE_SITTER_LANGUAGE_VERSION`）内的版本；没有可用版本时显示为「需要更新 Lectern」。进程插件按 JSON-RPC 协议版本做同样的匹配。
- 「扫到就下载」：项目模型识别出文件类型和清单（如出现 `.kt`、`build.gradle.kts`）时，与索引里插件的激活条件匹配。
  - 官方签名的插件：后台下载，装好后在侧栏底部提示一次。
  - 第三方插件：只提示，由用户点安装。
  - 设置里可以改成全部手动。
- 下载、校验、解压都在后台线程，不阻塞界面，不影响冷启动（ADR 0017）。
- 已装插件放在 `~/Library/Application Support/Lectern/plugins/<id>/<version>/`；更新时先下载新版本，切换后再删旧版本。
- 离线时用已装版本；从未装过的能力显示为「可安装」，不报错。

**插件接口**

ADR 0010 的服务接口（`SessionSource`、`ForgeProvider`、`NavigationProvider`、`ProjectDetector`）同时用于内置插件和独立进程插件。审阅台等核心视图不区分插件来自哪里。

## 影响

- `kernel` 增加两类插件宿主：进程插件宿主（启动、JSON-RPC、空闲退出）和 grammar 加载器（ABI 与 sha256 校验、按需加载）。二者只编排生命周期和协议；与 macOS 相关的部分（Seatbelt 沙箱启动子进程、代码签名校验、`dlopen`）由 `platform` 实现 kernel 定义的接口，`app` 装配时注入，kernel 不依赖 `platform`（架构规则 6）。
- 新增 `marketplace` 模块：索引拉取与签名校验、下载、安装、更新、卸载。
- 发布流程：每个可选插件单独构建、签名、上传，索引在发布时重新生成并签名。
- 每个插件的激活耗时和常驻内存仍按 ADR 0010 的预算检查；独立进程插件的内存单独统计，不计入主进程的 60 MB。
- 交互：侧栏底部的「插件已安装」提示，设置里的插件列表（已装、可用、自动安装开关）。
