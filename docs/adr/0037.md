# ADR 0037：跳转的份额按第一批计、在首次跳转会遇到的状态下测量；当前文本的解析按 blob OID 保留在有上限的内存里

- 状态：已接受
- 日期：2026-10-19
- 修订：[ADR 0034](0034.md)（「解析与高亮」中「阅读时不保留打开文件的整棵语法树」：跳转用的当前文本在 128 KiB 以内时保留它的解析）；[ADR 0030](0030.md)（「延迟预算」中「跳转到定义：同文件或索引命中，候选列表 ≤ 50 ms」：适用于 128 KiB 以内的当前文本）

## 背景

[ADR 0030](0030.md) 把「跳转到定义：同文件或索引命中，候选列表 ≤ 50 ms」列为顶层预算，[code_intel 设计「性能」](../design/code_intel.md#性能)从中给本 crate 定了 20 ms 的份额，分项是当前文本（100 KB 以内）解析与 locals ≤ 10 ms、按名字查找 ≤ 2 ms、过滤分层排序 ≤ 3 ms。第 4 步的审阅指出这个份额只在最容易的状态下成立：

- 基准重复同一次跳转，核算的遍历已缓存；索引变化后的第一次跳转是未缓存的（实测 16.2 ms 对 19.5 ms）。
- 夹具的当前文本是 64 KiB，而不是这一行写的 100 KB。解析加 locals 在 64 KiB 时约 14–16 ms，随大小线性增长，单这一项就超过 10 ms 的分项；Linux 上三次测得 19.1、24.1、19.8 ms，余量很小。
- 按名字查找没有上限，每行约 7 µs。约 3000 个定义的常见名字（`get`、`new`）多出约 25 ms。
- 10 万文件的仓库约 270 MiB，通常已超过 256 MiB 的配额（满额模式）。这时核算要逐批核对存储，跳转到 `Done` 约 290 ms，查引用约 1.02 s。根作用域、没有子项目或 `Named` 不带 `near` 时，这一核对没有上限，中途也不能取消。
- 设计的分项与实际验证的结论相互矛盾。

当前文本的解析（`ParsedFile`）实测约为源码的 46.6 倍（100 KB 的 TypeScript 约 4.7 MB）。只缩小 locals 的查询范围，结果会变（code_intel「实际验证」的限制试验），所以靠缩小查询降不到 10 ms。[ADR 0034](0034.md) 规定阅读时不保留打开文件的整棵语法树，理由是大文件的树是源码的 14–41 倍（4 MiB 时 134 MiB）。

## 决策

**份额与测量**

- 顶层预算不变。本 crate 的份额是从查询到第一批有候选的结果 ≤ 20 ms，前提是当前文本的解析已保留（见下）。这一条在首次跳转会遇到的状态下分别判定：遍历已缓存、遍历未缓存、约 3000 个定义的常见名字、满额模式。
- `Done` 在查询的 1 s 时间盒内到达，最多再加一条语句；满额模式下判定。
- 取消在 20 ms 内生效，每条路径都是如此：查询里的每条语句都有上限（一页 ≤ 256 行，或 ≤ 500 个 OID），语句之间检查查询是否已停止。
- 50 ms 里抽屉的份额是 18 ms：从收到第一批的事件到候选列表画出，一帧（ADR 0030 的「一帧」按 16 ms 判定）加 2 ms 把事件送到 UI 线程。本 crate 第一批的 20 ms 留出的余量比这更多。
- 当前文本还没有保留解析时的第一次跳转（冷路径：文本刚成为当前文本、预热还没完成）按 50 − 18 = 32 ms 判定，在保留的上限 128 KiB 处测量（`code_intel/goto_cold_parse`）。
- 分项改为实测值，写进 code_intel 设计「性能」；budgets.rs 和 bench 设计按此修改。
- 修订 ADR 0030：「同文件或索引命中，候选 ≤ 50 ms」适用于 128 KiB 以内的当前文本。更大的文本不保留解析（见下），每次跳转为光标处重新解析，1 MiB 的 TypeScript 约 165 ms（ADR 0034 的实测），不在 50 ms 之内；它们是少数，写进「已知限制」，不另设预算。

**当前文本的解析按 blob OID 保留**

- 键是（blob OID、语言版本）（架构规则 5），值是整个 `ParsedFile`：任意位置的标识符、定义和绑定模型都可以从它得到。同一文本里再次跳转不读文件、不解析。
- 上限：最多 2 份；源码 ≤ 128 KiB 的才保留；按每字节源码 48 字节估算，合计 ≤ 12 MiB（实测 46.6 字节，`code_intel/parse_cache_bytes` 在上限处测量：两份略小于 128 KiB）。超过时淘汰最久未用的一份，当前文本的那份最后淘汰。
- 当前文本的那份在它是当前文本期间一直保留，读多久都不会过期，所以读了一分钟之后的跳转不会走冷路径。它不再是当前文本时（另一份文本成为当前文本、`Focus::Current(None)`、项目关闭）开始计时，60 s 没用到即释放；其他的从最后一次用到开始计 60 s。它的语言被语言表替换时也立即释放（释放 grammar 的租约）。
- 预热：文本成为当前文本（`Focus::Current`）时预热，冷路径的跳转或预取之后也预热。预热在 `Background` 任务里进行，排在首屏的 `Interactive` 工作之后（ADR 0033、0034）；没有打开的项目时不预热。跳转从不等它。
- 内存：这是只因阅读才填充的缓存，属于 [ADR 0035](0035.md)「关键约束」里由各自的上限约束、不在采样状态里的那一类（与 `file_reader` 的 8 MB 高亮与文本 LRU、`git` 的 hunk LRU 同类）。ADR 0035 把空闲内存的分配对应到 ADR 0017 的采样状态：首页加载完成、没有打开文件、Diff 或会话。只有文本成为当前文本、或者在它里面跳转之后才有保留的解析。采样状态（[ADR 0017](0017.md)、[ADR 0029](0029.md) 的 `app/idle_monorepo`、`app/idle_monorepo_indexed`，ADR 0035 的 `app/idle_100k`、`app/idle_100k_indexed`）没有打开的文件，也就没有当前文本，所以里面没有它；文本不再是当前文本 60 s 之后也没有它。因此它不占 ADR 0030 和 ADR 0035 分给 `code_intel` 的常驻份额（10 万文件 ≤ 10 MB），也不占 ADR 0035 的 12 MB 余量。阅读时它的上限是 12 MiB，ADR 0035「已知限制」里「审阅之后的空闲内存可以比采样状态多出几个缓存的上限」也包括它。`plugin/code-intel/resident_*` 在测量前丢掉保留的解析，按采样状态测量。
- 修订 ADR 0034：128 KiB 以内的当前文本在它是当前文本期间、以及之后 60 s 内保留语法树。更大的文本仍不保留，每次跳转为光标处重新解析。

**按名字查找有上限**

- 一页是名字在索引里的 256 行，按索引给出的行计，不按通过筛选的行计：任何版本、状态、大小写的行都占一行，版本和状态在 Rust 里比对。所以旧版本的单元（淘汰之前不删除）、其他语言、名字的其他大小写都不会让一条语句多读；一次扫描覆盖查询的所有版本，不再按版本分组各扫一遍。游标是索引里最后一行的 (unit, kind, rowid)，一个单元的同名定义可以跨页，每行读一次；一页可以一个定义也没有，少于 256 行时查找结束。
- 第一批只读两样：名字的第一页，以及名字还有更多页时，离查询最近的文件里的定义。最近的文件按排序的顺序取：先是所在目录自己的文件（不含子目录，含工作区的改动），审阅集合在前，单独用语句查；再是所在子项目的其他文件，审阅集合在前、按路径距离排序。合计 ≤ 2048 个，每 500 个文件一条语句，每条 ≤ 256 行，所以一条语句的行数上限不会让近的文件让位给远的。其余页在之后的批次里逐页追加，直到时间盒。时间盒到时没读的行数计入未搜（上限，按定义行计）。
- `ci_def_name` 改为 (name NOCASE, unit, kind) 的索引：按名字分页从游标定位，在给定文件里按 (name, unit) 定位，名字表按索引顺序读 (name, unit, kind)、不读表。命名空间的版本因此升为 2：旧版本的表在第一次使用时删除，单元随之后的写事务删除、重新抽取（`lectern-cache`「自定义表」）。查引用的 `ci_ref` 按同样的页取（游标是 unit），页与页之间检查查询是否已停止。
- 名字表按索引顺序分页读（每条语句 4096 项），语句之间检查是否停止；大小写不同的同名在索引里相邻，每个名字只和它所在的那一串比较，不为每个定义分配，每个不同的名字做一次 NFC。

**满额模式的核对**

- 搜索范围内外的每条核对语句之前，都检查查询是否已停止、时间盒是否已到。到时没核对的计为 `Unchecked`：范围内计入未搜，范围外计入 `outside`，从不算作已入索引。
- 时间盒按查询的种类定：跳转和 `Named` 是 1 s（ADR 0030：1.1 s 内停止并画出），查引用是 1.9 s（ADR 0030：全部结果 ≤ 2 s，同样留 0.1 s 画出）。查引用的 `ci_ref` 一轮在 10 万文件时就要 0.8–1 s，与跳转共用 1 s 时，核对总被截断，全部已入索引的仓库也报 `Partial { outside }`。
- 第一批不等核对：`Named` 先交出候选，再做核算的遍历；查引用在 `ci_ref` 一轮之后、读搜索范围之前先交出已找到的结果。

**放弃的方案**

| 方案 | 原因 |
|---|---|
| 只对光标外围的条目跑 locals 查询 | 模块级的 locals 定义也绑定条目里的引用，结果会变（实测 161 个位置的 `site_at` 不同） |
| 只保留位置分析需要的数据，不保留语法树 | `site_at` 按字节位置查找节点、按父节点判断语法，要先把绑定模型改成不依赖语法树的表，改动大；内存不够时再做 |
| 把解析结果持久化到 cache | 语法树不能序列化，读回仍要重新解析 |
| 解析不限大小 | ADR 0034 的理由：大文件的树是源码的几十倍 |
| 在 SQL 里按层排序候选 | 存储按 OID 存放内容，路径属于各个 worktree 的映射，SQL 里没有路径 |
| 查找前先数定义行数，再决定怎么查 | 每次跳转多一条语句；第一页本身就能看出名字是否常见 |
| 去掉每份 128 KiB 的上限，只靠 12 MiB 的合计上限 | 冲突只是挪到约 256 KiB（12 MiB ÷ 48）：更大的文本仍然每次重新解析；两份接近上限的大文本还会互相挤出，读两个文件时来回走冷路径 |
| 页按通过版本筛选的行计（`LIMIT` 在连接之后） | 旧版本的单元、其他语言的行都要读却不计数，一条不能取消的语句可读几千到约 5 万行 |

## 影响

- `code_intel`：在设计文档「跳转到定义」「候选的分层与过滤」「查找引用与调用方」「完整性的核算」「性能」「存储表」里按本 ADR 实现。查询的解析缓存放在 `query/parsed.rs`，存储的分页放在 `store.rs`。
- `bench`：budgets.rs 和 [bench 设计「预算表」](../design/bench.md#预算表)。`code_intel/goto_indexed`、`goto_uncached`、`goto_popular`、`goto_full` 判定第一批 ≤ 20 ms，`goto_cold_parse` 判定 ≤ 32 ms，`goto_full/done` 判定 ≤ 1.02 s，`references_full/all` 判定 ≤ 2 s、`/first` ≤ 200 ms，`parse_cache_bytes` 判定 ≤ 12 MiB。`goto_full` 和 `references_full` 的夹具存着每个单元，每次都要 `Complete`。同文件、对象一侧和其余各项的 `Done` 只记录。
- 上下文抽屉（[#20](https://github.com/SoloJiang/lectern-app/issues/20)）：跳转的候选列表从收到事件到画出 ≤ 18 ms。它的设计文档还没写，写时列入「性能」，并以 `app/goto_candidates` 检查两者之和。
- [技术调研](../design/tech-research.md)「代码导航与编辑」里「语法树不常驻」一句加上本 ADR 的例外。
- ADR 0030、ADR 0034 的状态行和索引注明被本 ADR 修订。

## 已知限制

- 常见名字的第一批是一页加上最近的文件。之后的页各自在页内排序后追加（结果只追加），整体不是全局最优的顺序。
- 时间盒到时没读的数目按定义行计，是文件数的上限。数这个数的语句只读索引，行数随名字的定义数增长（5 万行约几毫秒），每次时间盒到时只做一次。
- 一页的语句按 (unit, kind) 定位，rowid 在其中过滤：一个单元里同一种类的同名定义超过一页时，后面的页会再走过这个单元前面的行。行数以这个单元自己的定义为限（一个文件 ≤ 4 MiB）。
- 超过 128 KiB 的当前文本每次跳转都重新解析，1 MiB 的 TypeScript 约 165 ms（ADR 0034 的实测），不在 50 ms 之内（上面对 ADR 0030 的修订）。
