# ADR 0037：跳转的份额按第一批计、在首次跳转会遇到的状态下测量；当前文本的解析按 blob OID 保留在有上限的内存里

- 状态：已接受
- 日期：2026-10-19
- 修订：[ADR 0034](0034.md)（「解析与高亮」中「阅读时不保留打开文件的整棵语法树」：跳转用的当前文本在 128 KiB 以内时保留它的解析）

## 背景

[ADR 0030](0030.md) 把「跳转到定义：同文件或索引命中，候选列表 ≤ 50 ms」列为顶层预算，[code_intel 设计「性能」](../design/code_intel.md#性能)从中给本 crate 定了 20 ms 的份额，分项是当前文本（100 KB 以内）解析与 locals ≤ 10 ms、按名字查找 ≤ 2 ms、过滤分层排序 ≤ 3 ms。第 4 步的审阅指出这个份额只在最容易的状态下成立：

- 基准重复同一次跳转，核算的遍历已缓存；索引变化后的第一次跳转是未缓存的（实测 16.2 ms 对 19.5 ms）。
- 夹具的当前文本是 64 KiB，而不是这一行写的 100 KB。解析加 locals 在 64 KiB 时约 14–16 ms，随大小线性增长，单这一项就超过 10 ms 的分项；Linux 上三次测得 19.1、24.1、19.8 ms，余量很小。
- 按名字查找没有上限，每行约 7 µs。约 3000 个定义的常见名字（`get`、`new`）多出约 25 ms。
- 10 万文件的仓库约 270 MiB，通常已超过 256 MiB 的配额（满额模式）。这时核算要逐批核对存储，跳转到 `Done` 约 290 ms，查引用约 1.02 s。根作用域、没有子项目或 `Named` 不带 `near` 时，这一核对没有上限，中途也不能取消。
- 设计的分项与实际验证的结论相互矛盾。

当前文本的解析（`ParsedFile`）实测约为源码的 46.6 倍（100 KB 的 TypeScript 约 4.7 MB）。只缩小 locals 的查询范围，结果会变（code_intel「实际验证」的限制试验），所以靠缩小查询降不到 10 ms。[ADR 0034](0034.md) 规定阅读时不保留打开文件的整棵语法树，理由是大文件的树是源码的 14–41 倍（4 MiB 时 134 MiB）。

## 决策

**份额与测量**

- 顶层预算不变。本 crate 的份额是从查询到第一批有候选的结果 ≤ 20 ms，前提是当前文本的解析已保留（见下）。这一条在首次跳转会遇到的状态下分别判定：遍历已缓存、遍历未缓存、约 3000 个定义的常见名字、满额模式。
- `Done` 在查询的 1 s 时间盒内到达，最多再加一条语句；满额模式下判定。
- 取消在 20 ms 内生效，每条路径都是如此：查询里的每条语句都有上限（一页 ≤ 256 行，或 ≤ 500 个 OID），语句之间检查查询是否已停止。
- 当前文本还没有保留解析时的第一次跳转（冷路径）只记录，不按 20 ms 判定；它仍在顶层的 50 ms 之内。
- 分项改为实测值，写进 code_intel 设计「性能」；budgets.rs 和 bench 设计按此修改。

**当前文本的解析按 blob OID 保留**

- 键是（blob OID、语言版本）（架构规则 5），值是整个 `ParsedFile`：任意位置的标识符、定义和绑定模型都可以从它得到。同一文本里再次跳转不读文件、不解析。
- 上限：最多 2 份；源码 ≤ 128 KiB 的才保留；按每字节源码 48 字节估算，合计 ≤ 12 MiB（实测 46.6 字节，`code_intel/parse_cache_bytes`）。超过时淘汰最久未用的一份。一份 60 s 没有用到即释放；它的语言被语言表替换时也立即释放（释放 grammar 的租约）。
- 预热：文本成为当前文本（`Focus::Current`）时预热，冷路径的跳转或预取之后也预热。预热在 `Background` 任务里进行，排在首屏的 `Interactive` 工作之后（ADR 0033、0034）；没有打开的项目时不预热。跳转从不等它。
- 内存：这是只因阅读才填充的缓存，属于 [ADR 0035](0035.md)「关键约束」里由各自的上限约束、不在采样状态里的那一类（与 `file_reader` 的 8 MB 高亮与文本 LRU、`git` 的 hunk LRU 同类）。ADR 0035 把空闲内存的分配对应到 ADR 0017 的采样状态：首页加载完成、没有打开文件、Diff 或会话。只有文本成为当前文本、或者在它里面跳转之后才有保留的解析，所以采样状态（[ADR 0017](0017.md)、[ADR 0029](0029.md) 的 `app/idle_monorepo`、`app/idle_monorepo_indexed`，ADR 0035 的 `app/idle_100k`、`app/idle_100k_indexed`）里没有它，最后一次用到的 60 s 之后也没有它。因此它不占 ADR 0030 和 ADR 0035 分给 `code_intel` 的常驻份额（10 万文件 ≤ 10 MB），也不占 ADR 0035 的 12 MB 余量。阅读时它的上限是 12 MiB，ADR 0035「已知限制」里「审阅之后的空闲内存可以比采样状态多出几个缓存的上限」也包括它。`plugin/code-intel/resident_*` 在测量前丢掉保留的解析，按采样状态测量。
- 修订 ADR 0034：128 KiB 以内的当前文本在被用到的 60 s 内保留语法树。更大的文本仍不保留，每次跳转为光标处重新解析。

**按名字查找有上限**

- 第一批只读两样：名字的第一页定义（≤ 256 行），以及名字还有更多页时，离查询最近的文件（所在目录、所在子项目，≤ 2048 个，每 500 个文件一条语句，每条 ≤ 256 行）里的定义。其余页在之后的批次里逐页追加，直到时间盒。时间盒到时没读的行数计入未搜（上限，按定义行计）。
- `ci_def_name` 改为 (name, unit) 的索引，所以每页和每个文件都只做一次查找。命名空间的版本升为 2，旧表整份重建一次，单元重新抽取。查引用的 `ci_ref` 按同样的页取，页与页之间检查查询是否已停止。

**满额模式的核对**

- 搜索范围内外的每条核对语句之前，都检查查询是否已停止、时间盒是否已到。到时没核对的计为 `Unchecked`：范围内计入未搜，范围外计入 `outside`，从不算作已入索引。
- 第一批不等核对：`Named` 先交出候选，再做核算的遍历；查引用在 `ci_ref` 一轮之后、读搜索范围之前先交出已找到的结果。

**放弃的方案**

| 方案 | 原因 |
|---|---|
| 只对光标外围的条目跑 locals 查询 | 模块级的 locals 定义也绑定条目里的引用，结果会变（实测 161 个位置的 `site_at` 不同） |
| 只保留位置分析需要的数据，不保留语法树 | `site_at` 按字节位置查找节点、按父节点判断语法，要先把绑定模型改成不依赖语法树的表，改动大；内存不够时再做 |
| 把解析结果持久化到 cache | 语法树不能序列化，读回仍要重新解析 |
| 解析不限大小 | ADR 0034 的理由：大文件的树是源码的几十倍 |
| 在 SQL 里按层排序候选 | 存储按 OID 存放内容，路径属于各个 worktree 的映射，SQL 里没有路径 |
| 查找前先数定义行数，再决定怎么查 | 每次跳转多一条语句；第一页本身就能看出名字是否常见 |

## 影响

- `code_intel`：在设计文档「跳转到定义」「候选的分层与过滤」「查找引用与调用方」「完整性的核算」「性能」「存储表」里按本 ADR 实现。查询的解析缓存放在 `query/parsed.rs`，存储的分页放在 `store.rs`。
- `bench`：budgets.rs 和 [bench 设计「预算表」](../design/bench.md#预算表)。`code_intel/goto_indexed`、`goto_uncached`、`goto_popular`、`goto_full` 判定第一批 ≤ 20 ms，`goto_full/done` 判定 ≤ 1.02 s，`references_full/first` 判定 ≤ 200 ms，`parse_cache_bytes` 判定 ≤ 12 MiB。冷路径、同文件、对象一侧和各项的 `Done` 只记录。
- [技术调研](../design/tech-research.md)「代码导航与编辑」里「语法树不常驻」一句加上本 ADR 的例外。
- ADR 0034 的状态行和索引注明被本 ADR 修订。

## 已知限制

- 常见名字的第一批是一页加上最近的文件。之后的页各自在页内排序后追加（结果只追加），整体不是全局最优的顺序。
- 时间盒到时没读的数目按定义行计，是文件数的上限。
- 一个单元里同名定义超过 256 个时，超出的部分不读。
- 超过 128 KiB 的当前文本每次跳转都重新解析，1 MiB 的 TypeScript 约 165 ms（ADR 0034 的实测），超过 50 ms。
