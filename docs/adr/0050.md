# ADR 0050：ACP agent 由用户安装，在插件沙箱之外以用户身份按需启动；Lectern 不声明客户端能力，不代为批准权限

- 状态：已接受
- 日期：2026-10-25
- 修订：[ADR 0018](0018.md)（「核心与可选的划分」表里「agent 适配」一行的「ACP 适配器」：不再是插件市场里的独立进程插件）

## 背景

Conversation 面板（[#23](https://github.com/SoloJiang/lectern-app/issues/23)）和权限请求（[#24](https://github.com/SoloJiang/lectern-app/issues/24)）经 ACP（Agent Client Protocol）与 agent 对话：Lectern 启动一个 ACP agent 子进程（Claude Code 与 Codex 各有一个适配器，[技术调研「Agent 原生面板」](../design/tech-research.md#4-agent-原生面板第二阶段)），经 stdio 上的 JSON-RPC 发出 prompt，收到结构化的消息、工具调用和权限请求。

ADR 0018 把「ACP 适配器」列为插件市场里的独立进程插件，在 Seatbelt 沙箱里运行；进程插件的能力清单默认只读当前项目、只写自己的数据目录、没有网络。ACP agent 的工作正是改项目里的文件、运行构建和测试命令、访问模型服务，它的凭据由它自己管理。它需要的权限与用户在 Terminal 页运行的 `claude --resume` 相同（[agents 设计「服务接口」](../design/agents.md#服务接口lectern-services-的-session-模块)里的恢复命令）。

架构规则 3 不允许 Lectern 引入 Node 这类运行时，而适配器之一是 Node 程序。

## 决策

- **由用户安装。** Lectern 不打包、不下载 ACP agent 和它需要的运行时，插件市场里没有这一类。登录 shell 环境的 PATH 里找不到程序时，界面说明要安装哪个程序。
- **以用户身份运行，不进插件沙箱。** 信任边界与 Terminal 页的恢复命令相同。关键约束：
  - 程序由宿主按 agent 的种类固定映射（Claude Code、Codex 各一个程序名，没有参数）。会话来源、ACP 消息和设置都不能给出程序、参数或环境变量。只对内置会话来源给出 `ResumeCommand` 的会话启动，会话 ID 必须是 UUID 的规范写法。
  - 工作目录是这个会话在会话列表里的 `cwd`，必须在一个已打开项目的 worktree 根或文件夹项目根之内。
  - 环境变量用用户登录 shell 的环境，与 Terminal 页启动 agent 时相同（`platform` 的 `login_env`，本次运行里只取一次，两处共用；取不到时退回 Lectern 进程的环境），去掉 `LECTERN_` 开头的变量；程序在这份环境的 PATH 里查找。取环境要运行一次用户的登录 shell，这不是启动 agent，在后台线程上进行。Lectern 不注入凭据、不检查环境变量的值，不调用 ACP 的 `authenticate`：agent 要求登录时，界面请用户在 agent 的命令行里登录。
- **按需启动，空闲即关。** 只有用户发出一条消息（Conversation 的回复、发回审阅意见）时才启动；打开面板、浏览历史都不启动。没有进行中的 prompt、也没有待确认的权限请求的状态持续 10 分钟，或会话所在的项目关闭，或 Lectern 退出时，关闭连接并终止它的整个进程组。同时最多 3 个连接：第 4 个先关闭最久未用的空闲连接，没有空闲连接时拒绝启动，并在界面说明。ACP agent 不计入 ADR 0017 的空闲内存预算，也不计入 ADR 0018 进程插件 50 MB 的总预算（空闲时它不运行）；与 jdtls 一样单独报告。
- **Lectern 不声明客户端能力。** `initialize` 不声明 `fs` 和 `terminal`：agent 自己读写文件、运行命令，Lectern 不替它读写任何文件，所以 ACP 消息不能让 Lectern 越过项目的边界。`mcpServers` 传空列表。
- **权限只由用户点击批准。** Lectern 不自动回答 `session/request_permission`，没有「全部允许」的开关，不发送改变 agent 权限模式的请求（如 `session/set_mode`）。按钮文字按选项的种类（允许一次、总是允许、拒绝、总是拒绝）由 Lectern 给出，不显示 agent 给选项写的名字。执行命令的请求显示 agent 原始输入里的命令文本，不只显示 agent 写的标题。取消（`session/cancel`）或连接关闭时，待确认的请求按协议回答 `cancelled`。
- **一个会话同一时刻只由 Lectern 里的一处驱动。** 会话已在 Terminal 页恢复时不经 ACP 发送；已有 ACP 连接时不在 Terminal 页恢复。
- **协议版本是 ACP v1。** `initialize` 协商出的版本不是 1 时，不使用这个 agent。

放弃的方案：

| 方案 | 原因 |
|---|---|
| 按 ADR 0018 作为插件市场的进程插件，在 Seatbelt 里运行 | 能力清单要放开整个项目的写权限、任意子进程和网络，沙箱实际上不再限制什么，只多出安装和确认的流程 |
| 随安装包带上适配器和它的运行时 | 违反架构规则 3；适配器的版本跟随 agent 的命令行，由用户的包管理器更新更合适 |
| 声明 `fs` 能力，由 Lectern 代为读写文件 | 要自己限制 agent 请求的路径，攻击面变大；agent 本来就能直接读写，审阅场景里也没有需要交给 agent 的未保存内容 |
| 打开面板就启动 agent 并加载会话 | 违反按需启动；多数审阅只读历史，历史来自本机日志 |

## 影响

- `services`：新增 `conversation` 模块，接口见 [conversation 设计「接口」](../design/conversation.md#接口)。
- `agents`：新增提供 `dyn Conversations` 的插件，实现 ACP 客户端、进程的生命周期和上面的约束。设计文档的修订写明对两个适配器的核对结果（程序名、能否按上游会话 ID 恢复、轮次是否写进同一份本机日志）；不满足的 agent 不提供 ACP 对话。
- `conversation`：Messages 页、权限请求、Terminal 页（[conversation 设计](../design/conversation.md)）；上面「一处驱动」的检查由它做。
- `terminal`：提供「哪个终端在恢复这个会话」的查询（conversation 设计「对其他 crate 的要求」D）。
- `platform`：`login_env` 模块（登录 shell 的环境、在 PATH 里查找程序），`agents` 与 `terminal` 共用（[terminal 设计](https://github.com/SoloJiang/lectern-app/pull/265)「对其他 crate 的要求」第 2 项）。
- [ADR 0018](0018.md) 的状态行与索引注明本条修订。

## 已知限制

- 用户在 Lectern 之外运行的同一会话不能被认定为「正在驱动」，只能按日志的活动给出提示。
- agent 自己的权限设置（如 Claude Code 的 allow 规则）照常生效，Lectern 不显示、不修改。
- 适配器的版本由用户管理；协议的变化由 `agents` 的适配处理。
