# ADR 0016：GPUI 通过 crates.io 的 gpui-pre 快照锁定

- 状态：提议
- 日期：2026-10-16
- 修订：[技术调研](../design/tech-research.md)中「GPUI 用 git 依赖锁 Zed commit」的做法

## 背景

立项时的方案是用 git 依赖引入 GPUI，并让 gpui-component 锁同一个 Zed commit。现在 Zed 把 GPUI 快照发布到 crates.io（`gpui-pre`、`gpui-pre-platform` 等，Apache-2.0），gpui-component 0.7.3 本身就用 `gpui-pre = "=0.3.9"` 精确锁定（对应 Zed `93d7456`）。如果我们继续用 git 依赖，会和 gpui-component 依赖的 GPUI 变成两份，编译不过。

## 决策

- `gpui = { package = "gpui-pre", version = "=0.3.9" }`
- `gpui_platform = { package = "gpui-pre-platform", version = "=0.3.9" }`
- `gpui-component = "=0.7.3"`
- 三者一起升级，GPUI 快照版本必须等于 gpui-component 发布时使用的版本；`Cargo.lock` 提交到仓库。
- 「锁定」的含义不变：未经确认不得升级（AGENTS.md）。

## 影响

- 不再需要拉取 Zed 仓库，首次构建更快，sccache 命中更稳定。
- 升级节奏跟随 gpui-component 的发布，不再自行挑选 Zed commit。
- 风险：gpui-pre 是快照，API 仍可能在小版本间变化；用精确版本号（`=`）规避。
