# ADR 0065：压缩成一行的文件在 `app/open_file` 里只记录，直到它回到下一帧

- 状态：已接受
- 日期：2026-11-21
- 修订：[ADR 0034](0034.md)（「预算」的「测量方式补充」里，压缩成一行的 4 MiB 文件与其他场景「预算相同」一句）

## 背景

[ADR 0034](0034.md) 的「测量方式补充」让 `app/open_file` 在压缩成一行的 4 MiB 文件上判定与其他场景相同的预算。进程级按 [ADR 0063](0063.md) 判定，CI 上为中位数 < 37.5 ms；按 [ADR 0064](0064.md)，只计语言已经编译过的打开。

[#396](https://github.com/SoloJiang/lectern-app/pull/396) 在 CI 上先用同语言的文件预热，再计时（运行 44776257791）：

| 场景 | 中位数 |
|---|---|
| 普通 Rust 文件 | 31.4 ms |
| 4 MiB TypeScript | 32.6 ms |
| 64 MiB TypeScript | 31.9 ms |
| 4 MiB `package-lock.json` | 28.9 ms |
| Diff 的旧版本 | 35.0 ms |
| 压缩成一行的 4 MiB JavaScript | 56.4 ms（样本 44–73 ms） |

只有压缩成一行的文件超标，比 TypeScript 的场景多约 24 ms，约晚一帧到一帧半。原因只找到一部分：

- 进程内的首屏计算（读取、规划、窗口的解析和查询）贵了约 5 ms：`syntax/first_screen/minified` 在 CI 上中位数 6.74 ms，p95 8.68 ms；同一次运行里普通文件的 `syntax/first_screen` 是 1.77 ms。Apple M5 上分别是 3.26 ms 和 0.85 ms。压缩代码没有空白、语法节点密，同样字节数的解析和查询更贵。
- 其余约 19 ms 还没有定位。候选是 UI 线程上第一次排版和绘制一条很长的行、首屏偶尔超过 8 ms 截止时间后等高亮，以及首屏没有赶上视图建好的那一帧。在 GPUI 的测试平台上（M5），压缩成一行的文件从请求到里程碑约 34 ms，多行的同样大小约 16 ms，差别主要不在窗口的解析。

[file_reader 设计「性能」](../design/file_reader.md#性能)已经让进程内的 `syntax/first_screen/minified` 只记录。

## 决策

1. **只记录。** 压缩成一行的 4 MiB 文件的端到端打开改为一个单独的只记录项 `app/open_file/minified`，CI 不判定。产品负责人在 2026-11-21 选定这一点。
2. **其余场景照旧。** `app/open_file` 对其他五个场景（普通文件、4 MiB 与 64 MiB 的 TypeScript、`package-lock.json` 中部、diff 的旧版本）照旧判定中位数 < 37.5 ms，结果取最慢场景的样本。
3. **恢复判定的条件。** [#399](https://github.com/SoloJiang/lectern-app/issues/399) 先按阶段定位这段时间，再修。不论用什么办法，端到端中位数回到 37.5 ms 以内时，另写 ADR 把这个场景恢复到 `app/open_file` 的预算。
4. **不变的约束。** 首屏仍受 8 ms 截止时间约束，超时先画文本（ADR 0034），UI 线程上不做解析。只记录不等于放开这些约束。

放弃的方案：

| 方案 | 原因 |
|---|---|
| 给这个场景单独一个宽松的上限（约 4 帧，< 66.7 ms） | 上限要放到现在读数之上才能通过，判定起不到作用 |
| 先优化，所有场景仍判 37.5 ms | 原因还没有完全定位，改动和收益都不确定，文件阅读其余的工作（#10）要等它 |

## 影响

- `bench`：`app/open_file/minified` 是只记录项，压缩成一行的场景从 `app/open_file` 的最慢场景里拿出；[bench 设计](../design/bench.md)的场景说明和预算表。随 #396 修改。
- [file_reader 设计「性能」](../design/file_reader.md#性能)：写明这个场景只记录。随 #396 修改。
- [技术调研「性能预算」](../design/tech-research.md#性能预算)：「打开文件到首屏高亮」一行加注（本 PR）。
- ADR 0034 的状态行和索引（本 PR）。

## 已知限制

- 压缩成一行的文件打开时，首屏约晚一帧；CI 不会因此失败，只能在基准报告里看到。
