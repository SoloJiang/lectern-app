# ADR 0033：依赖源码按需解析、空闲时只索引直接依赖；后台工作在交互时让路，不区分电源

- 状态：已接受
- 日期：2026-10-18
- 修订：[ADR 0029](0029.md)（「电池供电」一节取消；「已知限制」中暂停开关只供测量一条；四条条件之外增加空闲预取一类）

## 背景

产品要求：跳转用到的依赖文件（如 node_modules）可以异步解析，解析要充分利用空闲时间。产品同时决定：省电模式暂不考虑，建索引不区分电源。

现有规则：被忽略的目录不进文件列表、不建索引、不监听（[技术调研「排除的功能」](../design/tech-research.md#排除的功能)）；导航第 3 层「依赖源码」按需（[ADR 0007](0007.md)）；可暂停的后台工作在批量线程上运行，kernel 有一个只供测量使用的全局暂停开关，电池供电时第 4、5 层暂缓（[ADR 0029](0029.md)，电池一条是待产品确认的默认值）。

[大文件与渲染调研](../research/large-files-rendering.md)第 1、2 节实测（Linux 容器）：

- 一个 21 个直接依赖的 Vite + React + TS 项目，`node_modules` 有 244 个包、10,053 个文件、116 MiB，声明文件 15.6 MiB；直接依赖从类型入口出发、沿相对 import 走到的声明文件（声明闭包）合计约 5 MiB、250 个文件。Next.js 项目的 `node_modules` 有 337 MiB，直接依赖的声明闭包 3.8 MiB。
- 读文件加求 blob OID（sha1dc）约 430–570 MiB/s；`lstat` 每个文件 1.9–3.9 µs。
- 主线程每帧 2 ms 的工作，在 4 个 vCPU 的虚拟机上另有 1–3 个线程解析时，中位数不变，p99 从 5.1 ms 变成 6.5–10.1 ms，占满全部 vCPU 时出现过一次 114 ms。

## 决策

**依赖源码**

- 依赖目录（`node_modules`、Cargo 的 registry 源码、Go 模块缓存、项目里的 Python 虚拟环境）不整体索引、不列出、不监听，规则不变。
- 按需：跳转的 import 解析（`code_intel` 的解析扩展点，TS 由 #19 实现）把裸模块名解析到依赖根里的声明文件时，当场读取和抽取，持有 `BusyGuard`、在 `Interactive` 上运行，计入查询的预算。
- 空闲时：当前子项目清单里的直接依赖，从声明入口出发、沿相对 import、re-export 和 `/// <reference path>` 走到的文件，作为批量层的「依赖层」建索引，排在第 3 层之后、第 4 层之前。它满足 ADR 0029 的四条条件，持有 `BackgroundGuard`。依赖的依赖不建索引，只按需解析。
- 限额：每个包的闭包最多 4,000 个文件、16 MiB；每个项目的依赖层最多读 64 MiB 源码、写入的索引最多 32 MiB，计入 `code_intel.tags` 的 256 MiB 配额；命名空间满时依赖层停下，不为它淘汰项目自己的单元。
- 键：被忽略的文件没有 index 的 OID，按 git 的 blob 格式对内容求哈希（与文件夹项目相同，ADR 0030），抽取结果的键与项目文件相同。包的（相对路径、OID）表存进应用级分库的新命名空间 `code_intel.deps`，键是（生态、包名、版本、身份），配额 8 MiB，各项目共用。
- 包的身份决定是否重读：lockfile 的 `integrity`、`Cargo.lock` 的 `checksum` 或 git 提交、`go.sum` 的哈希、`*.dist-info/RECORD` 的 OID，都没有时取包清单的 OID。身份不变时不读、不 stat；身份变了或取不到时，按（设备号、inode、大小、修改时间、状态改变时间）的 stat 表跳过没变的文件。跳转打开目标文件时按读到的字节重新求 OID，与记下的不同就当场重新抽取。
- 失效：受跟踪的 lockfile 和清单的变化（`fs_watch` 照常交付）、打开项目时的身份检查、跳转时的读取核对。依赖目录本身仍不监听。
- 安全：依赖根只能是工作区之内的目录，或按 Lectern 自己进程的环境得到的用户级缓存（`$CARGO_HOME`、`$GOMODCACHE` 及其默认值，`~/.m2`、`~/.gradle`）；项目文件里写的路径不扩大范围，不为取路径运行外部命令。pnpm 等的符号链接只在依赖根内部解析，目标落在允许的根之外时按读不到处理，其余路径仍只经 `SafeRoot` 读取（[ADR 0028](0028.md)）。
- 放在核心的 `code_intel` 里，不做成插件：不新增依赖，TS / JS 是核心语言（ADR 0018）。Java 的 `-sources.jar` 要 zip 解码器，按 ADR 0007 和 #26 决定归属，键、身份、配额和分层沿用本 ADR。

**空闲时的后台工作**

- 交互静止：300 ms 内没有键盘、鼠标按键、滚轮（含惯性）和拖拽，没有运行中的 `ui` 动效，executor 没有排队或在途的 `Interactive` 任务。由 `app` 在 UI 线程上判断；电源状态不参与。
- 交互让路：kernel 在测量用的暂停开关之外增加一个全局的让路开关，`app` 离开交互静止时打开、回到交互静止时关闭。打开时可暂停的后台工作在下一个批次边界停下，关闭后继续；不放弃在途的那个文件，不改变「静止」和后台工作状态的报告，`Kernel::pause` 的语义和 bench 的采样不变。
- 空闲预取：交互静止时，预先算出审阅集合的下一个未看文件、抽屉里第一个候选的文件、跳转唯一候选的目标文件的高亮区间（和第 1 层的符号抽取），每次进入交互静止最多 4 个文件，结果只进 `file_reader` 已有的 8 MB 高亮与文本 LRU，不另占常驻内存。预取持有 `BackgroundGuard`、在批量线程上运行、受让路开关约束，排在第 3 层之前。它不满足 ADR 0029 第二条（结果写入 `cache`），作为单列的一类：结果只在内存里，丢了在用到时现算，暂停或退出最多丢掉在途的一个文件。
- 首帧之前不做任何一项：没有打开的项目就没有依赖层和预取的来源（ADR 0017）。

**电源**

取消 ADR 0029 的「电池供电」一节：建索引、依赖层和预取不区分电源，`code_intel` 的第 4、5 层不再因电池暂缓；`platform` 不再为此提供电源状态。

放弃的方案：

| 方案 | 原因 |
|---|---|
| 整体索引 `node_modules` | 实测是直接依赖声明闭包的 24 倍，99% 不会被跳到；还要监听被忽略的目录 |
| 监听依赖目录 | 与「不监听被忽略的目录」冲突；`npm install` 一次写上万个文件；lockfile 已经反映了几乎全部变化 |
| 每次打开项目都读一遍闭包求 OID | TS 项目约 10 ms 可以接受，Rust 和 Go 的闭包大一个量级；身份不变时没有必要 |
| 交互时用测量用的暂停开关 | 它放弃在途的文件，连续滚动会让一个大文件反复重做；还会改变 bench 读到的后台状态 |
| 每个插件自己判断空闲 | 只有 `app` 同时知道输入、滚动和动效；分散判断会不一致 |

## 影响

- `code_intel`：依赖层、依赖根的发现、包的身份与 stat 表、读取核对、去掉电源相关的接口和测试；设计文档的改动见调研「设计文档的修改」，在第 4 步合并之后进行。
- `cache`：命名空间表增加 `code_intel.deps`（应用级，8 MiB）。
- `kernel`：让路开关；设计文档「静止」一节写明它与暂停开关的区别。
- `app`：交互静止的判断，打开和关闭让路开关。
- `file_reader`：预取的条目在 LRU 里先于用户打开过的条目淘汰。
- `platform`：不再需要电源状态与变化通知（ADR 0029「影响」中的这一项取消）。
- `bench`：`app/scroll_frames` 另在批量层有工作时测量（`app/scroll_frames_indexing`），预算相同；`code_intel` 增加依赖层的份额基准。
- [技术调研](../design/tech-research.md)：「排除的功能」「跨子项目导航」「性能预算」的索引覆盖一行按本 ADR 修改。

## 已知限制

- lockfile 被忽略或不存在的项目，只在打开项目和跳转时发现依赖的变化。
- 手工改过的依赖文件，在被跳转打开之前，索引里的位置可能过期。
- Python 只支持项目目录里的虚拟环境，不支持全局的 site-packages。
- 交互期间索引停下，频繁交互时整仓索引的完成时间推迟。
- 让路对帧时间的效果只在 Linux 虚拟机上间接测过，M 系列上由帧时间基准确认。
