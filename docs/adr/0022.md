# ADR 0022：用量只统计 token 与额度，不估算费用

- 状态：已接受
- 日期：2026-10-17
- 修订：[ADR 0014](0014.md)（费用）、[ADR 0020](0020.md)（界面位置表里的费用）、[ADR 0018](0018.md)（数据包里的价格表更新）

## 背景

[ADR 0014](0014.md) 规定按 LiteLLM 的价格表把 token 折算成 API-equivalent 费用，[ADR 0020](0020.md) 把这个金额放进了侧栏、worktree 列表和 MR 视图。2026-10-17 人确认不需要估算模型成本。

Lectern 的用户大多用 Claude Code 和 Codex 的订阅，实际约束是额度窗口的百分比，按公开价格折算的金额不是他们的账单，放在 token 旁边容易被误读。维护价格表还要内置快照、联网更新、允许用户覆盖，这部分工作不属于审阅闭环。

## 决策

- Lectern 不计算、不显示任何金额。用量界面只显示 token 和额度窗口。
- token 仍按 ADR 0014 的类别保存（输入、输出、缓存读取、缓存写入），按服务商规范化成互不重叠的类别；缓存命中率由这些类别算出，照常显示。
- 不内置价格表，不联网更新价格，不提供覆盖单价的设置。插件市场的数据包不再包含价格表更新。
- ADR 0020 界面位置表里的「token 与 API-equivalent 费用」都改为只显示 token；MR 视图显示 MR 的累计 token，按会话、按轮次的明细，「编写」与「审阅」分开。
- [ADR 0019](0019.md) 的 Analyze 用量照常记录。那里的「估算（上限）」指 token 数的估算，不是金额。

放弃的方案：保留费用、默认隐藏。仍然要维护价格表，而用户确认过不需要这个数字。

## 影响

- `usage`：去掉价格表，聚合结果只有 token 和额度快照。
- `project_home`、`worktrees`、`usage_view`：用量位置只显示 token；Usage 页的明细表去掉 API-Equivalent 列和说明文字。
- [交互规范](../design/interaction.md)「用量」、README、`cargo-workspace.md` 与 `tech-research.md` 的 crate 表、交互设计画布同步修改。
