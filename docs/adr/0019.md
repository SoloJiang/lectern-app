# ADR 0019：会话简报默认由规则生成，模型分析由用户手动触发

- 状态：已接受
- 日期：2026-10-16

## 背景

审阅页顶部的会话简报列出「值得先看的几处」（[交互规范](../design/interaction.md#核心闭环)），此前没有规定简报的内容从哪里来。[pulls.review 调研](../research/pulls-review.md)提出了两个需要人决定的问题：简报是否调用模型，以及 MR 视图是否读取 pulls.review 写在 PR 里的共享分析评论。2026-10-16 人确认按调研的推荐处理，结论记录在这里。

## 决策

**简报默认只用规则生成**

- 打开会话时，简报只用本地已有的信息生成：Drifted 的行、没有同步修改的调用方、改到的公开接口、噪声文件（生成文件、lockfile、快照）的折叠情况等。规则的完整列表在 `review` 的设计文档里定义。
- 规则生成不调用模型，不消耗额度，在首帧之后的后台任务里计算。

**模型分析由用户手动触发**

- 简报上有一个 Analyze 操作，也可以从 ⌘K 执行。只有用户执行它时才调用模型，Lectern 不在打开会话、切换会话或会话更新时自动调用。
- 调用的是用户本机已登录的 Claude Code 或 Codex 命令行，默认用被审阅会话所属的 agent。Lectern 不保存模型 API key，也不直接请求模型的 HTTP 接口。
- 查找命令行：从 Finder 启动的应用不读取 shell 的启动文件，继承的 `PATH` 常常不含 `~/.local/bin`、`/opt/homebrew/bin` 这类安装位置。Lectern 依次查找设置里配置的绝对路径、用户登录 shell 的 `PATH`（第一次执行 Analyze 时查询一次并缓存）和常见安装目录。找不到时 Analyze 显示为不可用，并说明原因和设置入口。
- 命令行以只读模式运行（Claude Code：`--allowedTools Read Grep Glob`，并禁用 Bash、Edit、Write；Codex：关闭它自己的沙箱（`--sandbox danger-full-access`，审批策略为 `never`），只读和断网由 Lectern 的外层 Seatbelt 配置保证，比 Codex 的 `read-only` 模式更严；Codex 的 `read-only` 模式要再调用 `/usr/bin/sandbox-exec` 套一层沙箱，与下文禁止嵌套沙箱冲突，所以不用。快照不是 git 仓库，所以同时传 `--skip-git-repo-check`），按需启动、完成即退出，符合架构规则 3。
- 被审阅的仓库里的 `AGENTS.md`、`CLAUDE.md` 也是被审阅的内容，可能被改过，不能作为给 agent 的项目指令自动加载。agent 会从项目目录和附加目录自动加载的配置（`CLAUDE.md`、`AGENTS.md`、`.claude/`（skills、commands、agents、settings）、`.codex/`、`.mcp.json` 等，按 agent 列出）不放进 agent 能看到的快照目录。判断一个路径是不是这类配置时按快照所在文件系统的等价规则比较：APFS 默认不区分大小写、不区分 Unicode 规范化形式，所以 `claude.md`、`AGENTS.MD`、`.CLAUDE/settings.json` 以及 NFD 写法的同名路径都算，比较前把每一级名字做 Unicode 大小写折叠和 NFC 规范化，再与按 agent 列出的名字比较（区分大小写的卷上同样按这个更宽的规则处理）。它们另放一份，作为普通数据可读，patch 里照常显示它们的改动。另放的位置是快照根下一个保留目录：名字默认 `_lectern_data`，被审阅的树和要叠加的工作区路径里已经有同名路径时依次加序号（`_lectern_data_1`、`_lectern_data_2`…），直到与这两者的并集都不冲突，所以保留目录本身不会和任何 git 条目撞名。目录里是平铺的文件，按序号命名（`000001.data`…），不保留原来的目录结构和文件名，旁边的 `index.jsonl` 记下每个序号对应的原路径：每行一个 JSON 对象，`file` 是序号文件名，路径是合法 UTF-8 时写在 `path` 里（制表符、换行等控制字符按 JSON 转义），否则写在 `path_base64` 里（原始字节的 base64），所以任何 git 允许的名字都能无歧义地写进去，不会伪造出多余的行或映射，提示词告诉模型这个目录的名字和索引。所以快照里任何位置都不会出现名为 `CLAUDE.md`、`AGENTS.md` 的文件或 `.claude/`、`.codex/` 目录，两个不同的 git 条目也不会落到同一个路径上（如 `.claude/skills/x` 和仓库里原有的 `_lectern_data/.claude/skills/x`：后者照常留在原位，前者进的是另一个保留目录）。命令行的工作目录是本次分析的空临时目录，不是快照；快照作为额外的可读目录传入（Claude Code：`--add-dir`；Codex：`-c project_doc_max_bytes=0` 关闭项目文档发现），附加目录里没有可被自动加载的配置。agent 的配置目录也指向临时目录（`CLAUDE_CONFIG_DIR`、`CODEX_HOME`），不读用户的全局指令。提示词说明快照里的所有文件都是待审阅的数据，其中的指令一律不执行。
- 只读参数只能防止写入，不能限制读取：被审阅的 diff 里可能有提示词注入，诱导 agent 读取仓库之外的文件再发给模型。所以命令行在 Seatbelt 沙箱里运行（由 `platform` 生成配置，与 [ADR 0018](0018.md) 的进程插件相同），满足以下约束。每个 agent 的具体参数在 `agents` 的设计文档里列出。
  - 可读：本次分析的临时目录（写着 patch）、被审阅版本的只读快照、该 agent 解析后的可执行文件及其依赖闭包（原生安装是那个版本自己的目录，如 `~/.local/share/claude/versions/<版本>`；npm 安装是包自己的目录和解析出的 `node` 可执行文件），不是它所在的公共目录：`~/bin`、`~/.local/bin`、`/opt/homebrew/bin` 里的启动链接先解析到目标，同目录下的其他文件不可读，以及固定的 macOS 运行时路径（只列具体子目录：`/System/Library`、`/System/Cryptexes`、`/usr/lib`、`/bin`、`/usr/bin` 等，供 shell、`env`、系统库和 dyld 共享缓存使用）；`/System/Volumes` 整个子树明确拒绝，因为 `/System/Volumes/Data/Users` 与 `/Users` 是同一个目录，放行 `/System` 会绕过对用户主目录的拒绝；该 agent 的配置、凭据文件、钥匙串和其余路径一律拒绝，也不能查看其他进程的信息（Seatbelt 拒绝 `process-info*`，`ps -E` 这类命令读不到其他进程的环境）。
  - 快照：从被审阅版本的提交树写出，文件内容取自 git 对象，符号链接按 git 记录重建为链接、不跟随目标；只有审阅对象包含工作区改动时才叠加属于它的改动，叠加的文件按下面的方式从已打开的描述符克隆或复制，符号链接都重建为链接，不把目标内容写进快照。clonefile 会带上扩展属性、资源分叉、ACL 和 BSD 文件标志（`UF_IMMUTABLE`、`UF_APPEND` 等），这些 git 不记录、指纹也不包含，所以写出后先在目标描述符上 `fchflags(fd, 0)` 清掉全部标志（否则不可变标志会让后续的清理和删除临时目录失败），再移除扩展属性、资源分叉和 ACL，只保留 git 能表示的内容和可执行位。叠加的文件按 git 的规范形式写出：基准快照来自 git 对象，是规范形式，所以工作区文件要先经过与生成 diff 相同的内置转换（`working-tree-encoding`、行尾转换、`ident`；不执行外部过滤器）再写进快照，例如 UTF-16 的工作区文件写成 UTF-8，模型读到的内容与 patch 和其他文件一致；没有适用的转换时直接从描述符复制。只接受普通文件和符号链接，类型检查和读取用同一个文件描述符，不分成「先按路径检查、再按路径读取」：每个要叠加的路径从 worktree 根目录的描述符出发，用 `openat` 带 `O_NOFOLLOW_ANY | O_NONBLOCK` 打开一次：`O_NOFOLLOW_ANY`（macOS 11 起）对路径的每一级都不跟随符号链接，中间某一级目录被换成符号链接时打开失败，这个路径按「路径经过符号链接」拒绝，不会读到 worktree 之外的文件；`O_NONBLOCK` 让 FIFO 的打开立即返回，不会卡住；对这个描述符 `fstat`，是普通文件才继续，克隆和复制都从这个描述符进行（`fclonefileat`，卷不支持时 `fcopyfile` 带 `COPYFILE_DATA`），快照里的内容哈希也从写出的这份计算；打开返回 `ELOOP` 时，再用 `O_NOFOLLOW_ANY` 打开它的父目录（失败说明中间一级是链接，按上面拒绝），父目录正常时说明最后一级是符号链接，从父目录描述符 `readlinkat` 读出目标、重建为链接；FIFO、socket、设备文件在 `fstat` 后拒绝，标为「不支持的文件类型」。所以检查之后路径被换成另一个文件，读到的仍是检查过的那个 inode，换进来的 FIFO 也不会让分析卡住。子模块（模式 `160000` 的 gitlink）在快照里只是一个空目录，记录的提交 OID 写在 patch 里，不复制子模块的工作区。审阅对象改动了 gitlink 时，模型看不到子模块里新旧两个提交之间的代码，所以分析结果标为「部分内容未提供」，并列出改动的子模块和新旧 OID，不显示为完整分析。改动的文件用了 clean / process 过滤器（如 Git LFS）时同样如此：快照里只有仓库里的对象（LFS 的是指针文件），`git` 也不为它生成 diff，模型看不到改动前后的真实内容，分析结果标为「部分内容未提供」并列出这些文件。写出之前逐项检查 git 树里的名字：空名、`.`、`..`、含 `/` 或 NUL 的名字、`.git`（不分大小写）都按损坏的树处理，Analyze 显示为不可用；写出时从快照根目录的文件描述符出发，用 `openat` / `mkdirat` 加 `O_NOFOLLOW` 逐级创建，保证写到的位置都在快照根目录之下。条目数和路径长度也有上限（默认 20 万个条目、路径合计 64 MB），按 git 树和要叠加的工作区路径的并集计算（上限按并集，比最终集合大，保守），读树和列出叠加路径时边读边检查，超过时不写出。再检查路径冲突：检查的是叠加之后快照里最终存在的路径集合，先按工作区的改动状态从 git 树的路径里去掉删除和重命名的旧路径，再加上新增和重命名的新路径（`Foo` 改名为 `foo` 这类只改大小写的重命名，最终只剩 `foo`，不算冲突）；这个集合里只有大小写或 Unicode 规范化形式不同的路径，在 macOS 默认的大小写不敏感、规范化不敏感的卷上会互相覆盖，检测到时 Analyze 显示为不可用并说明原因，不生成不完整的快照。快照里只有受 git 跟踪的文件和本次改动的文件，`.env` 这类被忽略或无关的未跟踪文件不在其中；即使有指向快照之外的符号链接，沙箱也按解析后的路径拒绝读取。快照总大小有上限（默认 500 MB），超过时 Analyze 显示为不可用并说明原因。diff 里被截断的文件，删除或修改前的那一版内容写进本次分析的临时目录 `base/`，模型可以读到被删掉的代码。`base/` 与保留目录用同样的平铺方式：文件按序号命名，`base/index.jsonl` 按同样的格式记下原路径，不按原路径重建目录，所以临时目录（agent 的工作目录）里也不会出现 agent 在读到文件时会自动加载的指令文件或配置目录；那一版本身也超过单文件上限时，分析结果标为「部分内容未提供」，不显示为完整分析。这些改动前的版本合计也有上限（默认 200 MB、5000 个文件），计入本次分析的临时目录，超过后不再写出，结果同样标为「部分内容未提供」；只复用不含工作区改动的基准快照：按树 OID 缓存，写出后只读，不再修改；审阅对象包含工作区改动时，每次分析用 clonefile 把基准快照目录克隆一份（APFS 写时复制，几乎不占额外空间）到本次分析的临时目录，在克隆上叠加改动，分析结束随临时目录删除，不复用，所以两个共享同一提交、改动不同的 worktree，以及同一 worktree 前后两次不同的改动，各自读到自己的内容；所有快照合计按字节 LRU 淘汰（默认 2 GB）；正在进行的分析用到的快照有引用计数，不参与淘汰，分析结束后才可以淘汰。只因为这些快照正在使用而超出上限时，允许暂时超出，但最多多出一个快照的上限（500 MB），再要开始新的分析时排队等待。快照缓存和每次分析的临时目录都放在一个有容量上限的稀疏 APFS 磁盘映像里：第一次使用 Analyze 时用 `hdiutil` 创建（不需要特权，默认上限 4 GB，按实际写入占用空间），挂载到 Lectern 的缓存目录下（`-nobrowse`，不出现在 Finder 里），没有进行中的分析、空闲 5 分钟后卸载。映像写满时写入直接返回 `ENOSPC`，由内核在写入之前限制，所以 agent 的 shell 写得再快也只会写满这个映像，不会占满用户的卷。快照的 LRU（2 GB）在映像之内；工作区文件跨卷叠加时 `fclonefileat` 失败，改用 `fcopyfile`。全局同时最多进行 2 次分析，其余排队；每次分析的临时目录另有 1 GB 的软上限，与进程一起每 500 ms 统计一次，超过时按下面的方式终止，避免一次分析占满映像、影响另一次；稀疏映像只限制虚拟容量，不预先占用宿主卷的空间，所以每次开始分析前（不只是创建映像时）检查宿主卷：剩余空间至少是映像还能增长的量（容量上限减去当前实际占用）再加 2 GB，不满足时这次分析排队，并提示释放空间，这样映像即使被写满，宿主卷也还留有 2 GB；分析进行中仍每 500 ms 检查一次，宿主卷剩余空间低于 2 GB（其他程序占用了空间）时终止全部分析。每次分析的临时目录和叠加的工作区文件在成功、失败、取消后都删除。Lectern 崩溃或被强制退出时，清理不能只靠 Lectern 自己：agent 经一个监护进程启动（Lectern 可执行文件以监护模式运行，只在分析期间存在，符合架构规则 3），监护进程与 Lectern 之间保持一条管道，读到 EOF（Lectern 已退出）时按这次分析的沙箱特征扫描并分两步终止全部成员，然后退出；监护进程本身不在沙箱里，agent 杀不掉它也改不了它。Lectern 启动时还会按上次异常退出留下的每个临时目录对应的沙箱特征再扫描一次，终止残留的成员，之后才删除这些目录和卸载映像。先生成快照，再从快照计算 diff 和指纹，指纹包含快照里每个改动文件的路径、改动状态、新旧文件模式和内容的哈希（只改了可执行位也会让指纹不同），在截断 diff 用于显示之前计算，不受上限影响：模型读到的内容、显示的 patch 和缓存键来自同一份状态，分析开始后工作区再变也不会对不上。
  - 凭据：真实凭据不进入沙箱，也不放进子进程的环境变量或参数。agent 能执行的命令（如 Codex 的 shell）可能被提示词注入利用，读取自己进程的环境、文件或钥匙串，沙箱分不开 agent 的登录代码和它的工具。所以 Lectern 在本机回环地址上提供一个凭据转发端点：命令行的模型服务地址指向这个端点，只拿到一个占位令牌；Lectern 在沙箱外取得真实凭据（环境变量、agent 的钥匙串条目或凭据文件），把请求转发给该 agent 配置的模型服务主机时换上真实凭据。命令行不支持设置模型服务地址时，这个 agent 的 Analyze 显示为不可用并说明原因。端点只转发该 agent 的推理接口：按 agent 列出允许的方法和路径（如 Claude Code 的 `POST /v1/messages`、Codex 的 `POST /v1/responses`），请求体里的模型必须是这次分析配置的模型，其他路径、方法和模型一律拒绝；请求体还要符合该 agent 的适配器生成的模板（按命令行版本维护）：只允许模板列出的字段，嵌套结构也按模板逐层检查；与安全和计费相关的字段必须等于模板里的值，不只是名字在列表里：必须是流式请求，`store` 一类让服务端保存请求或输出的字段必须为 `false`（Codex 的请求构造代码固定写 `false`），`background` 一类异步执行的选项必须缺省，工具定义、`include` 一类会让服务端返回额外数据的字段只能取模板里的取值；不认识的字段和取值一律拒绝，所以每个被接受的请求都在这个连接上同步完成，结束时带回最终用量，不会在超时或取消之后继续在服务端运行，所以 agent 的 shell 读到端点地址也调不了该主机的其他接口。同一次分析同时只处理一个请求，不排队：已有请求在转发时，新请求直接返回 429，不读请求体，agent 按自己的重试逻辑稍后重发；端点同时最多保持 4 个连接，多出的连接立即关闭，请求头上限 64 KB，空闲 30 秒的连接关闭。所以沙箱里的 shell 并发发起大量请求，也只占用固定的内存和文件描述符。轮数和 token 预算在转发之前检查并计入：请求体超过 4 MB 直接拒绝；输入 token 在转发前算出，模型服务有计数接口时用它（如 Anthropic 的 `POST /v1/messages/count_tokens`，由端点在沙箱外调用），没有时按请求体的 UTF-8 字节数作为上界估计，超过剩余预算就拒绝；转发时把请求体里的输出上限（`max_tokens` 一类字段）改为不超过剩余预算。
  - 模型服务的配置：用户为该 agent 配置的模型服务（Amazon Bedrock、Google Vertex AI、公司网关、自定义 CA 与代理）按白名单逐项传入，只包括服务类型、地址、区域、CA 证书这类非工具配置；其中需要的密钥或取密钥的辅助命令由 Lectern 在沙箱外处理，只在转发端点上使用。hooks、MCP 服务器、额外工具和其他环境变量一律不传。
  - 可写：只有本次分析的临时目录。agent 的配置目录指向它，所以辅助会话的日志也写在这里，用量导入后随临时目录删除，不留在用户的会话目录里。
  - 资源：命令行以后台优先级运行（`PRIO_DARWIN_BG`），不抢前台的 CPU；每个进程用 `setrlimit` 设置 CPU 时间上限（子进程继承）；macOS 没有不需要特权的内存配额：`RLIMIT_AS` 不支持，`RLIMIT_DATA` 管不住 `mmap` 分配，也没有按一组进程合计的内核限额，所以内存只能靠统计和系统内存压力来限制（见下文），这是已知限制；哪些进程属于这次分析按沙箱判断，不按进程组或父子关系：Seatbelt 沙箱由所有子孙进程继承，换进程组、`setsid`、double fork 后被 launchd 收养都去不掉。每次分析的沙箱配置允许读本次唯一的临时目录、拒绝读一个固定的哨兵路径，Lectern 枚举当前用户的全部进程（`proc_listallpids`），用 `sandbox_check` 检查这两条权限，同时满足的就是这次分析的进程；kqueue `EVFILT_PROC` 的 `NOTE_FORK` 只用来提前触发一次扫描。这个识别方式要求子孙进程不能换上另一份沙箱配置（否则一份更严格的嵌套配置可以拒绝读临时目录，让自己不再满足这两条权限）：已经在 Seatbelt 沙箱里的进程再调用 `sandbox_init` / `sandbox_apply` 会被拒绝（`EPERM`），沙箱配置另外明确拒绝执行 `/usr/bin/sandbox-exec`。Lectern 首次使用 Analyze 前做一次自检：在这份配置下启动一个探针进程，尝试再应用一份嵌套配置，成功（说明当前系统允许嵌套）时，带 shell 的 agent 的 Analyze 不可用并说明原因；macOS 大版本更新后重新自检。`platform` 用不了 `sandbox_check` 时，带 shell 的 agent（Codex）的 Analyze 同样不可用。每 500 ms 统计这些进程的数量和常驻内存合计，以及 CPU 时间合计（常驻内存在两次统计之间增长超过 512 MB 时，改为每 100 ms 统计，直到回落），超过上限（默认 64 个进程、4 GB、合计 300 CPU 秒）时终止这次分析的全部进程，按失败处理。Lectern 同时监听系统内存压力（`DISPATCH_SOURCE_TYPE_MEMORYPRESSURE`），进入警告级别时立即终止全部进行中的分析，不等下一次统计。两次统计之间分配的内存仍可能短暂超过 4 GB；由于 Seatbelt 已经禁止网络（除凭据转发端点）和临时目录之外的写入，这种情况的后果是本机短时的内存压力，分析随后被终止，ADR 接受这个限制。CPU 合计包括已经退出的成员：每个成员取 `proc_pid_rusage` 里自己的 CPU 时间加上它已回收的子孙的 CPU 时间（`ri_child_user_time`、`ri_child_system_time`），扫描到过、之后退出的成员按最后一次采样的值继续计入。被 launchd 收养、又在两次扫描之间退出的进程仍可能漏计，所以 300 CPU 秒是提前终止的阈值，硬上界是每次调用的超时：默认 10 分钟，超时就按上面的方式终止，一次分析消耗的 CPU 不超过超时乘以核数，且始终是后台优先级。终止（超限、超时、取消和分析结束）分两步，不和不停 fork 的进程赛跑：先按沙箱扫描，对找到的每个进程发 `SIGSTOP`，再扫描、再暂停，直到一次扫描找不到还在运行的成员（暂停的进程不能再 fork，所以这一步会收敛）；然后对全部成员发 `SIGKILL`。agent 的标准输出和标准错误也有上限：单条 JSON 行 1 MB，合计 64 MB，Lectern 边读边计数，超过时按上面的方式终止，按失败处理，不把超出的部分读进内存。
  - 网络：只允许连接 Lectern 的凭据转发端点；端点只转发到该 agent 当前配置的模型服务主机（与 ADR 0018 的本机代理相同的放行方式）。
- 每次分析有用量上限，纠错重试也计算在内：轮数上限默认 12 轮（Claude Code 用 `--max-turns`，不支持该参数的 agent 由 Lectern 从输出流里计数）；命令行支持单次请求输出上限的，按剩余预算设置。输入加输出 token 上限默认 300k，Lectern 在凭据转发端点上按每个响应里的用量字段累计，达到时终止进程；转发前按剩余预算改写输出上限（见「凭据」），所以累计值不会超过上限。请求都经过转发端点，输入在转发前计数或按上界估计，输出上限按剩余预算改写，所以累计值不超过上限。任一上限达到时按失败处理。
- 每次调用有超时（默认 10 分钟）。超时、用户取消、离开审阅页或关闭项目时，Lectern 终止全部跟踪中的子孙进程并回收，丢弃尚未返回的输出，不留下在后台运行的 agent，也不会在之后显示过期的结果。分析返回、显示之前，再算一次当前审阅对象的指纹，与分析用的快照指纹比较：不一致（审阅页没离开，但工作区或会话已经变了）时不当作当前结果显示，标为「基于较早的版本」并提供重新分析。
- 分析在单独的会话里运行，不续接被审阅的会话。这个辅助会话不出现在 Lectern 的会话列表里：可用时用不保存会话的调用方式；否则它写在本次分析的临时目录里，随临时目录删除（包括启动时清理上次异常退出留下的目录），会话发现不扫描这个目录。
- 模型的输出是 `critical` 标记加文件备注和行备注，经过结构校验、覆盖检查、一次纠错重试和对账后才显示；校验失败时报错，保留规则生成的简报，不把规则结果当作模型结果保存。
- 结果按完整分析请求的哈希缓存（规范化后的提示词、每个文件规范化后的完整 patch 的哈希（包含新旧路径、blob OID、文件模式和改动状态）、被审阅 worktree 的指纹（基准树 OID 加每个改动文件的路径、改动状态、新旧文件模式和完整内容（符号链接为目标）的哈希，因为 agent 可以读快照里的任何文件，包括 diff 被截断时只列出路径的文件）、schema 版本、模型 ID，以及调用的 agent、它的命令行版本和影响输出的模型服务配置）。这次调用消耗的 token 计入用量统计（[ADR 0014](0014.md)），在简报上显示：用量在凭据转发端点上记录：每个模型请求的响应一到达，就按其中的用量字段写入一条原始用量记录交给 `usage`（带本次分析的 ID），所以超时、取消或失败的分析中途已经发生的请求也计入；请求在返回最终用量之前被中断时，输入按请求体估算，输出按已经转发的流式片段估算，合起来记一条，标为「估算」。辅助会话不写入用户的会话目录，不会被重复计算。

**MR 视图只读取 pulls.review 的共享分析评论**

- MR 视图读取 PR 评论里带 `<!-- pulls.review data -->` 标记的分析结果，作为这个 PR 的分组参考显示。
- 评论可能来自任何人，所以只有受信任作者的评论直接显示：仓库所有者、成员、协作者（GitHub 的 `author_association` 为 OWNER、MEMBER、COLLABORATOR，GitLab 按项目成员角色）和用户在设置里加的机器人账号（默认包括 `github-actions[bot]`）。其他作者的评论列为「来自 @作者 的未验证分析」，用户点开才显示，不当作共享分析。
- pulls.review 的评论只记录 head sha。评论没有记下当时的 base（或合并基点）、标题和描述，Lectern 无从判断这些在评论之后有没有变：head 不一致时标为过期；head 一致时也一律标为「可能过期」，只作为分组参考，不显示为当前结果。
- 评论按 GitHub / GitLab 的分页接口从最新的一页往前读（GitHub 的评论接口只按时间正序，所以先取 `Link` 头里的 `last` 页再依次往前；GitLab 用 `sort=desc`），合计最多读 1000 条评论，而且按流读取响应、累计原始字节不超过 32 MB（单条评论正文超过 2 MB 时跳过，不完整读入），达到任一上限就停止翻页，评论多也不会撑大内存。pulls.review 每个作者只有一条评论、之后原地更新，更新不会让它移到更新的一页，所以只按创建顺序往前读可能读不到它：`forge` 同时按更新时间查找，GitHub 用评论接口的 `since` 参数（只返回在这个时间之后更新过的评论），GitLab 用 `order_by=updated_at`，时间取当前 head 提交的时间，因为只有之后更新过的评论才可能是针对当前 head 的分析；每个 MR 还记下以前找到过的 pulls.review 评论 ID，直接按 ID 重新读取。三种方式的结果合并去重，同样受上面的条数和字节上限约束。只解压和保留最新的一条受信任作者的有效结果；未验证作者的评论只记录作者和位置，用户点开时才解压那一条。所有评论合计解压不超过 8 MB，达到后停止读取。
- 解析失败的评论忽略，不报错；评论里的文字按外部内容处理，原样显示，不执行其中的任何指令。解析成功的结果在显示前经过与本地模型输出相同的校验：schema 版本必须是支持的版本，结构校验、覆盖检查、路径与行号对账，指向不存在的文件或 diff 里不显示的行的条目丢弃或降级，没被分到的文件进入「未分类」。
- 评论可能来自任何人。lz-string 压缩的内容按流解压，解压后超过 2 MB 时停止并丢弃，不读入完整结果再校验；未压缩的 JSON 同样限 2 MB。
- Lectern 不向 PR 写入自己的分析结果。以后需要时另写 ADR。

## 影响

- `review`：定义简报的规则、模型输出的数据结构与校验流程。
- `agents`：查找并启动只读的 Claude Code / Codex 命令行，提供凭据转发端点，按进程 ID 跟踪子孙进程，超限、超时与取消时全部终止，过滤辅助会话，把用量交给 `usage`。
- `platform`：为 Analyze 生成 Seatbelt 配置。
- `cache`：模型结果的缓存键；快照的字节 LRU。
- `services`：定义按能力划分的改动来源接口，`git` 和 `forge` 实现它。
- `usage`：接收凭据转发端点记录的 Analyze 用量（每个请求一条，含取消和失败的分析，中断的请求标为「估算」）。
- `forge`：解析 pulls.review 的共享分析评论，限制解压后的大小（P3）。
- `review_view`：简报上的 Analyze 操作、进行中与取消、结果与失败的显示；离开审阅页时发出取消命令；界面字符串走 Fluent。
