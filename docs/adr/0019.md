# ADR 0019：会话简报默认由规则生成，模型分析由用户手动触发

- 状态：已接受
- 日期：2026-10-16

## 背景

审阅页顶部的会话简报列出「值得先看的几处」（[交互规范](../design/interaction.md#核心闭环)），此前没有规定简报的内容从哪里来。[pulls.review 调研](../research/pulls-review.md)提出了两个需要人决定的问题：简报是否调用模型，以及 MR 视图是否读取 pulls.review 写在 PR 里的共享分析评论。2026-10-16 人确认按调研的推荐处理，结论记录在这里。

模型分析的风险来自被审阅的内容本身：diff 和仓库文件可能含有提示词注入，诱导 agent 读取仓库之外的文件、泄露凭据或向外发请求。所以调用模型的方式要满足的约束比「只读参数」更多。

## 决策

**简报默认只用规则生成**

- 打开会话时，简报只用本地已有的信息生成：Drifted 的行、没有同步修改的调用方、改到的公开接口、噪声文件（生成文件、lockfile、快照）的折叠情况等。规则列表由 `review` 的设计文档定义。
- 规则生成不调用模型，不消耗额度，在首帧之后的后台任务里计算。

**模型分析由用户手动触发**

- 简报上有一个 Analyze 操作，也可以从 ⌘K 执行。只有用户执行它时才调用模型，Lectern 不在打开、切换或更新会话时自动调用。
- 调用用户本机已登录的 Claude Code 或 Codex 命令行，默认用被审阅会话所属的 agent。Lectern 不保存模型 API key，也不直接请求模型的 HTTP 接口。命令行按需启动、完成即退出（架构规则 3）。找不到命令行或当前系统满足不了下面的约束时，Analyze 显示为不可用并说明原因。
- 分析在单独的辅助会话里运行，不续接被审阅的会话；辅助会话不出现在会话列表里，随本次分析的临时目录删除。

放弃的方案：

- 打开会话时自动调用模型：每次打开都消耗额度，与「首帧之前不做非必要工作」和用户对用量的控制冲突。
- 由 Lectern 直接请求模型 API：要保存 API key，又要自己维护各家的模型配置；复用用户已登录的命令行没有这些成本。

**Analyze 的关键约束**

1. **只读，且读取范围受限。** 命令行在 `platform` 生成的 Seatbelt 沙箱里运行（与 [ADR 0018](0018.md) 的进程插件相同）。可读的只有：本次分析的输入（patch、改动前的版本）、被审阅版本的只读快照、该 agent 自己的可执行文件及依赖、系统运行时路径。用户主目录、其他项目、agent 自己的配置和凭据一律拒绝。子进程不继承 Lectern 打开的任何文件描述符。
2. **快照只含受 git 跟踪的文件和本次改动。** 快照从被审阅版本的 git 树写出，有工作区改动时叠加属于审阅对象的改动；`.env` 这类被忽略或未跟踪的无关文件不在其中。写出时不跟随符号链接，不读到 worktree 之外的文件。
3. **被审阅仓库里的 agent 配置不作为指令加载。** 仓库里的 `CLAUDE.md`、`AGENTS.md`、`.claude/`、`.codex/`、`.mcp.json` 等会被 agent 自动加载的文件也是被审阅的内容，可能被改过。它们移出快照中 agent 会自动加载的位置，作为普通数据另放；agent 的配置目录指向临时目录，不读用户的全局指令。提示词声明快照里的内容都是数据。
4. **凭据不进入沙箱。** 真实凭据不放进子进程的文件、环境变量或参数。命令行的模型服务地址指向 Lectern 在回环地址上的凭据转发端点，只拿到占位令牌；端点在沙箱外换上真实凭据，只转发该 agent 的推理接口和本次配置的模型，拒绝服务端执行的工具（网页搜索、代码执行、远程 MCP 等）。命令行不支持设置模型服务地址时，这个 agent 的 Analyze 不可用。
5. **只能写本次分析的工作目录。** agent 只能写临时目录里的 `work/`，它放在一个单独的、有容量上限的磁盘映像里，写满时由内核拒绝写入，影响不到用户的卷和审阅的输入。
6. **网络只通向凭据转发端点。** 端点只连到该 agent 当前配置的模型服务主机。
7. **有资源上限。** 每次分析默认最多 12 轮、300k token、10 分钟；后台优先级；进程数、内存和 CPU 时间有上限，超出时终止这次分析的全部进程。全局同时最多 2 次分析。快照缓存默认 2 GB、单个快照 500 MB。
8. **取消和超时不留残余。** 超时、取消、离开审阅页或关闭项目时，终止这次分析的全部子孙进程（按沙箱识别，不按进程组），并中止正在转发的上游请求。Lectern 崩溃或卡住时，由一个只在分析期间存在的监护进程完成同样的清理。
9. **结果要对得上当前版本。** 模型读到的快照、显示的 patch 和缓存键来自同一份状态。结果显示前重新比较审阅对象的指纹和会话修订号，不一致就标为「基于较早的版本」并提供重新分析。快照缺了部分内容（子模块、LFS、超过上限的改动前版本）时，结果标为「部分内容未提供」。
10. **输出经过校验。** 模型输出是 `critical` 标记加文件备注和行备注，经过结构校验、覆盖检查、一次纠错重试和对账后才显示；校验失败时报错，保留规则生成的简报。
11. **结果和用量可追溯。** 结果按完整分析请求的哈希缓存（提示词、patch、worktree 指纹、schema、模型、agent 与版本、处理规则和分析流程的版本）。用量由凭据转发端点按请求记录、交给 `usage`（[ADR 0014](0014.md)），中途取消或失败的请求也计入，无法确认的按上限估算并标明。

**MR 视图只读取 pulls.review 的共享分析评论**

- MR 视图读取 PR 评论里带 `<!-- pulls.review data -->` 标记的分析结果，作为这个 PR 的分组参考。
- 只有受信任作者的评论直接显示：对仓库有写权限的人（按代码平台的权限接口查询，不看 `author_association`）和用户在设置里加的机器人账号（按平台主机加账号的不变 ID 比较，不按用户名）。其他作者的评论列为「来自 @作者 的未验证分析」，用户点开才显示。
- 评论只记录 head sha，不记录 base、标题和描述，所以一律标为「可能过期」，只作为分组参考，不显示为当前结果。
- 评论内容按外部输入处理：读取的条数、字节和解压后的大小都有上限，解析失败的忽略；解析成功的结果经过与本地模型输出相同的校验后才显示；其中的文字不作为指令。读到上限仍未找到时标为「共享分析可能未找到」，不当作没有。
- Lectern 不向 PR 写入自己的分析结果。以后需要时另写 ADR。

## 影响

实现细节由各 crate 的设计文档定义；设计文档写出之前，以各 crate 的 AGENTS.md 和本 ADR 精简前的版本（[7a19055](https://github.com/SoloJiang/lectern-app/blob/7a19055/docs/adr/0019.md)）为准。

- `review`：简报规则、模型输出的数据结构与校验流程。
- `agents`：查找并启动命令行、凭据转发端点、按沙箱跟踪和终止进程、过滤辅助会话、把用量交给 `usage`。
- `platform`：Seatbelt 配置，以及受限进程的启动与监护、安全的文件读取与克隆、磁盘映像等 macOS 专属机制（架构规则 6）；其他 crate 只调用它的平台无关接口。
- `git`：快照写出、工作区指纹、diff 截断与改动前版本。
- `fs_watch`：worktree 修订号，供结果过期判断。
- `cache`：模型结果的缓存键、快照的字节 LRU。
- `services`：按能力划分的改动来源接口，`git` 和 `forge` 实现它。
- `usage`：接收 Analyze 的用量记录。
- `forge`：读取和校验 pulls.review 的共享分析评论（P3）。
- `review_view`：简报上的 Analyze 操作、进行中与取消、结果与失败的显示；界面字符串走 Fluent。
- [交互规范](../design/interaction.md)「核心闭环」第 3 步补充简报的来源。

## 已知限制

- macOS 没有不需要特权的按进程组内存配额，内存靠定期统计和系统内存压力限制，两次统计之间可能短暂超过上限。
- `RLIMIT_NPROC` 按用户的进程总数计算，不是精确的「最多 64 个子孙」，超出部分靠统计终止。
- 系统允许嵌套 Seatbelt 配置或 `sandbox_check` 不可用时，带 shell 的 agent（Codex）的 Analyze 不可用。
- 受信任作者的权限查询有缓存和每次读取的数量上限，超出的作者这次按未验证处理。
