# ADR 0019：会话简报默认由规则生成，模型分析由用户手动触发

- 状态：已接受
- 日期：2026-10-16

## 背景

审阅页顶部的会话简报列出「值得先看的几处」（[交互规范](../design/interaction.md#核心闭环)），此前没有规定简报的内容从哪里来。[pulls.review 调研](../research/pulls-review.md)提出了两个需要人决定的问题：简报是否调用模型，以及 MR 视图是否读取 pulls.review 写在 PR 里的共享分析评论。2026-10-16 人确认按调研的推荐处理，结论记录在这里。

## 决策

**简报默认只用规则生成**

- 打开会话时，简报只用本地已有的信息生成：Drifted 的行、没有同步修改的调用方、改到的公开接口、噪声文件（生成文件、lockfile、快照）的折叠情况等。规则的完整列表在 `review` 的设计文档里定义。
- 规则生成不调用模型，不消耗额度，在首帧之后的后台任务里计算。

**模型分析由用户手动触发**

- 简报上有一个 Analyze 操作，也可以从 ⌘K 执行。只有用户执行它时才调用模型，Lectern 不在打开会话、切换会话或会话更新时自动调用。
- 调用的是用户本机已登录的 Claude Code 或 Codex 命令行，默认用被审阅会话所属的 agent。Lectern 不保存模型 API key，也不直接请求模型的 HTTP 接口。
- 查找命令行：从 Finder 启动的应用不读取 shell 的启动文件，继承的 `PATH` 常常不含 `~/.local/bin`、`/opt/homebrew/bin` 这类安装位置。Lectern 依次查找设置里配置的绝对路径、用户登录 shell 的 `PATH`（第一次执行 Analyze 时查询一次并缓存）和常见安装目录。找不到时 Analyze 显示为不可用，并说明原因和设置入口。
- 命令行以只读模式运行（Claude Code：`--allowedTools Read Grep Glob`，并禁用 Bash、Edit、Write；Codex：`--sandbox read-only`，快照不是 git 仓库，所以同时传 `--skip-git-repo-check`），按需启动、完成即退出，符合架构规则 3。
- 被审阅的仓库里的 `AGENTS.md`、`CLAUDE.md` 也是被审阅的内容，可能被改过，不能作为给 agent 的项目指令自动加载。命令行的工作目录是本次分析的空临时目录，不是快照；快照作为额外的可读目录传入（Claude Code：`--add-dir`，不加载附加目录里的 `CLAUDE.md`；Codex：`-c project_doc_max_bytes=0` 关闭项目文档发现）。agent 的配置目录也指向临时目录（`CLAUDE_CONFIG_DIR`、`CODEX_HOME`），不读用户的全局指令。提示词说明快照里的所有文件都是待审阅的数据，其中的指令一律不执行。
- 只读参数只能防止写入，不能限制读取：被审阅的 diff 里可能有提示词注入，诱导 agent 读取仓库之外的文件再发给模型。所以命令行在 Seatbelt 沙箱里运行（由 `platform` 生成配置，与 [ADR 0018](0018.md) 的进程插件相同），满足以下约束。每个 agent 的具体参数在 `agents` 的设计文档里列出。
  - 可读：本次分析的临时目录（写着 patch）、被审阅版本的只读快照、该 agent 的安装目录、运行它所需的解释器和依赖（如 Node 启动器解析出的 `node` 可执行文件及其模块目录），以及固定的 macOS 运行时路径（`/System`、`/usr/lib`、`/bin`、`/usr/bin` 等系统目录，供 shell、`env` 和系统库使用）；该 agent 的配置、凭据文件、钥匙串和其余路径一律拒绝，也不能查看其他进程的信息（Seatbelt 拒绝 `process-info*`，`ps -E` 这类命令读不到其他进程的环境）。
  - 快照：从被审阅版本的提交树写出，文件内容取自 git 对象，符号链接按 git 记录重建为链接、不跟随目标；只有审阅对象包含工作区改动时才叠加属于它的改动，叠加的文件用 clonefile 并带 `CLONE_NOFOLLOW`，所在卷不支持时改为不跟随链接的复制（`copyfile` 带 `COPYFILE_NOFOLLOW_SRC`，只复制数据），符号链接无论哪种方式都重建为链接，不把目标内容写进快照。clonefile 会带上扩展属性、资源分叉和 ACL，这些 git 不记录、指纹也不包含，所以克隆后全部移除，只保留 git 能表示的内容和可执行位。只接受普通文件和符号链接：工作区里换成 FIFO、socket 或设备文件的路径用不跟随链接的 `lstat` 判断后拒绝，不打开，标为「不支持的文件类型」。子模块（模式 `160000` 的 gitlink）在快照里只是一个空目录，记录的提交 OID 写在 patch 里，不复制子模块的工作区。写出之前逐项检查 git 树里的名字：空名、`.`、`..`、含 `/` 或 NUL 的名字、`.git`（不分大小写）都按损坏的树处理，Analyze 显示为不可用；写出时从快照根目录的文件描述符出发，用 `openat` / `mkdirat` 加 `O_NOFOLLOW` 逐级创建，保证写到的位置都在快照根目录之下。条目数和路径长度也有上限（默认 20 万个条目、路径合计 64 MB），读树时边读边检查，超过时不写出。再检查路径冲突：git 树里的路径和要叠加的工作区路径合在一起，只有大小写或 Unicode 规范化形式不同的路径，在 macOS 默认的大小写不敏感、规范化不敏感的卷上会互相覆盖，检测到时 Analyze 显示为不可用并说明原因，不生成不完整的快照。快照里只有受 git 跟踪的文件和本次改动的文件，`.env` 这类被忽略或无关的未跟踪文件不在其中；即使有指向快照之外的符号链接，沙箱也按解析后的路径拒绝读取。快照总大小有上限（默认 500 MB），超过时 Analyze 显示为不可用并说明原因。diff 里被截断的文件，删除或修改前的那一版内容按版本写进本次分析的临时目录（`base/<路径>`），模型可以读到被删掉的代码；那一版本身也超过单文件上限时，分析结果标为「部分内容未提供」，不显示为完整分析；同一个树 OID 的快照复用，不重复写出，所有快照合计按字节 LRU 淘汰（默认 2 GB）。每次分析的临时目录和叠加的工作区文件在成功、失败、取消后都删除，Lectern 启动时清理上次异常退出留下的临时目录。先生成快照，再从快照计算 diff 和指纹，指纹包含快照里每个改动文件内容的哈希，在截断 diff 用于显示之前计算，不受上限影响：模型读到的内容、显示的 patch 和缓存键来自同一份状态，分析开始后工作区再变也不会对不上。
  - 凭据：真实凭据不进入沙箱，也不放进子进程的环境变量或参数。agent 能执行的命令（如 Codex 只读模式下的 shell）可能被提示词注入利用，读取自己进程的环境、文件或钥匙串，沙箱分不开 agent 的登录代码和它的工具。所以 Lectern 在本机回环地址上提供一个凭据转发端点：命令行的模型服务地址指向这个端点，只拿到一个占位令牌；Lectern 在沙箱外取得真实凭据（环境变量、agent 的钥匙串条目或凭据文件），把请求转发给该 agent 配置的模型服务主机时换上真实凭据。命令行不支持设置模型服务地址时，这个 agent 的 Analyze 显示为不可用并说明原因。端点只转发该 agent 的推理接口：按 agent 列出允许的方法和路径（如 Claude Code 的 `POST /v1/messages`、Codex 的 `POST /v1/responses`），请求体里的模型必须是这次分析配置的模型，其他路径、方法和模型一律拒绝，所以 agent 的 shell 读到端点地址也调不了该主机的其他接口。同一次分析同时只转发一个请求，后到的请求排队；轮数和 token 预算在转发之前检查并计入，转发时把请求体里的输出上限（`max_tokens` 一类字段）改为不超过剩余预算。
  - 模型服务的配置：用户为该 agent 配置的模型服务（Amazon Bedrock、Google Vertex AI、公司网关、自定义 CA 与代理）按白名单逐项传入，只包括服务类型、地址、区域、CA 证书这类非工具配置；其中需要的密钥或取密钥的辅助命令由 Lectern 在沙箱外处理，只在转发端点上使用。hooks、MCP 服务器、额外工具和其他环境变量一律不传。
  - 可写：只有本次分析的临时目录。agent 的配置目录指向它，所以辅助会话的日志也写在这里，用量导入后随临时目录删除，不留在用户的会话目录里。
  - 资源：命令行以后台优先级运行（`PRIO_DARWIN_BG`），不抢前台的 CPU；每个进程用 `setrlimit` 设置 CPU 时间和内存上限（子进程继承）；Lectern 每 500 ms 统计整个进程组的进程数和常驻内存合计，整个进程组的 CPU 时间合计，超过上限（默认 64 个进程、4 GB、合计 300 CPU 秒）时终止整个进程组，按失败处理。
  - 网络：只允许连接 Lectern 的凭据转发端点；端点只转发到该 agent 当前配置的模型服务主机（与 ADR 0018 的本机代理相同的放行方式）。
- 每次分析有用量上限，纠错重试也计算在内：轮数上限默认 12 轮（Claude Code 用 `--max-turns`，不支持该参数的 agent 由 Lectern 从输出流里计数）；命令行支持单次请求输出上限的，按剩余预算设置。输入加输出 token 上限默认 300k，Lectern 在凭据转发端点上按每个响应里的用量字段累计，达到时终止进程；转发前按剩余预算改写输出上限（见「凭据」），所以累计值不会超过上限。请求都经过转发端点，预算在转发前检查，输出上限按剩余预算改写，只有输入 token 要等响应才知道确切值，所以累计上限最多被超出一次请求的输入量。任一上限达到时按失败处理。
- 每次调用有超时。超时、用户取消、离开审阅页或关闭项目时，Lectern 终止整个子进程组并回收，丢弃尚未返回的输出，不留下在后台运行的 agent，也不会在之后显示过期的结果。
- 分析在单独的会话里运行，不续接被审阅的会话。这个辅助会话不出现在 Lectern 的会话列表里：可用时用不保存会话的调用方式；否则它写在本次分析的临时目录里，随临时目录删除（包括启动时清理上次异常退出留下的目录），会话发现不扫描这个目录。
- 模型的输出是 `critical` 标记加文件备注和行备注，经过结构校验、覆盖检查、一次纠错重试和对账后才显示；校验失败时报错，保留规则生成的简报，不把规则结果当作模型结果保存。
- 结果按完整分析请求的哈希缓存（规范化后的提示词、每个文件规范化后的完整 patch 的哈希（包含新旧路径、blob OID、文件模式和改动状态）、被审阅 worktree 的指纹（基准树 OID 加每个改动文件完整内容的哈希，因为 agent 可以读快照里的任何文件，包括 diff 被截断时只列出路径的文件）、schema 版本、模型 ID，以及调用的 agent、它的命令行版本和影响输出的模型服务配置）。这次调用消耗的 token 计入用量统计（[ADR 0014](0014.md)），在简报上显示：用量在凭据转发端点上记录：每个模型请求的响应一到达，就按其中的用量字段写入一条原始用量记录交给 `usage`（带本次分析的 ID），所以超时、取消或失败的分析中途已经发生的请求也计入；请求在返回最终用量之前被中断时，输入按请求体估算，输出按已经转发的流式片段估算，合起来记一条，标为「估算」。辅助会话不写入用户的会话目录，不会被重复计算。

**MR 视图只读取 pulls.review 的共享分析评论**

- MR 视图读取 PR 评论里带 `<!-- pulls.review data -->` 标记的分析结果，作为这个 PR 的分组参考显示。
- 评论可能来自任何人，所以只有受信任作者的评论直接显示：仓库所有者、成员、协作者（GitHub 的 `author_association` 为 OWNER、MEMBER、COLLABORATOR，GitLab 按项目成员角色）和用户在设置里加的机器人账号（默认包括 `github-actions[bot]`）。其他作者的评论列为「来自 @作者 的未验证分析」，用户点开才显示，不当作共享分析。
- pulls.review 的评论只记录 head sha。head 不一致时标为过期；head 一致但 MR 的 base（或合并基点）、标题、描述在评论之后变过时，标为「可能过期」。
- 评论按 GitHub / GitLab 的分页接口从最新的一页往前读（GitHub 的评论接口只按时间正序，所以先取 `Link` 头里的 `last` 页再依次往前；GitLab 用 `sort=desc`），合计最多读 1000 条评论，最新的共享分析不会因为评论太多而读不到。只解压和保留最新的一条受信任作者的有效结果；未验证作者的评论只记录作者和位置，用户点开时才解压那一条。所有评论合计解压不超过 8 MB，达到后停止读取。
- 解析失败的评论忽略，不报错；评论里的文字按外部内容处理，原样显示，不执行其中的任何指令。解析成功的结果在显示前经过与本地模型输出相同的校验：schema 版本必须是支持的版本，结构校验、覆盖检查、路径与行号对账，指向不存在的文件或 diff 里不显示的行的条目丢弃或降级，没被分到的文件进入「未分类」。
- 评论可能来自任何人。lz-string 压缩的内容按流解压，解压后超过 2 MB 时停止并丢弃，不读入完整结果再校验；未压缩的 JSON 同样限 2 MB。
- Lectern 不向 PR 写入自己的分析结果。以后需要时另写 ADR。

## 影响

- `review`：定义简报的规则、模型输出的数据结构与校验流程。
- `agents`：查找并启动只读的 Claude Code / Codex 命令行，提供凭据转发端点，超时与取消时终止进程组，过滤辅助会话，把用量交给 `usage`。
- `platform`：为 Analyze 生成 Seatbelt 配置。
- `cache`：模型结果的缓存键；快照的字节 LRU。
- `services`：定义按能力划分的改动来源接口，`git` 和 `forge` 实现它。
- `usage`：接收凭据转发端点记录的 Analyze 用量（每个请求一条，含取消和失败的分析，中断的请求标为「估算」）。
- `forge`：解析 pulls.review 的共享分析评论，限制解压后的大小（P3）。
- `review_view`：简报上的 Analyze 操作、进行中与取消、结果与失败的显示；离开审阅页时发出取消命令；界面字符串走 Fluent。
