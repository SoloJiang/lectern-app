# ADR 0019：会话简报默认由规则生成，模型分析由用户手动触发

- 状态：已接受
- 日期：2026-10-16

## 背景

审阅页顶部的会话简报列出「值得先看的几处」（[交互规范](../design/interaction.md#核心闭环)），此前没有规定简报的内容从哪里来。[pulls.review 调研](../research/pulls-review.md)提出了两个需要人决定的问题：简报是否调用模型，以及 MR 视图是否读取 pulls.review 写在 PR 里的共享分析评论。2026-10-16 人确认按调研的推荐处理，结论记录在这里。

## 决策

**简报默认只用规则生成**

- 打开会话时，简报只用本地已有的信息生成：Drifted 的行、没有同步修改的调用方、改到的公开接口、噪声文件（生成文件、lockfile、快照）的折叠情况等。规则的完整列表在 `review` 的设计文档里定义。
- 规则生成不调用模型，不消耗额度，在首帧之后的后台任务里计算。

**模型分析由用户手动触发**

- 简报上有一个 Analyze 操作，也可以从 ⌘K 执行。只有用户执行它时才调用模型，Lectern 不在打开会话、切换会话或会话更新时自动调用。
- 调用的是用户本机已登录的 Claude Code 或 Codex 命令行，默认用被审阅会话所属的 agent。Lectern 不保存模型 API key，也不直接请求模型的 HTTP 接口。
- 查找命令行：从 Finder 启动的应用不读取 shell 的启动文件，继承的 `PATH` 常常不含 `~/.local/bin`、`/opt/homebrew/bin` 这类安装位置。Lectern 依次查找设置里配置的绝对路径、用户登录 shell 的 `PATH`（第一次执行 Analyze 时查询一次并缓存）和常见安装目录。找不到时 Analyze 显示为不可用，并说明原因和设置入口。
- 命令行以只读模式运行（Claude Code：`--allowedTools Read Grep Glob`，并禁用 Bash、Edit、Write；Codex：`--sandbox read-only`），按需启动、完成即退出，符合架构规则 3。
- 只读参数只能防止写入，不能限制读取：被审阅的 diff 里可能有提示词注入，诱导 agent 读取仓库之外的文件再发给模型。所以命令行在 Seatbelt 沙箱里运行（由 `platform` 生成配置，与 [ADR 0018](0018.md) 的进程插件相同），满足以下约束。每个 agent 的具体参数在 `agents` 的设计文档里列出。
  - 可读：本次分析的临时目录（写着 patch）、被审阅版本的只读快照、该 agent 的安装目录；该 agent 的配置、凭据文件、钥匙串和其余路径一律拒绝，也不能查看其他进程的信息（Seatbelt 拒绝 `process-info*`，`ps -E` 这类命令读不到其他进程的环境）。
  - 快照：从被审阅版本的提交树写出，文件内容取自 git 对象，符号链接按 git 记录重建为链接、不跟随目标；只有审阅对象包含工作区改动时才叠加属于它的改动，叠加的文件用 clonefile 并带 `CLONE_NOFOLLOW`，所在卷不支持时改为不跟随链接的复制（`copyfile` 带 `COPYFILE_NOFOLLOW_SRC`），符号链接无论哪种方式都重建为链接，不把目标内容写进快照。快照里只有受 git 跟踪的文件和本次改动的文件，`.env` 这类被忽略或无关的未跟踪文件不在其中；即使有指向快照之外的符号链接，沙箱也按解析后的路径拒绝读取。快照总大小有上限（默认 500 MB），超过时 Analyze 显示为不可用并说明原因；同一个树 OID 的快照复用，不重复写出，所有快照合计按字节 LRU 淘汰（默认 2 GB）。每次分析的临时目录和叠加的工作区文件在成功、失败、取消后都删除，Lectern 启动时清理上次异常退出留下的临时目录。先生成快照，再从快照计算 diff 和指纹，指纹包含快照里每个改动文件内容的哈希，在截断 diff 用于显示之前计算，不受上限影响：模型读到的内容、显示的 patch 和缓存键来自同一份状态，分析开始后工作区再变也不会对不上。
  - 凭据：真实凭据不进入沙箱，也不放进子进程的环境变量或参数。agent 能执行的命令（如 Codex 只读模式下的 shell）可能被提示词注入利用，读取自己进程的环境、文件或钥匙串，沙箱分不开 agent 的登录代码和它的工具。所以 Lectern 在本机回环地址上提供一个凭据转发端点：命令行的模型服务地址指向这个端点，只拿到一个占位令牌；Lectern 在沙箱外取得真实凭据（环境变量、agent 的钥匙串条目或凭据文件），把请求转发给该 agent 配置的模型服务主机时换上真实凭据。命令行不支持设置模型服务地址时，这个 agent 的 Analyze 显示为不可用并说明原因。
  - 模型服务的配置：用户为该 agent 配置的模型服务（Amazon Bedrock、Google Vertex AI、公司网关、自定义 CA 与代理）按白名单逐项传入，只包括服务类型、地址、区域、CA 证书这类非工具配置；其中需要的密钥或取密钥的辅助命令由 Lectern 在沙箱外处理，只在转发端点上使用。hooks、MCP 服务器、额外工具和其他环境变量一律不传。
  - 可写：只有本次分析的临时目录和该 agent 写会话所需的目录。
  - 网络：只允许连接 Lectern 的凭据转发端点；端点只转发到该 agent 当前配置的模型服务主机（与 ADR 0018 的本机代理相同的放行方式）。
- 每次分析有用量上限，纠错重试也计算在内：轮数上限默认 12 轮（Claude Code 用 `--max-turns`，不支持该参数的 agent 由 Lectern 从输出流里计数）；命令行支持单次请求输出上限的，按剩余预算设置。输入加输出 token 上限默认 300k，Lectern 从输出流里累计用量，达到时终止进程。命令行在发出请求之前不经过 Lectern，所以累计上限最多被超出一次请求的量（一次请求的输入加上它的输出上限），这是能保证的界限。任一上限达到时按失败处理。
- 每次调用有超时。超时、用户取消、离开审阅页或关闭项目时，Lectern 终止整个子进程组并回收，丢弃尚未返回的输出，不留下在后台运行的 agent，也不会在之后显示过期的结果。
- 分析在单独的会话里运行，不续接被审阅的会话。这个辅助会话不出现在 Lectern 的会话列表里：可用时用不保存会话的调用方式，否则记录它的会话 ID，会话发现时过滤掉。
- 模型的输出是 `critical` 标记加文件备注和行备注，经过结构校验、覆盖检查、一次纠错重试和对账后才显示；校验失败时报错，保留规则生成的简报，不把规则结果当作模型结果保存。
- 结果按完整分析请求的哈希缓存（规范化后的提示词、每个文件规范化后的完整 patch 的哈希（包含新旧路径、blob OID、文件模式和改动状态）、被审阅 worktree 的指纹（基准树 OID 加每个改动文件完整内容的哈希，因为 agent 可以读快照里的任何文件，包括 diff 被截断时只列出路径的文件）、schema 版本、模型 ID，以及调用的 agent、它的命令行版本和影响输出的模型服务配置）。这次调用消耗的 token 计入用量统计（[ADR 0014](0014.md)），在简报上显示：`agents` 从命令行的结构化输出里取出用量，交给 `usage` 作为一条带会话 ID 的原始用量记录；辅助会话如果也被保存到日志里，`usage` 按会话 ID 去重，同一次调用只计一次。

**MR 视图只读取 pulls.review 的共享分析评论**

- MR 视图读取 PR 评论里带 `<!-- pulls.review data -->` 标记的分析结果，作为这个 PR 的分组参考显示。
- 评论可能来自任何人，所以只有受信任作者的评论直接显示：仓库所有者、成员、协作者（GitHub 的 `author_association` 为 OWNER、MEMBER、COLLABORATOR，GitLab 按项目成员角色）和用户在设置里加的机器人账号（默认包括 `github-actions[bot]`）。其他作者的评论列为「来自 @作者 的未验证分析」，用户点开才显示，不当作共享分析。
- pulls.review 的评论只记录 head sha。head 不一致时标为过期；head 一致但 MR 的 base（或合并基点）、标题、描述在评论之后变过时，标为「可能过期」。
- 评论按 GitHub / GitLab 的分页接口读取全部页（合计最多读 1000 条评论），不只看第一页。只解压和保留最新的一条受信任作者的有效结果；未验证作者的评论只记录作者和位置，用户点开时才解压那一条。所有评论合计解压不超过 8 MB，达到后停止读取。
- 解析失败的评论忽略，不报错；评论里的文字按外部内容处理，原样显示，不执行其中的任何指令。解析成功的结果在显示前经过与本地模型输出相同的校验：schema 版本必须是支持的版本，结构校验、覆盖检查、路径与行号对账，指向不存在的文件或 diff 里不显示的行的条目丢弃或降级，没被分到的文件进入「未分类」。
- 评论可能来自任何人。lz-string 压缩的内容按流解压，解压后超过 2 MB 时停止并丢弃，不读入完整结果再校验；未压缩的 JSON 同样限 2 MB。
- Lectern 不向 PR 写入自己的分析结果。以后需要时另写 ADR。

## 影响

- `review`：定义简报的规则、模型输出的数据结构与校验流程。
- `agents`：查找并启动只读的 Claude Code / Codex 命令行，提供凭据转发端点，超时与取消时终止进程组，过滤辅助会话，把用量交给 `usage`。
- `platform`：为 Analyze 生成 Seatbelt 配置。
- `cache`：模型结果的缓存键；快照的字节 LRU。
- `services`：定义按能力划分的改动来源接口，`git` 和 `forge` 实现它。
- `usage`：接收 Analyze 调用的用量记录，按会话 ID 与日志去重。
- `forge`：解析 pulls.review 的共享分析评论，限制解压后的大小（P3）。
- `review_view`：简报上的 Analyze 操作、进行中与取消、结果与失败的显示；离开审阅页时发出取消命令；界面字符串走 Fluent。
