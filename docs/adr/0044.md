# ADR 0044：审阅的用户标注存为按仓库分开的追加日志，不进 cache

- 状态：已接受
- 日期：2026-10-21

## 背景

审阅（[#15](https://github.com/SoloJiang/lectern-app/issues/15)）要记住用户做过的事：哪些文件标为已看、一个会话按哪个提交作为基准，以及之后的审阅意见（[#22](https://github.com/SoloJiang/lectern-app/issues/22)）。`crates/review/AGENTS.md` 规定已看状态和审阅意见「可以从 git 对象、会话 JSONL 和用户标注日志重建」：前两者是派生数据的来源，第三者只记录用户的操作，删掉就找不回。

已有的两种本地存储都不合适：

- `cache`（[cache 设计](../design/cache.md)）只存可以随时删除重建的派生数据，按字节 LRU 淘汰，版本不符或损坏时整份重建。用户的标记放进去会被淘汰掉。
- [ADR 0027](0027.md) 规定只有 `cache` 和 `usage` 直接使用 rusqlite，两者的页缓存合计 8 MB（[ADR 0017](0017.md)）。`usage` 的数据库归 `usage` 所有，`review` 与 `usage` 都是插件，不能直接共用对方的存储（[ADR 0025](0025.md)）。

数据量很小：一个已看标记约 250 字节，一个仓库通常几百到几千条；读取的模式是打开项目时整份读入、之后只追加。

## 决策

- `review` 把用户标注写进应用数据目录下的 `review/` 目录，每个仓库一个文件，按 git 公共目录的绝对规范路径区分（文件名取路径哈希，与 `cache` 的分库命名方式相同），同一仓库的 worktree 共用。文件夹项目不写。
- 格式是追加写的 JSON 行：第一行是带格式版本和仓库路径的文件头，之后每行一条记录（已看、取消已看、会话基准；#22 加入审阅意见）。由 `review` 自己读写，用工作区已有的 `serde_json`，不引入新依赖，不用 SQLite。
- 只记录用户的操作和为了让标记保持有效而必须固定下来的选择（会话基准）。归因、改动叙事、简报都是派生数据，进 `cache` 或每次重算。

关键约束：

- 不在用户的 `.git` 或项目目录里写任何文件。
- 首帧之前不读；只在 executor 的任务里读写，UI 线程上不做任何文件操作。界面上的勾选先在内存里生效，写盘在后台进行（[交互规范「动效」](../design/interaction.md#动效)「界面先更新」）。
- 每批追加之后 `fdatasync`。读取时末尾不完整的一行丢弃，并在下一次追加之前截掉。
- 文件超过 4 MiB 时压缩：只保留仍然有效的记录，写临时文件后原子改名替换，不原地改写。
- 认不出的记录（以后版本加入的类型）原样保留，压缩时也保留；坏行跳过并计数。
- 文件丢失或损坏只让已看状态回到「未看」，不阻止审阅。

放弃的方案：

| 方案 | 原因 |
|---|---|
| 存进 `cache` | 会被 LRU 淘汰、随版本变化整份删除，违反 `cache`「不存只有这里才有的数据」的边界 |
| 存进 `usage` 的数据库 | 归另一个插件所有；插件之间只经 `services` 交互（ADR 0025），为几千条记录设计跨插件的写接口不划算 |
| `review` 自己的 SQLite 数据库 | ADR 0027 把 rusqlite 限定在两个 crate，再加一个要重新分配 8 MB 的页缓存预算；追加日志足够 |
| 写进用户仓库（git notes、`refs/`、`.git` 下的文件） | 修改用户的仓库，`git` 的只读约束（[git 设计「范围」](../design/git.md#范围)）也不允许 |
| 每个审阅对象一个文件 | 大量小文件，打开项目时要列目录、逐个读 |

## 影响

- `review`：日志的记录格式、压缩、损坏处理和内存里的索引由 [review 设计](../design/review.md)「标注日志」负责。
- `platform`：提供应用数据目录（macOS 是 `~/Library/Application Support/` 下的应用目录），`app` 把其中的 `review/` 传给 `review`；`usage` 的数据库以后放在同一个应用数据目录下。由 review 设计「对其他 crate 的要求」列出。
- `cache`、`usage`、ADR 0027 不变。

## 已知限制

- 同时运行两个 Lectern 进程写同一个仓库的日志时，两边的追加可能交错成坏行，坏行按上文跳过；Lectern 只运行一个实例。
- 文件不跨机器同步；换机器后已看状态从「未看」开始。
