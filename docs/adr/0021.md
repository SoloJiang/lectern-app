# ADR 0021：文档链接检查用 pulldown-cmark 与 html5gum 解析

- 状态：已接受
- 日期：2026-10-16

## 背景

`just check` 要检查仓库里所有 Markdown 文件的相对链接和锚点（[CI 与约束检查「文档链接检查」](../design/ci.md#文档链接检查)），因为设计文档、ADR 和 AGENTS.md 之间的链接改名或删节后会失效，agent 读到失效链接会找不到规则原文。

最初的 Python 脚本用正则识别链接，Codex 审阅时连续发现漏判和误判：引用式链接、容器里的标题、代码块与代码片段、HTML 注释、跨行的 HTML 标签、`script` 里的示例、字符引用。每一种都是 Markdown 或 HTML 的语法规则，靠正则逐条补不完。

## 决策

- 链接检查是 tool 层的 crate `lectern-doc-check`，用 Rust 实现，只由 `just check` 运行，不链接进 Lectern 应用。
- Markdown 用 [pulldown-cmark](https://crates.io/crates/pulldown-cmark) 0.13 按 CommonMark 渲染成 HTML（`default-features = false`，只开 `html`，MIT）。
- 渲染出的整篇 HTML 用 [html5gum](https://crates.io/crates/html5gum) 0.8 按 WHATWG HTML 标准一次分词，链接、标题和锚点都从分词结果取，不在 Markdown 事件之间自己维护分词状态（`default-features = false`，MIT）：字符引用、注释、`script` / `style` 等原始文本元素都按标准处理。
- 标题锚点按 GitHub 的规则生成：要删掉的字符取自 github-slugger 2.0.0 的 `regex.js`，逐个码点求值后写成 `crates/doc_check/src/slug_table.rs` 里的区间表，不引入 Unicode 分类的依赖。
- 两个依赖的版本只写在根 `Cargo.toml` 的 `[workspace.dependencies]` 里。html5gum 只给 `doc_check` 用；应用以后渲染 Markdown 时用什么解析器，在对应 crate 的设计文档里另行决定，不受本 ADR 约束。

## 影响

- 根 `Cargo.toml`、`crates/doc_check`、`justfile` 的 `check`。
- `cargo-deny` 的许可证检查覆盖这两个依赖，均在允许列表内。
- 不进入应用的二进制，不影响 [ADR 0017](0017.md) 的启动与内存预算和 [ADR 0018](0018.md) 的安装包预算。
