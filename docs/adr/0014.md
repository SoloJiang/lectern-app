# ADR 0014：接入 token 用量与额度统计

- 状态：已接受，统计单位与界面位置已被 [ADR 0020](0020.md) 修订
- 日期：2026-10-16

## 决策

Lectern 从本地会话日志统计 token 用量，并显示 agent 的额度窗口。用量信息显示在对应的会话和项目界面里，不做成独立的仪表盘应用。

**数据来源**

| | Claude Code | Codex |
|---|---|---|
| token | `type:"assistant"` 记录的 `message.usage`：`input_tokens`、`output_tokens`、`cache_creation_input_tokens`、`cache_read_input_tokens`，模型取 `message.model` | `event_msg` 中 `payload.type:"token_count"`：`info.last_token_usage`（本轮增量）与 `info.total_token_usage`（会话累计），模型取 `turn_context` |
| 额度 | 日志里没有；通过 Claude Code 的 statusline 输入获取 `rate_limits.five_hour` / `seven_day` | 日志里有：`payload.rate_limits.primary` / `secondary` 的 `used_percent`、`window_minutes`、`resets_at` |

**解析规则**（参照 [ccusage](https://github.com/ryoppippi/ccusage) 的适配器说明，MIT）

- Claude Code 每个内容块写一行、重复同一份 usage：按 `message.id` + `requestId` 去重，保留 token 合计最大的一条；sidechain 重放保留非 sidechain 的一条；同一 `requestId` 跨会话文件只计一次；子 agent 会话在 `<session>/subagents/` 下，计入父会话。
- Codex 的 `input_tokens` 已包含缓存命中部分，`reasoning_output_tokens` 已包含在 `output_tokens` 里；子 agent 会话先重放父会话历史，只统计 `task_started` 之后的用量；`.jsonl` 与 `.jsonl.zst` 都要读取。
- 用 serde 自行解析，不把 ccusage 作为运行时依赖；ccusage 的 `--json` 输出只在测试里做对照。
- Claude Code 默认删除 30 天前的会话文件，所以聚合结果写入 Lectern 自己的 SQLite。

**费用**

- 按 LiteLLM 的 `model_prices_and_context_window.json` 计算：内置一份快照，联网时更新，允许用户覆盖单个模型的价格。
- 界面统一标为「API-equivalent」。订阅用户的实际约束是额度百分比，不是这个金额。

**Claude Code 额度默认开启**

- 用户没有配置 statusline：安装 Lectern 的脚本。
- 用户已有 statusline：保留原命令。Lectern 的脚本先保存一份收到的 JSON，再原样传给原命令，输出不变。
- 首次生效时提示一次；设置里可关闭，关闭时恢复原配置。

**界面位置**

| 位置 | 内容 | 阶段 |
|---|---|---|
| 项目主页会话卡片 | 会话 token 数 | P1 |
| 审阅页会话简报 | 会话 token 数与 API-equivalent 费用 | P1 |
| 审阅页每轮标题 | 该轮 token 数与占会话比例 | P1 |
| Conversation 面板 | 上下文窗口占用、本会话累计 token | P2 |
| 项目侧栏底部 | Usage 入口，带最紧张的额度窗口进度条，快到上限时变色 | P2 |
| Usage 页（按需层） | 额度卡片、每日 token 柱状图（按 agent 堆叠）、按会话与按模型的明细；当前项目 / 所有项目切换 | P2 |

## 影响

- 新增领域 crate `usage`：从 `agents` 的解析结果聚合 token，负责去重、价格表与额度快照；不依赖 `gpui`。
- `platform` crate 负责安装和恢复 Claude Code 的 statusline 配置。
- P1 增加会话与每轮 token 统计；P2 增加 Usage 页、额度提醒和 statusline 接入。
