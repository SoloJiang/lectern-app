# ADR 0047：用量归属的改动权重由 usage 在轮次结束时从改动工具调用算出，不读 review 的归因

- 状态：已接受
- 日期：2026-10-22
- 修订：[ADR 0020](0020.md)（「归属规则」里「改动来自 `review` 对轮次的归因结果」，以及「影响」里 `usage` 的输入「`review` 给出的每轮改动」）

## 背景

[ADR 0020](0020.md) 规定有改动的轮次按改动所在 worktree 的分支归属，一轮改了几个分支时按「改动行数 + 改动文件数」分摊，并写明「改动来自 `review` 对轮次的归因结果」。写 [usage 设计](../design/usage.md)时发现这个来源对不上 `usage` 的需要：

- `review` 的归因是一个审阅对象从基准到当前工作区的逐行来源（[review 设计「改动链」](../design/review.md#改动链)），只为打开的审阅和项目主页的概览计算，概览只看当前 worktree 里最近 14 天的会话。`usage` 要为本机全部会话的每一轮算权重，包括没有打开的项目、已经删除的 worktree 和 30 天以前导入的历史。
- 归因随工作区变化：之后的提交、手工修改、另一个会话的改动都会改变一行的来源和存活。ADR 0020 同时要求「观察先落盘，之后不再修改」，权重要在轮次结束时固定下来，重建时从落盘的记录得到同样的结果。
- `review` 和 `usage` 都是插件，只能经 `services` 交互（[ADR 0025](0025.md)）。为了权重给 `review` 加一个面向全部会话的后台服务，等于在 `review` 里再做一遍 `usage` 的补读和节奏控制。

## 决策

- `usage` 在一轮结束时，用这一轮的改动工具调用（`ToolKind::Edit`，状态 `Completed`）的改动内容（`SessionSource::load` 给出的 `FileEdit`）算出每个文件的改动行数，按「文件 × 分支观察」写进自己的 SQLite，之后不再修改；会话日志被 `Batch::reset` 重放时随新一代一起重算。
- 行数的口径：`Replace` 是 `git::line_diff(old, new)` 的增删行数之和，`Patch` 是 hunk 里 `+`、`-` 行的数量，`Add` 和新建的 `Write` 是内容的行数，`Delete` 记 0 行。改动步的认定（路径、状态、时刻取调用的结果时刻）与 [review 设计「改动步与声明」](../design/review.md#改动步与声明)相同，`usage` 引用那里的定义，不复制改动链和逐行来源。
- 一个文件在这一轮里的改动随之后同一轮里的命令去向（提交到某个分支、随工作区带到另一个分支）的规则，以及权重的分摊和取整，由 usage 设计规定。

放弃的方案：

| 方案 | 原因 |
|---|---|
| 读 `review` 的归因 | 只覆盖打开的审阅和概览范围内的会话；结果随工作区变化，不能固定成观察；要给 `review` 加面向全部会话的后台服务 |
| 把改动链移进一个非插件的库，两边共用 | 改动链要读审阅对象的基准和工作区，`usage` 只需要每个调用自己的行数；共用之后链的每次修改都要同时满足两边 |
| 按轮次结束时工作区相对 HEAD 的改动集计权重 | 分不清是哪一轮、哪个会话的改动，并行会话共用一个 worktree 时全部算错 |

## 影响

- `usage`：[usage 设计](../design/usage.md)「轮次的观察与改动项」写行数规则、去向规则和落盘格式；测试覆盖每一种 `EditOp`。
- `review`：不变，不为 `usage` 提供接口。
- [ADR 0020](0020.md) 的状态行与索引注明本条修订。

## 已知限制

- 命令期间改动的文件（格式化、`sed -i`、代码生成）在日志里没有改动内容，不计入权重；只有这类改动的轮次按没有改动的轮次归属。
- 没有 `structuredPatch` 的覆盖写（`Write` 且不是新建）按新内容的全部行数计，比实际的改动行数多。
- 改动之后被撤销或覆盖的行仍然计入那一轮的权重。
