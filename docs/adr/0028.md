# ADR 0028：工作区的目录遍历和忽略规则也只经 SafeRoot

- 状态：已接受
- 日期：2026-10-17
- 修订：[ADR 0024](0024.md)（「使用边界」里由 gix 提供目录遍历，以及「已知限制」第 3 条）

## 背景

ADR 0024 让 gix 负责未跟踪文件的目录遍历和 `.gitignore` 的加载，并把遍历期间目录被换成符号链接（TOCTOU）列为不在威胁模型内的已知限制，理由是「只有以用户身份运行的进程能做到」。这个前提不成立：被审阅的 agent 和它启动的进程正是在工作区里写文件、建链接、改名目录的进程，Analyze 防的就是被审阅内容里的提示词注入（AGENTS.md「Review guidelines」）。它们完全可以在比较进行时把工作区里的某个目录换成指向工作区之外的符号链接。

gix 0.88 的遍历按路径读目录（`read_dir`、`symlink_metadata`），工作区的 `.gitignore` 也按路径读，未跟踪的 `.gitignore` 是符号链接时还会跟随它（gix-worktree 的 `WorktreeThenIdMappingIfNotSkipped`）。于是忽略规则可能来自工作区之外的文件，列出的名字也可能来自工作区之外的目录，违反 crates/git/AGENTS.md「工作区文件只经 SafeRoot」的边界（PR #87 的审阅意见）。

## 决策

- `platform` 的 `SafeRoot` 增加列目录的接口 `list`：与 `read` 用同样的一步打开和 `Walk` 后备，路径的任何一级（含要列的目录本身）是符号链接都返回 `PathThroughSymlink`，名字从打开的那个描述符读出，所以总在根目录之下；条目的类型来自目录项，缺失时对同一个描述符 `fstatat`，符号链接作为条目返回，不跟随。macOS 专属的部分仍只在 `platform`（架构规则 6）。
- `git` 自己遍历未跟踪文件，只用 `SafeRoot::list` 和 `SafeRoot::read`：工作区里的 `.gitignore` 只读普通文件（符号链接不读，与 git 2.32 起的行为相同），解析和匹配用 gix-ignore 在内存里进行；`info/exclude`、`core.excludesFile` 这类 git 目录和用户配置里的文件仍由 gix 的排除栈加载，排除栈和属性栈都只用 id-mapping 来源，不按路径读工作区里的任何文件。
- gix 的 `dirwalk` 不再用于工作区。gix 仍负责 index、配置、属性与忽略规则的解析和匹配、内置转换和对象读取。
- 子模块的 HEAD 也不按路径读工作区：工作区里的 `.git` 目录经 `SafeRoot` 读 `HEAD` 和引用；`.git` 文件（`gitdir:`）只接受本仓库公共目录 `modules/` 之下的 git 目录，指向别处的为读不到；接受的目录也经以公共目录为根的 `SafeRoot` 读，`modules/<名字>` 和其中的 `HEAD`、引用任何一级是符号链接都为读不到，不跟随。

放弃的方案：

- 继续用 gix 的遍历，只把 `.gitignore` 换成内存里的规则：gix 的排除栈要在遍历开始前知道全部 id-mapping，未跟踪目录里的 `.gitignore` 要边遍历边发现，做不到；目录名仍来自按路径的 `read_dir`。
- 遍历后再用 `SafeRoot` 复核每个名字：能挡住读到的内容，挡不住列出工作区之外的名字和被外部规则误判为忽略的文件。

## 影响

- `platform`：`SafeRoot::list` 和它的测试（含目录与符号链接来回交换的竞态测试），设计见 [platform 设计](../design/platform.md)。
- `git`：未跟踪文件的遍历、忽略规则和子模块 HEAD 的读取，设计见 [git 设计「工作区比较」](../design/git.md#工作区比较)；ADR 0024 的使用边界相应收紧。
- 根 `Cargo.toml` 的 gix feature 去掉 `dirwalk`（ADR 0024 的 feature 清单相应减少一项）：再没有代码用它，`cargo tree -e features -i gix` 里也没有别的依赖需要它；`gix-dir` 随之从 Cargo.lock 移除。忽略规则仍由 `excludes` 提供。
- 性能：遍历的系统调用数与 gix 的遍历同一量级（每个目录一次打开和读目录项），仍计入 `git/changes_clean` 的预算。

## 已知限制

- 每次 `list`、`read`、`stat` 的结果对应调用期间某一时刻的状态；两次调用之间被替换的目录，下一次调用报告为不存在或 `PathThroughSymlink`，不会读到根目录之外。
- macOS 上 `core.precomposeUnicode` 的名字规范化由 `git` 做，与 git 相同只在开启时转换。
