# ADR 0066：每帧读取贡献方的当前值不计入静止

- 状态：已接受
- 日期：2026-11-23
- 修订：[ADR 0017](0017.md)（「已静止」的定义：只读的每帧读取不再让 kernel 变忙）

## 背景

[ADR 0017](0017.md) 的空闲内存基准和 bench 都等 kernel 的「已静止」信号，并用 `quiescent_epoch()` 在采样前后各读一次，两次相同样本才有效。[kernel 设计「静止」](../design/kernel.md#静止)把所有持有中的准入（`ActivationToken::enter()`）计入静止条件：插件代码正在运行、还没来得及取 `BusyGuard` 时，kernel 不报告静止。这条规则针对的是事件式的调用：Action、命令处理函数、视图工厂、主线程上应用任务结果。这些调用可能开始新的工作。

`workspace` 的工具栏要显示当前屏幕的标题、副标题和控件，所以每画一帧就调用一次当前屏幕的 `ui::contrib::Screen::toolbar` 闭包，按 [workspace 设计](../design/workspace.md)的通用规则在 `token.enter()` 的准入内调用。结果是每画一帧 kernel 就忙碌一次：GPUI 测试平台上画一帧，`quiescent_epoch()` 从 66 变为 68；不画帧时不变。只要界面上有东西在动（编辑模式的光标闪烁、滚动、动画），kernel 就一直不静止。[#393](https://github.com/SoloJiang/lectern-app/issues/393) 的编辑模式滚动基准因此在 CI 上挂了 6 小时，[#401](https://github.com/SoloJiang/lectern-app/pull/401) 只在 bench 里绕开了它。

## 决策

每帧在主线程上读取贡献方当前值的闭包，在一种不计入静止的准入内调用。

- kernel 公开 `ActivationToken::enter_frame()`：与 `enter()` 一样只接受 `Live`，计入这次激活自己的准入计数，所以停用照常等它释放（[kernel 设计「撤销」](../design/kernel.md#撤销)第 3 步不变）；不计入全局准入计数，不影响 `is_quiescent`、`quiescent_epoch()` 和 `Busy` / `Quiescent`。
- 只用于每帧调用、只读状态的闭包。目前只有 `Screen::toolbar` 一个。视图工厂、Action、命令处理函数、离开守卫的 `ask`、结果应用仍用 `enter()`，计入静止。
- 关键约束：在这种准入内运行的闭包只读状态、构造元素，不开始工作（不提交任务、不发事件、不排主线程队列）。闭包需要开始工作时，在返回之前自己取 `BusyGuard` 或 `PendingGuard`；守卫照常计入静止，`quiescent_epoch()` 随之变化，采样前后的检查仍会丢弃这次样本。
- panic 的处理不变：仍在 `contain` 里调用，panic 时在持有准入的情况下 `fail` 这次激活。

放弃的方案：

- 在 bench 里放宽等待（[#401](https://github.com/SoloJiang/lectern-app/pull/401) 的做法）：只解决一个 bench，空闲内存基准和其他等静止的地方仍受影响；而且「静止」的含义变成「没有在画帧」，与 ADR 0017 要测的「没有工作」不符。
- 让 `in_scope` 全部改为不计入：视图工厂会创建视图、可能开始加载，属于静止要等的工作。
- 由 `workspace` 缓存工具栏的值、只在通知时重新读取：要给 `Screen` 加变化通知，改动所有贡献方，收益只是少一次闭包调用。

## 影响

- `kernel`：新增 `ActivationToken::enter_frame()`，设计文档「接口」「静止」「撤销」「测试」随之更新；新增单元测试：准入期间 `quiescent_epoch()` 不变，停用等它释放，`Dead` 时返回 None。
- `workspace`：工具栏闭包改用 `enter_frame()`，其余贡献方闭包不变；设计文档「`ui::contrib` 的载荷类型」和「注册表与驱动」随之更新；新增 `#[gpui::test]`：只画帧、没有其他工作时 `quiescent_epoch()` 不变，并确认工具栏闭包确实被调用。
- `ui`：`Screen::toolbar` 的文档注释写明上面的关键约束。
- `bench`：#401 的绕开做法在本 ADR 实现后可以去掉，由 #401 所在的工作跟进。

## 已知限制

- 「闭包只读」靠约定和代码审阅保证，kernel 不检查。
- 视图自己的渲染路径里调用 `ServiceRef::get` 或 `ServiceSet` 时仍计入静止；目前没有发现每帧这样调用的视图，出现时按本 ADR 另行处理。
