# i18n 设计

对应 issue [#28](https://github.com/SoloJiang/lectern-app/issues/28)。界面英文优先，支持简体中文，所有界面字符串从第一天起走 Fluent 资源文件（[ADR 0013](../adr/0013.md)、[交互规范「语言」](interaction.md#语言)）。

## 范围

- 做：
  - en 与 zh-CN 的 Fluent 资源，在编译期解析、校验并编译成静态数据，运行时不解析（[ADR 0017](../adr/0017.md)）。
  - 从系统的首选语言列表协商出界面语言。
  - 按键取字符串、带参数格式化、复数。
  - 编译期生成的键常量：键写错是编译错误。
  - 数量与相对时间的格式化。
  - 检查两种语言资源一致的编译期校验和测试，由 CI 运行。
- 不做：
  - 读写系统语言设置：归 `platform`（架构规则 6），由 `app` 把结果传进来。
  - 把字符串交给视图的 GPUI 胶水（全局状态、切换后刷新窗口）：归 `ui`。
  - 翻译人和 agent 写的内容：prompt、说明、评论、代码、路径、命令、快捷键原样显示。
- 本 issue 之外：
  - 插件市场下载的额外界面语言（[ADR 0018](../adr/0018.md)）。下载的语言包只能在运行时解析，接入时要另写设计，并对照 ADR 0017 的首帧规则。
  - 调试用的伪语言（拉长、加重音，检查截断）。
  - 在类型上禁止视图传字面量：`ui` 的控件只接受来自本 crate 的文本或标明原样显示的文本，写进 `ui` 的设计文档。

## 依赖

| 依赖 | 用途 | 选用理由 |
|---|---|---|
| `fluent-syntax` 0.12（build-dependency） | `build.rs` 解析全部 FTL，校验后生成 Rust 代码 | fluent-rs 的解析器（ADR 0013）；MIT / Apache-2.0；只在构建时运行，不进入二进制 |
| `fluent-bundle` 0.16（dev-dependency） | 测试里作为参考实现：每条消息用 fluent-bundle 格式化一遍，与生成代码的结果对比 | 同一套 fluent-rs，不进入二进制 |

运行时没有外部依赖：格式化器和两种语言的复数规则都由本 crate 实现（见「数据结构」）。

不用 `fluent-langneg` 做协商：它把 `zh-TW`、`zh-Hant` 也匹配到 `zh-CN`（P0 原型实测），见「未决问题」。不用 icu4x：数据体积与安装包预算（ADR 0018）不相称，需要的格式化只有下面几种。

## 接口

```rust
/// 界面语言。新增语言时在这里加一项，并加一个资源目录和它的复数规则。
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum Locale {
    En,
    ZhCn,
}

impl Locale {
    pub const ALL: [Locale; 2] = [Locale::En, Locale::ZhCn];

    /// BCP 47 标签："en"、"zh-CN"。
    pub fn tag(self) -> &'static str;

    /// 语言选择器里这种语言的名称。名称在 common.ftl 里，两种语言的资源都用该语言自身的写法
    ///（`common-language-en = English`、`common-language-zh-cn = 简体中文`）。
    pub fn name_key(self) -> Key;

    /// 按顺序遍历系统的首选语言列表（如 macOS 的 `["ja-JP", "zh-Hans-CN", "en-US"]`），
    /// 取第一个能对应到已有语言的项；都对应不上时返回 `En`。纯函数，可在任何线程调用。
    pub fn negotiate<'a>(preferred: impl IntoIterator<Item = &'a str>) -> Locale;
}

/// 没有变量的消息或属性：编译后表格里的下标。只由生成的 `keys` 模块构造。
#[derive(Clone, Copy, Debug)]
pub struct Key { /* index: u16 */ }

/// 带变量的消息或属性。与 `Key` 是不同的类型：把带变量的消息传给 `get`、
/// 或把不带变量的消息传给 `format`，都是编译错误。
#[derive(Clone, Copy, Debug)]
pub struct FmtKey { /* index: u16 */ }

/// build.rs 从 locales/en/*.ftl 生成。`review-looks-good` → `keys::review::LOOKS_GOOD: Key`，
/// 属性 `review-looks-good.tooltip` → `keys::review::LOOKS_GOOD_TOOLTIP: Key`，
/// `review-files-changed`（用到 `$count`）→ `keys::review::FILES_CHANGED: FmtKey`。
/// 每个 `FmtKey` 常量的文档注释列出变量名和类型（数字或字符串）。
pub mod keys;

/// 格式化参数，按变量名传入。
#[derive(Default)]
pub struct Args<'a> { /* 小数组，不分配 */ }

impl<'a> Args<'a> {
    pub fn new() -> Self;
    pub fn num(self, name: &'a str, value: impl Into<f64>) -> Self; // 参与复数选择
    pub fn str(self, name: &'a str, value: &'a str) -> Self;        // 原样插入，如路径、会话标题；输出时加方向隔离符
}

/// 一种语言的全部界面字符串：指向编译进二进制的静态表格。`Copy`，`Send + Sync`。
#[derive(Clone, Copy)]
pub struct Strings { /* locale, &'static Table */ }

impl Strings {
    /// 取这种语言的表格。不解析、不分配、不读文件，耗时是常数。
    pub fn of(locale: Locale) -> Strings;

    pub fn locale(&self) -> Locale;

    /// 没有变量的消息。
    pub fn get(&self, key: Key) -> &'static str;

    /// 带变量的消息。
    pub fn format(&self, key: FmtKey, args: &Args<'_>) -> String;

    /// "just now"、"5 min ago"、"3 days ago" / "刚刚"、"5 分钟前"、"3 天前"。
    /// 文案来自 common.ftl，本函数只选消息和单位。
    pub fn relative_time(&self, elapsed: Duration) -> String;
}

/// 数量的紧凑写法，用于 token 数：`950`、`12.3K`、`4.5M`。两种语言写法相同，见「数据结构」。
pub fn count_compact(n: u64) -> String;
```

调用方：

- `app` 启动时调用 `Locale::negotiate` 和 `Strings::of`（见「数据流与线程」）。
- 视图通过 `ui` 拿到当前的 `Strings`，在渲染时调用 `get` / `format`。格式化是对静态数据的纯计算，在 UI 线程上调用。
- 领域层不依赖本 crate：领域层输出数据和错误枚举，由视图映射到键。

错误处理：

- 资源的语法、引用、两种语言的一致性都在编译期检查（见「编译期校验」），运行时不会缺键、缺消息引用。
- 运行时唯一可能的错误是调用方漏传或传错类型的参数：调试构建 `debug_assert!` 失败；发布构建在对应位置输出 `{$name}` 并记一条日志，不崩溃。

## 数据结构

资源目录：

```
crates/i18n/
├── build.rs                # 解析、校验、生成表格与 keys 模块
└── locales/
    ├── en/
    │   ├── common.ftl      # 通用：按钮、相对时间、语言名称、空状态
    │   ├── welcome.ftl     # 每个视图 crate 一个文件
    │   ├── review.ftl
    │   └── ...
    └── zh-CN/              # 与 en 同名同键
        └── ...
```

资源规则：

- 键的前缀等于文件名：`review.ftl` 里只有 `review-*`，避免跨文件重名。
- 用属性放同一个元素的附属文案：`.tooltip`、`.label`（无障碍标签）、`.placeholder`。
- 复数用选择表达式：en 写 `[one]` 和 `*[other]`；zh-CN 只有 `other`，写成不带选择的普通消息。
- 支持的 Fluent 子集：文本、变量、消息引用、term（如 `-app-name = Lectern`）、属性、选择表达式（按复数类别或数字字面量选择数字变量，按字面量选择字符串变量）。不支持函数（包括 `NUMBER()`）：分组与小数位的格式由调用方算好后用 `Args::str` 传入（如 `count_compact` 的结果）。用到不支持的写法时构建失败。

示例：

```ftl
# en/review.ftl
review-looks-good = Looks good
    .tooltip = Mark every file as reviewed
review-progress = { $reviewed }/{ $total } reviewed
review-files-changed = { $count ->
    [one] { $count } file changed
   *[other] { $count } files changed
}
```

```ftl
# zh-CN/review.ftl
review-looks-good = 看起来没问题
    .tooltip = 将所有文件标记为已看
review-progress = 已看 { $reviewed }/{ $total }
review-files-changed = { $count } 个文件有改动
```

编译后的形式：`build.rs` 把每种语言编译成一张静态表格，下标就是 `Key`。

```rust
// 生成的代码（示意）
enum Part {
    Text(&'static str),
    Var(u8),                                          // 消息内的变量序号
    Select { var: u8, arms: &'static [(Selector, &'static [Part])], default: &'static [Part] },
}
enum Selector { Plural(PluralCategory), Exact(f64), Str(&'static str) }
static EN: [&'static [Part]; N] = [ /* ... */ ];
static ZH_CN: [&'static [Part]; N] = [ /* ... */ ];
```

- 消息引用和 term 在编译期展开，运行时只有文本、变量和选择。
- 没有变量的消息编译成单个 `Text`，`get` 直接返回 `&'static str`。
- 复数规则按语言手写：en 在数值为整数 1 时是 `one`，其余为 `other`；zh-CN 总是 `other`（CLDR 规则）。测试用 fluent-bundle 依赖的 `intl_pluralrules` 对照一段数值区间。

方向隔离：`Args::str` 传入的值（路径、会话标题、用户写的文本）在输出时包上 U+2068 FSI 和 U+2069 PDI。界面语言都是从左到右书写，但这些值可能含阿拉伯文或希伯来文，不隔离会打乱相邻标点和标签的顺序。数字参数不加。

语言协商规则（`Locale::negotiate`）：

| 首选语言 | 结果 |
|---|---|
| `zh-Hans*`；没有书写系统的 `zh`、`zh-CN`、`zh-SG`、`zh-MY` | `ZhCn` |
| `zh-Hant*`、`zh-TW`、`zh-HK`、`zh-MO` | 跳过，继续看下一个首选语言（见「未决问题」） |
| `en*` | `En` |
| 其他 | 跳过 |

数量：token 数在两种语言里都写成 `12.3K`、`4.5M`，不用「万」。token 数是开发工具里的计数，这种写法与 agent 自身的界面和日志一致，列宽也与英文界面相同。文件数、轮次等小数字直接显示。

## 编译期校验

`build.rs` 在生成代码之前检查以下各项，任一项不满足即构建失败，错误信息给出文件、行号和键：

- 两种语言的文件名集合相同；每个文件里，消息 ID 集合相同，每条消息的属性集合相同。
- 每条消息在两种语言里引用的变量集合相同，选择器里的变量也算。
- 每个变量在两种语言里的类型相同。类型由用法推出：用作复数选择器或数字字面量选择器的是数字，用作字符串字面量选择器的是字符串，只出现在占位符里的两种都可以。一种语言把它当数字、另一种当字符串时报错，因为同一次 `Args` 调用无法同时满足两边。推出的类型写进生成的 `FmtKey` 文档注释。
- 资源全部能解析，没有语法错误和重复的 ID；键的前缀等于文件名。
- 每个消息引用和 term 引用都能解析到已有的消息或 term，没有循环引用。
- 只用了支持的 Fluent 子集。
- 选择表达式有默认分支；按复数类别选择时，类别属于该语言的复数规则（zh-CN 写 `[one]` 是错误）。

这些检查在每次构建时运行，Linux 与 macOS 的 CI 任务都会执行。

## 数据流与线程

启动（首帧之前）：

1. `app` 在主线程上调用 `platform` 读取系统首选语言列表（内存中的系统偏好，不读 Lectern 自身的文件），再调用 `Locale::negotiate` 和 `Strings::of`。三步都是常数级的内存操作，没有解析。
2. 窗口骨架用这份 `Strings` 绘制首帧。

语言设置：

- 设置里的选项是「跟随系统 / English / 简体中文」。
- 选择结果保存在应用 user defaults 的 `AppleLanguages` 键里，由 `platform` 读写；选「跟随系统」时删除这个键。`platform` 提供两个读取函数：
  - `preferred_languages()`：本进程实际生效的首选语言列表，包含应用自己的覆盖，启动时用；
  - `system_languages()`：全局域（`NSGlobalDomain`）里的系统首选语言列表，不受应用覆盖影响，运行中选「跟随系统」时用。运行中的进程里，删除覆盖后前者仍返回旧值，直到下次启动。
- 因此：
  - 下次启动时，第 1 步读到的首选语言列表已经是用户选的语言，首帧直接以正确的语言显示，首帧之前不需要读 Lectern 自身的设置文件。
  - 这个键与 macOS「系统设置 › 通用 › 语言与地区 › 应用」里的按应用语言设置是同一个设置，两处保持一致。
- 发布用的 `.app` 在 `Info.plist` 的 `CFBundleLocalizations` 里声明 `en` 与 `zh-Hans`，并带对应的 `.lproj`，系统提供的界面（打开文件夹面板、标准菜单项）因此与启动时的界面语言一致。这一项在打包时做（[#38](https://github.com/SoloJiang/lectern-app/issues/38)）。

运行中切换：

1. 视图发出切换命令。选的是具体语言时，新语言就是它；选「跟随系统」时，新语言是 `Locale::negotiate(system_languages())`。
2. UI 线程上把 `ui` 持有的 `Strings` 换成 `Strings::of(新语言)`（常数时间），所有窗口重绘。Lectern 绘制的界面和 Lectern 自己构建的菜单立即切换。
3. 写 `AppleLanguages` 的请求进入 `platform` 的一个串行队列，按选择的先后执行，最后一次选择总是最后写入。连续切换时，队列里尚未执行的旧请求直接丢弃。
4. AppKit 自己提供的界面（标准菜单项、打开文件夹面板、服务菜单）按启动时的语言显示，切换后要重新启动才会变。设置页在语言选项下方显示一行说明和「重新启动」按钮。
5. 点「重新启动」时，先等写入队列清空，并调用 `CFPreferencesAppSynchronize` 确认写入磁盘，再退出并重新打开。写入失败时不重启，按「状态与异常」提示。

## 性能

- 首帧之前没有解析：表格是编译进二进制的静态数据，`Strings::of` 只取一个指针。满足 ADR 0017「当前语言的 Fluent 资源在编译期预解析并内嵌」。
- 格式化：没有变量的消息零开销；带变量的消息一次遍历加一次 `String` 分配。原型里 fluent-bundle 格式化 800 条带复数的消息约 0.45 ms（Linux 容器，release），静态表格的格式化不会比它慢。
- 体积与内存：表格大小与资源文本同一量级。预计全部界面文案在 50 KB 以内，两种语言合计约 100 KB 静态数据，不占堆内存。
- 构建：`build.rs` 只在 `locales/` 变化时重新运行（`cargo:rerun-if-changed`）。
- `bench`（[#7](https://github.com/SoloJiang/lectern-app/issues/7)）增加一项：典型界面一帧内所有 `get` / `format` 调用的总耗时。

## 状态与异常

- 系统首选语言都对应不上：英文。
- `platform` 读系统语言失败：英文，记日志。
- 写 `AppleLanguages` 失败：本次运行仍按新语言显示，提示一次「语言设置未能保存，下次启动仍使用〈上一次保存的设置〉」。下次启动使用最后一次成功保存的值（从未保存过时跟随系统）。

## 测试

全部测试可在 Linux 上运行（`just test -p lectern-i18n`），由 CI 的 Linux 任务覆盖：

- 与参考实现对照：每种语言的每条消息和每个属性，用合成参数（每个数字变量取 0、1、2、5、1.5，字符串变量取固定文本）分别用生成的格式化器和 fluent-bundle 格式化，结果在去掉方向隔离符后必须相同，fluent-bundle 不得报告错误。这一项同时检查资源里没有无法解析的引用。
- 变量类型：一种语言把变量当数字、另一种当字符串的资源构建失败；生成的 `FmtKey` / `Key` 与消息是否带变量一致（用 trybuild 检查把 `FmtKey` 传给 `get` 无法编译）。
- 编译期校验：对每条校验规则准备一组错误的资源（测试用的独立目录），调用 `build.rs` 的校验函数，断言给出对应的错误。
- 复数规则：en 与 zh-CN 的手写规则对照 `intl_pluralrules`，数值覆盖 0–1000 的整数和若干小数。
- `Locale::negotiate`：上面的协商表逐行覆盖，包括 `["ja-JP", "zh-Hans-CN"]` 这种第一项对应不上的列表，以及空列表。
- 格式化：用 insta 快照记录两种语言下的复数、方向隔离、`relative_time` 的各个区间、`count_compact` 的边界值（999、1000、999 949、1 000 000）。

只能在 macOS 上验证的部分：方向隔离符在 GPUI 的文字渲染里不显示为可见字形（UI 探针截图，[#6](https://github.com/SoloJiang/lectern-app/issues/6)）。调用系统 API 的部分（读写 `AppleLanguages`、`system_languages()` 在有应用覆盖时仍返回全局设置、写入队列与重启前的同步）在 `platform` 里测试。

## 未决问题

1. **繁体中文用户看什么。** 选项：
   - (a) 显示英文（倾向）：不向台湾、香港用户显示简体中文；以后可以加 zh-TW 资源。
   - (b) 显示简体中文：多数繁体用户读得懂简体，比英文更易读。

   由产品负责人决定。默认按 (a) 实现，改成 (b) 只需改协商表的一行。

## 验收

- 两种语言的资源编译成静态表格；`keys` 模块由 en 资源生成；运行时二进制不含 Fluent 解析器。
- en 与 zh-CN 的键、属性、变量不一致，或有无法解析的引用时，构建失败，CI 失败。
- 生成的格式化器与 fluent-bundle 对每条消息的输出一致。
- 协商表的每一行都有测试。
- 首帧之前不解析、不读 Lectern 自身的文件（`app` 接入时验证，基准在 #7）。
- 交互规范与 ADR 0013 里过时的字体说明改为 ADR 0015 的 SF Pro / SF Mono（随本设计文档一起修改）。
