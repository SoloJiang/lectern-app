# i18n 设计

状态：已实现（设计 [#44](https://github.com/SoloJiang/lectern-app/pull/44)，实现 [#59](https://github.com/SoloJiang/lectern-app/pull/59)）；运行日志接入 `lectern-logging`（「日志与诊断」，[logging 设计「对其他 crate 的要求」](logging.md#对其他-crate-的要求)第 9 项的 `i18n` 部分，[#190](https://github.com/SoloJiang/lectern-app/pull/190)）已实现。

对应 issue [#28](https://github.com/SoloJiang/lectern-app/issues/28)。界面英文优先，支持简体中文，所有界面字符串从第一天起走 Fluent 资源文件（[ADR 0013](../adr/0013.md)、[交互规范「语言」](interaction.md#语言)）。

## 范围

- 做：
  - en 与 zh-CN 的 Fluent 资源，在编译期解析、校验并编译成静态数据，运行时不解析（[ADR 0017](../adr/0017.md)）。
  - 从系统的首选语言列表协商出界面语言。
  - 按键取字符串、带参数格式化、复数。
  - 编译期生成的键常量：键写错是编译错误。
  - 数量与相对时间的格式化。
  - 检查两种语言资源一致的编译期校验和测试，由 CI 运行。
- 不做：
  - 读写系统语言设置：归 `platform`（架构规则 6），由 `app` 把结果传进来。
  - 把字符串交给视图的 GPUI 胶水（全局状态、切换后刷新窗口）：归 `ui`。
  - 翻译人和 agent 写的内容：prompt、说明、评论、代码、路径、命令、快捷键原样显示。
- 本 issue 之外：
  - 插件市场下载的额外界面语言（[ADR 0018](../adr/0018.md)）。下载的语言包只能在运行时解析，接入时要另写设计，并对照 ADR 0017 的首帧规则。
  - 调试用的伪语言（拉长、加重音，检查截断）。
  - 在类型上禁止视图传字面量：`ui` 的控件只接受来自本 crate 的文本或标明原样显示的文本，写进 `ui` 的设计文档。

## 依赖

| 依赖 | 用途 | 选用理由 |
|---|---|---|
| `fluent-syntax` 0.12（build-dependency） | `build.rs` 解析全部 FTL，校验后生成 Rust 代码 | fluent-rs 的解析器（ADR 0013）；MIT / Apache-2.0；只在构建时运行，不进入二进制 |
| `fluent-bundle` 0.16（dev-dependency） | 测试里作为参考实现：每条消息用 fluent-bundle 格式化一遍，与生成代码的结果对比 | 同一套 fluent-rs，不进入二进制 |
| `lectern-logging` | 运行日志的宏与类型化字段（「日志与诊断」）；测试用它的 `test-support` feature 捕获记录 | kernel 层，只依赖 `log`（[ADR 0046](../adr/0046.md)），`log` 已经在发布构建里 |

运行时没有 Fluent 相关的依赖：格式化器和两种语言的复数规则都由本 crate 实现（见「数据结构」）。运行时的依赖只有 `lectern-logging`。

不用 `fluent-langneg` 做协商：它把 `zh-TW`、`zh-Hant` 也匹配到 `zh-CN`（P0 原型实测），见「未决问题」。不用 icu4x：数据体积与安装包预算（ADR 0018）不相称，需要的格式化只有下面几种。

## 接口

```rust
/// 界面语言。新增语言时在这里加一项，并加一个资源目录和它的复数规则。
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum Locale {
    En,
    ZhCn,
}

impl Locale {
    pub const ALL: [Locale; 2] = [Locale::En, Locale::ZhCn];

    /// BCP 47 标签："en"、"zh-CN"。
    pub fn tag(self) -> &'static str;

    /// 语言选择器里这种语言的名称。名称在 common.ftl 里，两种语言的资源都用该语言自身的写法
    ///（`common-language-en = English`、`common-language-zh-cn = 简体中文`）。
    pub fn name_key(self) -> Key;

    /// 按顺序遍历系统的首选语言列表（如 macOS 的 `["ja-JP", "zh-Hans-CN", "en-US"]`），
    /// 取第一个能对应到已有语言的项；都对应不上时返回 `En`。纯函数，可在任何线程调用。
    pub fn negotiate<'a>(preferred: impl IntoIterator<Item = &'a str>) -> Locale;
}

/// 没有变量的消息或属性：编译后表格里的下标。只由生成的 `keys` 模块构造。
#[derive(Clone, Copy, Debug)]
pub struct Key { /* index: u16 */ }

impl Key {
    /// Fluent 消息 ID：`review-looks-good`，属性为 `review-looks-good.tooltip`。
    /// `ui::Text` 带着它，探针据此记下文字来自哪条消息（[ui 设计「文本」](ui.md#文本)）。
    pub fn name(&self) -> &'static str;
}

/// 带变量的消息或属性。与 `Key` 是不同的类型：把带变量的消息传给 `get`、
/// 或把不带变量的消息传给 `format`，都是编译错误。
#[derive(Clone, Copy, Debug)]
pub struct FmtKey { /* index: u16 */ }

impl FmtKey {
    /// 同 `Key::name`。
    pub fn name(&self) -> &'static str;
}

/// build.rs 从 locales/en/*.ftl 生成。`review-looks-good` → `keys::review::LOOKS_GOOD: Key`，
/// 属性 `review-looks-good.tooltip` → `keys::review::LOOKS_GOOD_TOOLTIP: Key`，
/// `review-files-changed`（用到 `$count`）→ `keys::review::FILES_CHANGED: FmtKey`。
/// 每个 `FmtKey` 常量的文档注释列出变量名和类型（数字或字符串）。
pub mod keys;

/// 格式化参数，按变量名传入。
#[derive(Default)]
pub struct Args<'a> { /* 小数组，不分配 */ }

impl<'a> Args<'a> {
    pub fn new() -> Self;
    pub fn num(self, name: &'a str, value: impl Into<f64>) -> Self; // 参与复数选择
    pub fn str(self, name: &'a str, value: &'a str) -> Self;        // 原样插入，如路径、会话标题；输出时加方向隔离符
}

/// 一种语言的全部界面字符串：指向编译进二进制的静态表格。`Copy`，`Send + Sync`。
#[derive(Clone, Copy)]
pub struct Strings { /* locale, &'static Table */ }

impl Strings {
    /// 取这种语言的表格。不解析、不分配、不读文件，耗时是常数。
    pub fn of(locale: Locale) -> Strings;

    pub fn locale(&self) -> Locale;

    /// 没有变量的消息。
    pub fn get(&self, key: Key) -> &'static str;

    /// 带变量的消息。
    pub fn format(&self, key: FmtKey, args: &Args<'_>) -> String;

    /// "just now"、"5 min ago"、"3 days ago" / "刚刚"、"5 分钟前"、"3 天前"。
    /// 文案来自 common.ftl，本函数只选消息和单位。
    pub fn relative_time(&self, elapsed: Duration) -> String;
}

/// 数量的紧凑写法，用于 token 数：`950`、`12.3K`、`4.5M`。两种语言写法相同，见「数据结构」。
pub fn count_compact(n: u64) -> String;
```

调用方：

- `app` 启动时调用 `Locale::negotiate` 和 `Strings::of`（见「数据流与线程」）。
- 视图通过 `ui` 拿到当前的 `Strings`，在渲染时调用 `get` / `format`。格式化是对静态数据的纯计算，在 UI 线程上调用。
- 领域层不依赖本 crate：领域层输出数据和错误枚举，由视图映射到键。

错误处理：

- 资源的语法、引用、两种语言的一致性都在编译期检查（见「编译期校验」），运行时不会缺键、缺消息引用。
- 运行时唯一可能的错误是调用方漏传或传错类型的参数：调试构建 `debug_assert!` 失败；发布构建在对应位置输出 `{$name}`，以它为选择器的选择取默认分支，不崩溃；同一个键的这类错误在本次运行中只记一次日志（按键去重，每个下标一个 `AtomicBool`），不会在每一帧重复写日志。记录的级别和字段见「日志与诊断」。

## 数据结构

资源目录：

```
crates/i18n/
├── build.rs                # 解析、校验、生成表格与 keys 模块
└── locales/
    ├── en/
    │   ├── common.ftl      # 通用：按钮、相对时间、语言名称、空状态
    │   ├── welcome.ftl     # 每个视图 crate 一个文件
    │   ├── review.ftl
    │   └── ...
    └── zh-CN/              # 与 en 同名同键
        └── ...
```

资源规则：

- 键的前缀等于文件名：`review.ftl` 里只有 `review-*`，避免跨文件重名。
- 用属性放同一个元素的附属文案：`.tooltip`、`.label`（无障碍标签）、`.placeholder`。
- 复数用选择表达式：en 写 `[one]` 和 `*[other]`；zh-CN 只有 `other`，写成不带选择的普通消息。
- 支持的 Fluent 子集：文本、变量、消息引用（含 `{ msg.attr }`）、term（如 `-app-name = Lectern`）、属性、字符串与数字字面量、选择表达式（按复数类别或整数字面量选择数字变量，按字面量选择字符串变量；选择器必须是变量）。不支持函数（包括 `NUMBER()`）：分组与小数位的格式由调用方算好后用 `Args::str` 传入（如 `count_compact` 的结果）。也不支持 term 的属性和参数（`-brand.gender`、`-brand(case: "x")`）、term 里的变量，以及小数分支键（`[1.5]`：fluent-bundle 不会让它匹配数字参数）。一条消息最多 8 个变量（`Args` 的容量）。用到不支持的写法时构建失败。
- term 在一种语言的全部文件里共用，不受前缀规则约束；消息引用也可以跨文件。

示例：

```ftl
# en/review.ftl
review-looks-good = Looks good
    .tooltip = Mark every file as reviewed
review-progress = { $reviewed }/{ $total } reviewed
review-files-changed = { $count ->
    [one] { $count } file changed
   *[other] { $count } files changed
}
```

```ftl
# zh-CN/review.ftl
review-looks-good = 看起来没问题
    .tooltip = 将所有文件标记为已看
review-progress = 已看 { $reviewed }/{ $total }
review-files-changed = { $count } 个文件有改动
```

编译后的形式：`build.rs` 把每种语言编译成一张静态表格，下标就是 `Key`。

```rust
// src/table.rs 与生成的 $OUT_DIR/table.rs
enum Part {
    Text(&'static str),
    Var(u8),                                          // 消息内的变量序号
    // arms 按源码顺序包含全部分支（含默认分支），取第一个匹配的；都不匹配时取 arms[default]
    Select { var: u8, default: u8, arms: &'static [(Selector, &'static [Part])] },
}
enum Selector { Plural(PluralCategory), Exact(f64), Str(&'static str) }
static NAMES: [&str; N] = [ /* "review-looks-good.tooltip"：日志用 */ ];
static VARS: [&[(&str, VarType)]; N] = [ /* 每个下标的变量名与推出的类型 */ ];
static EN: [&'static [Part]; N] = [ /* ... */ ];
static ZH_CN: [&'static [Part]; N] = [ /* ... */ ];
```

- 分支匹配与 fluent-bundle 相同：数字参数按复数类别或数值匹配；字符串参数按字面量匹配，也匹配同名的复数类别键（`"one"` 匹配 `[one]`）。

- 消息引用和 term 在编译期展开，运行时只有文本、变量和选择。
- 没有变量的消息编译成单个 `Text`，`get` 直接返回 `&'static str`。
- 复数规则按语言手写：en 在数值的绝对值为整数 1 时是 `one`（CLDR `i = 1 and v = 0`，`-1` 也是 `one`），其余为 `other`；zh-CN 总是 `other`。测试用 fluent-bundle 依赖的 `intl_pluralrules` 对照一段数值区间。
- 数字参数按 Rust 打印 `f64` 的方式输出（`5`、`1.5`），与 fluent-bundle 不设格式时相同。

方向隔离：`Args::str` 传入的值（路径、会话标题、用户写的文本）在输出时包上 U+2068 FSI 和 U+2069 PDI。界面语言都是从左到右书写，但这些值可能含阿拉伯文或希伯来文，不隔离会打乱相邻标点和标签的顺序。数字参数不加。

语言协商规则（`Locale::negotiate`）：

| 首选语言 | 结果 |
|---|---|
| `zh-Hans*`；没有书写系统的 `zh`、`zh-CN`、`zh-SG`、`zh-MY` | `ZhCn` |
| `zh-Hant*`、`zh-TW`、`zh-HK`、`zh-MO` | 跳过，继续看下一个首选语言（见「未决问题」） |
| `en*` | `En` |
| 其他 | 跳过 |

子标签不区分大小写，`-` 与 `_` 都算分隔符；扩展语言子标签（`zh-cmn-Hans` 的 `cmn`）跳过后再看书写系统或地区。

数量：token 数在两种语言里都写成 `12.3K`、`4.5M`，不用「万」。token 数是开发工具里的计数，这种写法与 agent 自身的界面和日志一致，列宽也与英文界面相同。文件数、轮次等小数字直接显示。`count_compact` 的规则：小于 1000 原样输出；否则取四舍五入到一位小数后仍小于 1000 的最大单位（K、M、B），末尾的 `.0` 省略（`1000` → `1K`，`999 950` → `1M`）；十亿以上一律用 B。

相对时间（`relative_time`）：不足 1 分钟为「刚刚」，之后依次按分钟（不足 1 小时）、小时（不足 1 天）、天（不足 7 天）、周（不足 30 天）、月（按 30 天，不足 365 天）、年（按 365 天）计数，向下取整。

## 编译期校验

`build.rs` 在生成代码之前检查以下各项，任一项不满足即构建失败，错误信息给出文件、行号和键：

- 两种语言的文件名集合相同；每个文件里，消息 ID 集合相同，每条消息的属性集合相同，每条消息是否有值（只有属性、没有值的消息在 Fluent 里是合法的）也相同。
- 每条消息在两种语言里引用的变量集合相同，选择器里的变量也算。
- 每个变量在两种语言里的类型相同。类型由用法推出：用作复数选择器或数字字面量选择器的是数字，用作字符串字面量选择器的是字符串，只出现在占位符里的两种都可以（只有 `*[other]` 一个分支的选择也不约束类型）。同一种语言里把一个变量既当数字又当字符串，或一个选择同时用数字键和字符串键，同样报错。一种语言把它当数字、另一种当字符串时报错，因为同一次 `Args` 调用无法同时满足两边。推出的类型写进生成的 `FmtKey` 文档注释。
- 资源全部能解析，没有语法错误和重复的 ID（同一种语言的所有文件里消息 ID、term ID 各自唯一，同一条消息的属性名唯一）；键的前缀等于文件名，前缀之后以字母开头；文件名只用小写字母、数字、`-` 和 `_`。
- 生成的键常量在同一个模块里不重名（如 `review-looks-good.tooltip` 与 `review-looks-good-tooltip` 都会生成 `LOOKS_GOOD_TOOLTIP`）。
- `locales/` 下只有 `en` 与 `zh-CN` 两个目录，且两个都存在。
- 每个消息引用和 term 引用都能解析到已有的消息或 term，没有循环引用。
- 只用了支持的 Fluent 子集。
- 选择表达式有默认分支；按复数类别选择时，类别属于该语言的复数规则（zh-CN 写 `[one]` 是错误）。

这些检查在每次构建时运行，Linux 与 macOS 的 CI 任务都会执行。实现在 `build/compile.rs`：`build.rs` 和 `tests/validation.rs` 都用 `#[path]` 引入它，测试直接调用同一套校验函数。

## 数据流与线程

启动（首帧之前）：

1. `app` 在主线程上调用 `platform` 读取系统首选语言列表（内存中的系统偏好，不读 Lectern 自身的文件），再调用 `Locale::negotiate` 和 `Strings::of`。三步都是常数级的内存操作，没有解析。
2. 窗口骨架用这份 `Strings` 绘制首帧。

语言设置：

- 设置里的选项是「跟随系统 / English / 简体中文」。
- 选择结果保存在应用 user defaults 的 `AppleLanguages` 键里，由 `platform` 读写；选「跟随系统」时删除这个键。`platform` 提供两个读取函数：
  - `preferred_languages()`：本进程实际生效的首选语言列表，包含应用自己的覆盖，启动时用；
  - `system_languages()`：全局域（`NSGlobalDomain`）里的系统首选语言列表，不受应用覆盖影响，运行中选「跟随系统」时用。运行中的进程里，删除覆盖后前者仍返回旧值，直到下次启动。
  - `language_override() -> Option<Locale>`：应用域里是否保存了 `AppleLanguages` 覆盖、覆盖成哪种语言。设置页据此标出当前选项；两个首选语言列表相同（如系统与覆盖都是英文）时，也能区分「跟随系统」与「English」。
- 因此：
  - 下次启动时，第 1 步读到的首选语言列表已经是用户选的语言，首帧直接以正确的语言显示，首帧之前不需要读 Lectern 自身的设置文件。
  - 这个键与 macOS「系统设置 › 通用 › 语言与地区 › 应用」里的按应用语言设置是同一个设置，两处保持一致。
- 发布用的 `.app` 在 `Info.plist` 的 `CFBundleLocalizations` 里声明 `en` 与 `zh-Hans`，并带对应的 `.lproj`，系统提供的界面（打开文件夹面板、标准菜单项）因此与启动时的界面语言一致。这一项在打包时做（[#38](https://github.com/SoloJiang/lectern-app/issues/38)）。

运行中切换：

1. 视图发出切换命令。选的是具体语言时，新语言就是它；选「跟随系统」时，新语言是 `Locale::negotiate(system_languages())`。
2. UI 线程上把 `ui` 持有的 `Strings` 换成 `Strings::of(新语言)`（常数时间），所有窗口重绘。Lectern 绘制的界面和 Lectern 自己构建的菜单立即切换。
3. 写 `AppleLanguages` 的请求进入 `platform` 的一个串行队列，按选择的先后执行，最后一次选择总是最后写入。连续切换时，队列里尚未执行的旧请求直接丢弃。
4. AppKit 自己提供的界面（标准菜单项、打开文件夹面板、服务菜单）按启动时的语言显示，切换后要重新启动才会变。设置页在语言选项下方显示一行说明和「重新启动」按钮。
5. 点「重新启动」时，先等写入队列清空，并调用 `CFPreferencesAppSynchronize` 确认写入磁盘，再退出并重新打开。写入失败时不重启，按「状态与异常」提示。

## 性能

- 首帧之前没有解析：表格是编译进二进制的静态数据，`Strings::of` 只取一个指针。满足 ADR 0017「当前语言的 Fluent 资源在编译期预解析并内嵌」。
- 格式化：没有变量的消息零开销；带变量的消息一次遍历加一次 `String` 分配。原型里 fluent-bundle 格式化 800 条带复数的消息约 0.45 ms（Linux 容器，release），静态表格的格式化不会比它慢。
- 体积与内存：表格大小与资源文本同一量级。预计全部界面文案在 50 KB 以内，两种语言合计约 100 KB 静态数据，不占堆内存。
- 构建：`build.rs` 只在 `locales/` 变化时重新运行（`cargo:rerun-if-changed`）。
- `bench`（[#7](https://github.com/SoloJiang/lectern-app/issues/7)）增加一项：典型界面一帧内所有 `get` / `format` 调用的总耗时。基准是 `i18n/frame_strings`（只记录）：en 资源里每条消息和属性各取一次，带变量的用样例参数格式化。遍历全部消息要用到生成的表格，由 `test-support` feature 下的 `testing::frame_strings(&Strings) -> usize`（返回文本的总字节数）提供，发布构建里没有它。

## 状态与异常

- 系统首选语言都对应不上：英文。
- `platform` 读系统语言失败：英文，记日志。
- 写 `AppleLanguages` 失败：本次运行仍按新语言显示，提示一次「语言设置未能保存，下次启动仍使用〈上一次保存的设置〉」。下次启动使用最后一次成功保存的值（从未保存过时跟随系统）。

## 日志与诊断

本 crate 经 `lectern-logging` 的宏记录（[ADR 0046](../adr/0046.md)、[logging 设计](logging.md)），target 为 `i18n`。记录只进 `lectern-logging` 的内存缓冲，调用线程（通常是 UI 线程）上不做 IO。读系统语言失败、写 `AppleLanguages` 失败由 `platform` 和 `app` 记录，不在本 crate。

- 默认记录：

  | 事件 | 级别 | `msg` | 字段 |
  |---|---|---|---|
  | `format` 的参数缺失或类型不对，发布构建在对应位置输出 `{$name}`、选择取默认分支 | warn | `a message was formatted with a missing or mistyped argument; the placeholder is shown` | `locale`、`key`、`error`、`var`、`expected` |

  - `locale` 是 `Locale::tag()`（`en`、`zh-CN`）。`key` 是消息 ID（如 `review-comments`、`review-looks-good.tooltip`），`var` 是变量名（如 `count`），两者都取自编译进二进制的静态表格（`NAMES`、`VARS`），由资源文件定义，不取自调用方传入的 `Args`。
  - `error` 是 `missing`（漏传）或 `wrong_type`（类型不对）；`expected` 只在 `wrong_type` 时出现，是变量要求的类型 `num`、`str` 或 `any`，`missing` 时为 null。
  - 级别按 ADR 0046「默认日志」的定义：界面照常显示，只是这一处文案降级，记 warn。
  - 同一个键在本次运行中只记一次（每个下标一个 `AtomicBool`）；`lectern-logging` 的每个调用点每 10 秒最多 20 条（[logging 设计「限流」](logging.md#限流)）再兜一层底。
- 详细级别：不另加 debug、trace 记录。`get`、`format` 在 UI 线程上每帧调用多次，按次记录会占去帧预算。
- 性能：记录只在参数出错的分支里，正确的调用不经过日志代码。级别关闭时宏只比较一次级别，字段不求值、不分配、不格式化；级别打开时字段都是 `&'static str`，写出的调用也不分配（`log/enabled_call`）。
- 关联 ID：本 crate 不设作用域，记录带调用线程上已有的作用域（视图渲染时由 `workspace` 和视图层设置，logging 设计「对其他 crate 的要求」第 11 项）。
- 不记录：格式化出的文本、`Args` 里的参数名和参数值（`Args::str` 的值可以是文件名、路径、会话标题等用户数据）、`ArgError` 的 `Display` 文字。用消息 ID、变量名、语言和错误种类代替。
- 金丝雀测试：`strings::tests::logs_hold_no_arguments`（`testing::capture()`，trace 级别）：金丝雀作为 `Args::str` 的值、以及一个消息不用的参数的名字和值，触发一次 `wrong_type`（en，`review-comments`）和一次 `missing`（zh-CN，`review-progress`，格式化出的文本含金丝雀）；同一个错误再触发一次、再做一次正确的调用。检查只有两条记录、级别和字段正确，之后 `assert_absent`。

## 测试

全部测试可在 Linux 上运行（`just test -p lectern-i18n`），由 CI 的 Linux 任务覆盖：

- 与参考实现对照：每种语言的每条消息和每个属性，用合成参数（每个数字变量取 0、1、2、5、1.5，以及所有选择表达式里出现的数字字面量；每个字符串变量取一段固定文本，以及所有出现的字符串字面量；按选择表达式的嵌套结构，为每一条可到达的分支路径（从外层选择到最内层叶子）各生成至少一组参数，不设上限）分别用生成的格式化器和 fluent-bundle 格式化，结果在去掉方向隔离符后必须相同，fluent-bundle 不得报告错误。这一项同时检查资源里没有无法解析的引用。
- 变量类型：一种语言把变量当数字、另一种当字符串的资源构建失败；生成的 `FmtKey` / `Key` 与消息是否带变量一致（用 trybuild 检查把 `FmtKey` 传给 `get` 无法编译）。
- 编译期校验：对每条校验规则准备一组错误的资源（测试用的独立目录），调用 `build.rs` 的校验函数，断言给出对应的错误。
- 复数规则：en 与 zh-CN 的手写规则对照 `intl_pluralrules`，数值覆盖 0–1000 的整数和若干小数。
- `Locale::negotiate`：上面的协商表逐行覆盖，包括 `["ja-JP", "zh-Hans-CN"]` 这种第一项对应不上的列表，以及空列表。
- 格式化：用 insta 快照记录两种语言下的复数、方向隔离、`relative_time` 的各个区间、`count_compact` 的边界值（999、1000、999 949、1 000 000）。
- 日志：`logs_hold_no_arguments`（用 `lectern-logging` 的 `testing::capture()`），见「日志与诊断」。

只能在 macOS 上验证的部分：方向隔离符在 GPUI 的文字渲染里不显示为可见字形（UI 探针截图，[#6](https://github.com/SoloJiang/lectern-app/issues/6)）。调用系统 API 的部分（读写 `AppleLanguages`、`system_languages()` 在有应用覆盖时仍返回全局设置、写入队列与重启前的同步）在 `platform` 里测试。

## 验收

- 两种语言的资源编译成静态表格；`keys` 模块由 en 资源生成；运行时二进制不含 Fluent 解析器。
- en 与 zh-CN 的键、属性、变量不一致，或有无法解析的引用时，构建失败，CI 失败。
- 生成的格式化器与 fluent-bundle 对每条消息的输出一致。
- 协商表的每一行都有测试。
- 首帧之前不解析、不读 Lectern 自身的文件（`app` 接入时验证，基准在 #7）。
- 交互规范与 ADR 0013 里过时的字体说明改为 ADR 0015 的 SF Pro / SF Mono（随本设计文档一起修改）。

日志接入（[logging 设计「对其他 crate 的要求」](logging.md#对其他-crate-的要求)第 9 项的 `i18n` 部分，`Refs #170`）：

- `rg 'eprintln!|println!|util::log' crates/i18n/src` 没有结果（`build.rs` 的输出是构建时给 cargo 的，不在运行时）。
- `logs_hold_no_arguments` 通过，其余测试照常通过。

## 实际验证

在 Linux 容器（x86_64，Rust 1.97.0）上运行：

- `just fmt`、`just check`（含架构检查、文档链接检查、clippy `-D warnings`）、`just test -p lectern-i18n`（51 个测试）、`just doctest`（本 crate 4 个示例和 2 个 `compile_fail`）、`just deny` 全部通过。
- 静态表格与 `keys` 模块：`cargo tree -p lectern-i18n -e normal --target all` 只有本 crate 自身，`fluent-syntax` 只是构建依赖；在一个依赖本 crate 的 release 程序里搜索 `fluent_syntax` 字样，结果为 0。
- 两种语言不一致时构建失败：把 `zh-CN/review.ftl` 的 `review-progress` 去掉 `$total` 后 `cargo check -p lectern-i18n` 失败，输出 `locales/zh-CN/review.ftl:5: review-progress: uses variables $reviewed but en uses variables $reviewed, $total`。每条校验规则在 `tests/fixtures/<规则>/` 下有一组错误资源，`tests/validation.rs` 用 insta 快照记录报错。
- 与 fluent-bundle 对照：`reference_tests::generated_formatter_matches_fluent_bundle` 对两种语言的每个下标按「测试」一节的参数组合逐一比较，全部一致，fluent-bundle 没有报错。
- 键的类型：`tests/compile_fail.rs`（trybuild）确认把 `FmtKey` 传给 `get`、把 `Key` 传给 `format`、写错键名、在 crate 外构造 `Key` 都无法编译。
- 复数规则对照 `intl_pluralrules`（0–1000 的整数和 9 个小数与负数）一致；协商表每一行都有测试（`locale::tests`）。
- 格式化快照：复数、方向隔离、`relative_time` 的 20 个区间点、`count_compact` 的边界值（含 999、1000、999 949、999 950、1 000 000）。
- 性能（release，同一容器，临时程序测得，不进入仓库）：`Strings::of` 加 `get` 约 1 ns；带复数的 `format` 约 68 ns；带字符串参数的 `format` 约 25 ns；800 次带复数的 `format` 约 52 µs（原型里 fluent-bundle 约 0.45 ms）。
- 没有验证的：「性能」一节的 `bench` 基准项和「首帧之前不解析、不读 Lectern 自身的文件」随 `app` 接入和 [#7](https://github.com/SoloJiang/lectern-app/issues/7) 验证；方向隔离符在 GPUI 里不显示为可见字形需要在 macOS 上用 UI 探针确认（[#6](https://github.com/SoloJiang/lectern-app/issues/6)）。

日志接入（logging 设计第 9 项的 `i18n` 部分），在 Linux（x86_64，Rust 1.97.0）上运行：

- `just check`、`just test`（工作区 2252 个测试通过，跳过 7 个）、`just doctest`、`just deny` 通过。`lectern-i18n` 共 53 个测试，新增 `logs_hold_no_arguments`；它与本 crate 其余单元测试在 `cargo test` 的同一进程里一起运行也通过，release 构建下单独运行也通过（不触发 `debug_assert!`，记录相同）。
- `rg 'eprintln!|println!|util::log' crates/i18n/src` 没有结果。`cargo tree -p lectern-i18n -e normal --target all` 是本 crate、`lectern-logging` 和 `log` 0.4.34；Cargo.lock 只在 `lectern-i18n` 的依赖里多了 `lectern-logging`，没有新的外部 crate。
- `logs_hold_no_arguments` 确认了两条记录的级别和字段：`wrong_type`（warn，`locale` 为 `en`，`key` 为 `review-comments`，`var` 为 `count`，`expected` 为 `num`）和 `missing`（warn，`locale` 为 `zh-CN`，`key` 为 `review-progress`，`var` 为 `total`，`expected` 为 null）；同一个错误的第二次调用和正确的调用不写记录；任何一行都没有金丝雀。
- 性能：没有跑基准。`get` 和参数正确的 `format` 经过的代码没有变化；记录在出错的分支里，级别关闭时的开销是 `log/disabled_call` 那一次级别比较。
- 没有验证的：没有在 macOS 上运行；记录写进真实日志文件要等 `app` 接入（logging 设计第 3 步），这里只经 `testing::capture()` 检查编码后的行。

## 与设计的差异

- `Part::Select` 的默认分支改为 `arms` 里的下标（`default: u8`），`arms` 保留包括默认分支在内的全部分支。Fluent 按源码顺序取第一个匹配的分支，默认分支也参与匹配；单独存一份默认分支的 `&[Part]` 会让嵌套的选择重复存储。
- 支持的子集写明了几处原文没有提到的限制：term 的属性与参数、term 里的变量、小数分支键、每条消息最多 8 个变量。前三种在 fluent-bundle 里要么需要 term 参数才有意义，要么永远匹配不到；8 个变量是 `Args` 不分配内存的容量。
- 编译期校验增加了三项：键常量不重名、文件名格式、`locales/` 下的语言目录。前一项不检查时会生成重复的常量，后两项保证生成的模块名合法、不漏掉某种语言。
- `count_compact` 增加了 B（十亿）单位，并写明舍入规则；原文只给了 K、M 的例子，按月统计的 token 数会超过十亿。
- 写明了 `relative_time` 的区间和 en 复数规则对负数的处理，原文没有规定。
- 资源目录目前有 `common.ftl`、`welcome.ftl`、`review.ftl`、`app.ftl`（应用菜单，[app 设计「界面」](app.md#界面)的前置条件 A）和 `workspace.ftl`（工作区外壳，[workspace 设计「界面」](workspace.md#界面)的前置条件 C）；其他视图 crate 的文件在实现各自界面时加入。

日志接入（logging 设计第 9 项的 `i18n` 部分）：

- 原实现在 `strings.rs` 里用一处 `eprintln!` 写一行 `lectern-i18n: <键>: <ArgError 的文字>`，现在改为「日志与诊断」表里的一条 warn，不新增调用点。`ArgError` 的文字只含静态的变量名，但仍不写出，改为 `error`、`var`、`expected` 三个字段，日志里只有固定的取值。`debug_assert!` 的消息不变。
- 原文写「运行时没有外部依赖」，`[dependencies]` 为空；现在有 `lectern-logging`（经它间接依赖 `log`），「依赖」一节和 `crates/i18n/AGENTS.md` 改为「运行时没有 Fluent 相关的依赖」。「实际验证」里 `cargo tree -p lectern-i18n -e normal` 只有本 crate 自身的结论只适用于接入之前。
- 键的去重标志在调用宏之前置位：日志级别关闭时出的错，之后级别打开也不再补记。
