# platform（`lectern-platform`）

macOS 专属能力：FSEvents、`open -a`、钥匙串、Seatbelt、代码签名校验、Claude Code statusline 安装；以及按平台实现的安全读取与原子替换（`SafeRoot`，Linux 实现也在这里）、线程的 CPU 时钟（`ThreadCpuClock`）、应用数据目录与日志目录（`dirs::app_data`、`dirs::logs`）、系统版本（`system::os_version`）和本地时区的偏移（`time::utc_offset`）。macOS 系统绑定只能出现在本 crate（架构规则 6）。

- 层：基础设施层。只依赖基础设施和 kernel 层；不依赖 GPUI。
- 设计文档：[docs/design/platform.md](../../docs/design/platform.md)，目前只覆盖安全读取（`SafeRoot`，含范围读取 `open_file` 与 `OpenFile`，[#103](https://github.com/SoloJiang/lectern-app/issues/103)，已实现）、原子替换（`SafeRoot::replace_file`，已实现）、线程的 CPU 时钟（`ThreadCpuClock`，已实现）、应用数据目录（`dirs::app_data`，已实现）、日志目录与系统版本（`dirs::logs`、`system::os_version`，已实现）、本地时区的偏移（`time::utc_offset`，已实现）和 bench 用的进程测量（`process::phys_footprint`）。FSEvents 与 kqueue 后端（`fs_events`，已实现）的设计在 [docs/design/fs_watch.md](../../docs/design/fs_watch.md)「platform 后端」。`open -a`、钥匙串、Seatbelt、statusline 尚未设计：先在这份文档里增加小节或另写设计文档，按[模板](../../docs/design/TEMPLATE.md)编写，设计文档 PR 合并后再写对应的代码。

## 边界

- 安全读取：从根目录描述符出发，路径任何一级都不跟随符号链接、不越出根目录；普通文件的类型判断和读取用同一个描述符。接口与实现见[设计文档](../../docs/design/platform.md)，`git` 读工作区只经它。
- 范围读取（`safe_read/range.rs`）：`open_file` 与 `read` 共用打开、`fstat` 和 `Walk` 后备，普通文件的描述符转交给 `OpenFile`，在它 drop 时关闭；`OpenFile` 上的读取只用 `pread`，不用文件偏移，不另开描述符，每次读完 `fstat` 一次，返回的 `Meta::identity()` 供调用方核对版本。一次 `read_ranges` 最多 `MAX_RANGES` 段、`MAX_RANGE_BYTES` 字节。不做内存映射，不建行索引（行检查点由 `file_reader` 按 blob OID 缓存）。
- 原子替换（`safe_read/replace.rs`）：`replace_file` 是 `safe_read` 里唯一的写。父目录用 `list` 与 `open_dir` 的目录打开函数打开，之后只在这个目录描述符上做单级名字的 `*at` 调用；临时文件 `O_CREAT | O_EXCL | O_NOFOLLOW`，比较身份之后 `renameat`，任何出错路径都删除临时文件。不创建原来不存在的文件。
- 线程的 CPU 时钟（`thread_clock.rs`）：Linux 用 `pthread_getcpuclockid` 加 `clock_gettime`，macOS 用 `thread_info(THREAD_BASIC_INFO)`，端口名来自 `pthread_mach_thread_np`，时钟自己持有一个用户引用、drop 时释放；读不到时为 `ErrorKind::Unsupported`，墙上时间的回退由调用方做。
- 应用数据目录与日志目录（`dirs.rs`）：`app_data` 只读 `HOME`、`XDG_DATA_HOME`，`logs` 只读 `HOME`、`XDG_STATE_HOME`，拼出路径，不创建目录，不做其他 IO，首帧前可以调用；两个平台的拼接是纯函数，测试直接传值，不修改进程的环境变量。日志目录的布局、权限和清理归 `logging`。
- 系统版本（`system.rs`）：`os_version` 在 macOS 上一次 `sysctlbyname("kern.osproductversion")`，只接受 ASCII 数字和点，拼成 `macOS <版本>`；其他平台为 None。字符集检查是纯函数，在所有平台上测试。
- 本地时区的偏移（`time.rs`）：`utc_offset` 在 macOS 和 Linux 上都是一次 `localtime_r`，取 `tm_gmtoff`，按给定的时刻求（含夏令时）；不读 `TZ`、不调用 `tzset`、自己不缓存，时区状态归 C 库；`localtime_r` 失败或偏移超出 TZif 的范围时为 None，其他平台为 None。范围检查是纯函数，在所有平台上测试。
- 实现其他 crate 定义的接口（`fs_watch`、`kernel` 的插件宿主等），由 `app` 注入；不依赖这些 crate 的实现。
- 文件监听后端（`fs_events`，只在 macOS）：`fs_events::backend(executor)` 返回 `lectern_fs_watch::Backend`。`Tree` 目标每个一个 FSEvents 流，都在后端私有的串行 dispatch 队列上；`Entries` 目标共用一个 kqueue 和一个经 `executor.run_dedicated` 启动的线程。CoreServices、CoreFoundation、libdispatch 的绑定手写在 `fs_events/ffi.rs`，不引入绑定 crate。`Armed` 的 drop 返回之后不再调用 `EventSink`（FSEvents 用 `dispatch_sync` 栅栏，kqueue 在同一把锁下交付和移除）。FSEvents 事件的转换是纯函数（`fs_events/convert.rs`），在所有平台上编译和测试。
- statusline 默认开启：用户已有 statusline 时保留原命令，Lectern 的脚本保存一份输入，再原样转发给原命令，关闭时恢复原配置（[ADR 0014](../../docs/adr/0014.md)）。
- 为 Analyze 调用的 agent 命令行生成 Seatbelt 配置（[ADR 0019](../../docs/adr/0019.md)）：只读本次分析的输入、被审阅版本的只读快照（已提交的文件从 git 对象写出，叠加的工作区改动从 worktree 根目录描述符出发、用 `O_NOFOLLOW_ANY | O_NONBLOCK` 打开的描述符（路径任何一级是符号链接都拒绝）用 `fclonefileat` 克隆，卷不支持时用 `fcopyfile` 复制，符号链接都重建为链接；只含受跟踪文件和本次改动的文件）、该 agent 解析后的可执行文件及其依赖闭包（npm 安装时包括按 Node 解析规则找到的已安装依赖包目录，如 `@openai/codex-darwin-arm64`；版本目录或包目录和解析出的解释器；启动链接先解析到目标，`~/bin`、`~/.local/bin` 这类公共目录里的其他文件不可读）和固定的 macOS 运行时路径（只放行具体子目录，如 `/System/Library`、`/System/Cryptexes`、`/usr/lib`、`/bin`、`/usr/bin`；`/System/Volumes` 整个子树明确拒绝，它经 firmlink 通到 `/Users` 等数据卷目录）；子模块只写成空目录，不复制它的工作区（改动了子模块的分析标为部分内容未提供）；只复用不含工作区改动的基准快照（按树 OID 加处理规则的版本，规则随 agent 命令行版本的自动加载清单变化；先写在暂存目录、完整后原子 `rename` 发布，只读），有工作区改动时每次分析 clonefile 克隆基准目录再叠加，不复用；平铺目录的索引是 `index.jsonl`（路径按 JSON 转义，非 UTF-8 的用 base64）；路径不是合法 UTF-8 的条目也移进保留目录平铺，模型按序号文件名读取；克隆后移除扩展属性、资源分叉和 ACL；只接受普通文件和符号链接（对打开的描述符 `fstat` 判断，检查和读取用同一个描述符，FIFO、socket、设备文件拒绝）；会被 agent 自动加载的配置和 `base/` 里的旧版本文件按序号平铺写出，附原路径索引，保留目录的名字按大小写折叠加 NFC 规范化避开树和叠加路径的并集，保留目录和其中的文件也参加最终的冲突检查；写出前拒绝空名、`.`、`..`、含 `/` 或 NUL 的名字和 `.git`，从快照根目录的描述符出发用 `openat` / `mkdirat` 加 `O_NOFOLLOW` 写出，条目数和路径长度有上限；对叠加之后的最终路径集合（去掉删除和重命名的旧路径）检测只在大小写或 Unicode 规范化上不同的路径，有冲突时不生成快照；快照缓存和临时目录里由 Lectern 写出的部分（`inputs/`、快照克隆）放在有容量上限的稀疏 APFS 数据映像里（`hdiutil`，不需要特权，默认 6 GB，大于全部同时允许的占用之和 4.5 GB 加余量，每次分析开始前在映像里预留 1 GB，写满时内核返回 `ENOSPC`）；`work/` 是每次分析单独创建的 1 GB 工作映像，与输入和快照不在同一个文件系统上，agent 建不了指向它们的硬链接（`EXDEV`），分析结束后强制卸载并删除映像文件，agent 设的标志、ACL 和目录权限不影响清理，平铺目录里的符号链接写成记录链接目标的数据文件，每次分析前要求宿主卷剩余空间不少于所有已挂载映像还能增长的量、新工作映像的 1 GB 与 2 GB 之和；叠加的文件写出后 `fchflags(fd, 0)` 清掉 BSD 标志；可写的只有本次分析临时目录里的 `work/`（工作目录、配置与会话数据、输出），patch 和改动前的版本放在只读的 `inputs/`；凭据文件和钥匙串一律拒绝，拒绝查看其他进程的信息（`process-info*`）；快照里的符号链接不跟随（ADR 0019）；网络只允许连接 `agents` 的凭据转发端点；每次分析的配置允许读本次唯一的临时目录、拒绝一个固定的哨兵路径，并提供 `sandbox_check` 的封装，供 `agents` 按沙箱识别这次分析的全部进程；配置拒绝执行 `/usr/bin/sandbox-exec`，并提供嵌套沙箱自检（探针尝试再应用一份配置，成功时带 shell 的 agent 不可用）；判断会被自动加载的配置路径时按 Unicode 大小写折叠加 NFC 规范化比较。

## 测试

本 crate 不依赖 GPUI，在 Linux 上也能编译：macOS 专属代码放在 `#[cfg(target_os = "macos")]` 后面，Linux 上只编译与平台无关的部分。

```sh
cargo check -p lectern-platform
just test -p lectern-platform   # macOS 上覆盖全部代码
```

- 安全读取的 Linux 实现（`openat2` 与逐级 `openat`）在 Linux CI 上测试，`O_NOFOLLOW_ANY`（`read`、`open_file`）与 `AT_SYMLINK_NOFOLLOW_ANY`（`stat`）的实现在 macOS CI 上测试。范围读取的测试（`open_file_*`、`range_*`、`identity_*`、`read_all_*` 等，见设计文档「范围读取」的「测试」）同样对每个后端各运行一次；合并区间的 `range::plan` 是纯函数，单独测试。原子替换的测试（`replace_file_*`、`race_replace_never_escapes` 等，在 `safe_read/tests/replace.rs`）也对每个后端各运行一次。线程的 CPU 时钟的测试（`thread_cpu_*`）在 Linux 和 macOS 上都运行。应用数据目录和日志目录的测试（`app_data_*`、`logs_*`）在所有平台上覆盖 macOS 和 Linux 两套规则。系统版本的字符集检查（`os_version_*`）在所有平台上运行，读取 `sysctl` 的 `os_version_reads_the_running_macos` 只在 macOS CI 上运行。本地时区的偏移的测试（`utc_offset_*`）在 Linux 和 macOS 上都运行：按时区的表在子进程里运行（`current_exe` 加 `--exact`，`TZ` 只设在子进程上），测试不修改本进程的环境变量。
- 计时：`lectern-bench` 的 `platform/safe_stat`、`platform/safe_read_4k`、`platform/safe_read_range`、`platform/safe_read_page`（`just bench platform/`，Linux 上用 `just bench --measure platform/` 采样），只测 `SafeRoot::open` 选中的生产后端。
- 文件监听后端：`fsevents_convert_*` 在所有平台上运行；`fsevents_*`、`kqueue_*` 只在 macOS CI 上运行，用真实的临时目录，经 `MacBackend::arm_with` 把批次交给记录用的闭包。FSEvents 是异步的：按期限等待（`Recorder::wait_until`，每次等待之间 `flush`），流刚启动时先写探针文件直到报告出现（`wait_live`），不用固定的 sleep 判断结果。在 Linux 上至少交叉检查：`cargo clippy -p lectern-platform --target aarch64-apple-darwin --all-features --all-targets -- -D warnings`。
- 其余调用系统 API 的行为只能在 macOS CI 上验证；能抽成纯函数的部分（如生成 Seatbelt 配置、合并 statusline 配置）写单元测试和 insta 快照，在任何平台上都能运行。
