# platform（`lectern-platform`）

macOS 专属能力：FSEvents、`open -a`、钥匙串、Seatbelt、代码签名校验、Claude Code statusline 安装；以及按平台实现的安全读取与原子替换（`SafeRoot`，Linux 实现也在这里）、线程的 CPU 时钟（`ThreadCpuClock`）、应用数据目录与日志目录（`dirs::app_data`、`dirs::logs`）、系统版本（`system::os_version`）、系统首选语言与语言偏好（`system::preferred_languages`、`system_languages`、`language_override`、`set_language_override`）、本地时区的偏移（`time::utc_offset`）、窗口 frame 的 autosave 名（`window::set_frame_autosave_name`）、系统外观（`appearance`：两个外观下的系统语义色、减弱动态效果、变化通知）、剪贴板的写入（`clipboard::write_text`），以及 bench 用的进程测量（`process`）、机器信息（`host`）、线程 QoS（`thread`）和测量构建里的帧时刻（`frame`，只在 `bench-hooks` feature 里；没有 `metal` 模块，[ADR 0049](../../docs/adr/0049.md)）。macOS 系统绑定只能出现在本 crate（架构规则 6）。

- 层：基础设施层。只依赖基础设施和 kernel 层；不依赖 GPUI。
- 设计文档：[docs/design/platform.md](../../docs/design/platform.md)，目前只覆盖安全读取（`SafeRoot`，含范围读取 `open_file` 与 `OpenFile`，[#103](https://github.com/SoloJiang/lectern-app/issues/103)，已实现）、原子替换（`SafeRoot::replace_file`，已实现）、线程的 CPU 时钟（`ThreadCpuClock`，已实现）、应用数据目录（`dirs::app_data`，已实现）、日志目录与系统版本（`dirs::logs`、`system::os_version`，已实现）、系统首选语言与语言偏好（`system::preferred_languages`、`system_languages`、`language_override`、`set_language_override`，已实现）、本地时区的偏移（`time::utc_offset`，已实现）、窗口 frame 的 autosave 名（`window::set_frame_autosave_name`，已实现）、系统外观（`appearance`，已实现）、剪贴板的写入（`clipboard::write_text`，已实现）、登录 shell 的环境（`login_env`，[#12](https://github.com/SoloJiang/lectern-app/issues/12)，已实现）、bench 用的进程测量（`process::phys_footprint`、`start_time`、`children`，已实现）、机器信息与线程 QoS（`host::describe`、`thread::set_user_interactive`，已实现）和测量构建的方法替换（`HookError` 与 `bench-hooks` 里的 `frame::on_first_presented`，已实现；`frame::record` 尚未实现；[ADR 0048](../../docs/adr/0048.md)；没有 `metal` 模块，[ADR 0049](../../docs/adr/0049.md)）。FSEvents 与 kqueue 后端（`fs_events`，已实现）的设计在 [docs/design/fs_watch.md](../../docs/design/fs_watch.md)「platform 后端」。`open -a`、钥匙串、Seatbelt、statusline 尚未设计：先在这份文档里增加小节或另写设计文档，按[模板](../../docs/design/TEMPLATE.md)编写，设计文档 PR 合并后再写对应的代码。

## 边界

- 安全读取：从根目录描述符出发，路径任何一级都不跟随符号链接、不越出根目录；普通文件的类型判断和读取用同一个描述符。接口与实现见[设计文档](../../docs/design/platform.md)，`git` 读工作区只经它。
- 范围读取（`safe_read/range.rs`）：`open_file` 与 `read` 共用打开、`fstat` 和 `Walk` 后备，普通文件的描述符转交给 `OpenFile`，在它 drop 时关闭；`OpenFile` 上的读取只用 `pread`，不用文件偏移，不另开描述符，每次读完 `fstat` 一次，返回的 `Meta::identity()` 供调用方核对版本。一次 `read_ranges` 最多 `MAX_RANGES` 段、`MAX_RANGE_BYTES` 字节。不做内存映射，不建行索引（行检查点由 `file_reader` 按 blob OID 缓存）。
- 原子替换（`safe_read/replace.rs`）：`replace_file` 是 `safe_read` 里唯一的写。父目录用 `list` 与 `open_dir` 的目录打开函数打开，之后只在这个目录描述符上做单级名字的 `*at` 调用；临时文件 `O_CREAT | O_EXCL | O_NOFOLLOW`，比较身份之后 `renameat`，任何出错路径都删除临时文件。不创建原来不存在的文件。
- 线程的 CPU 时钟（`thread_clock.rs`）：Linux 用 `pthread_getcpuclockid` 加 `clock_gettime`，macOS 用 `thread_info(THREAD_BASIC_INFO)`，端口名来自 `pthread_mach_thread_np`，时钟自己持有一个用户引用、drop 时释放；读不到时为 `ErrorKind::Unsupported`，墙上时间的回退由调用方做。
- 应用数据目录、日志目录与应用缓存目录（`dirs.rs`）：`app_data` 只读 `HOME`、`XDG_DATA_HOME`，`logs` 只读 `HOME`、`XDG_STATE_HOME`，`app_cache` 只读 `HOME`、`XDG_CACHE_HOME`，拼出路径，不创建目录，不做其他 IO，首帧前可以调用；两个平台的拼接是纯函数，测试直接传值，不修改进程的环境变量。日志目录的布局、权限和清理归 `logging`。
- 系统版本与首选语言（`system.rs`）：`os_version` 在 macOS 上一次 `sysctlbyname("kern.osproductversion")`，只接受 ASCII 数字和点，拼成 `macOS <版本>`；其他平台为 None。`preferred_languages` 在 macOS 上用 `CFLocaleCopyPreferredLanguages`，只接受 ASCII 字母、数字和连字符的标签，最多 16 个；其他平台为空。两者的字符集检查都是纯函数，在所有平台上测试。
- 语言偏好（`system/language.rs`、`system/language/queue.rs`）：`system_languages` 读全局域、`language_override` 读应用域的 `AppleLanguages`，都用 `CFPreferencesCopyValue` 指定域（不用 `CopyAppValue`：它会回落到全局域），数组的读取与过滤和 `preferred_languages` 共用；`set_language_override` 把请求交给一个全局的串行队列（最多一个等待的请求，新请求顶掉旧请求并以 `Superseded` 完成，线程在队列空时结束），用 `CFPreferencesSetValue` 加 `CFPreferencesSynchronize` 写，失败记一条 warn（只带种类）。队列是纯逻辑，写入函数可替换，在所有平台上测试；测试里的偏好写进临时目录里的 plist，不写用户的偏好。首帧之前不调用。
- 本地时区的偏移（`time.rs`）：`utc_offset` 在 macOS 和 Linux 上都是一次 `localtime_r`，取 `tm_gmtoff`，按给定的时刻求（含夏令时）；不读 `TZ`、不调用 `tzset`、自己不缓存，时区状态归 C 库；`localtime_r` 失败或偏移超出 TZif 的范围时为 None，其他平台为 None。范围检查是纯函数，在所有平台上测试。
- 窗口 frame 的 autosave 名（`window.rs`）：`set_frame_autosave_name` 从 `raw_window_handle` 的 AppKit 句柄取 `NSView`，对它的 `NSWindow` 调 `setFrameAutosaveName:`（ADR 0017：窗口位置与大小由 AppKit 保存，不读 Lectern 自己的文件）。检查按名字、句柄、主线程（`pthread_main_np`）、AppKit 的顺序，不在主线程时不读视图指针；Objective-C 运行时与 CoreFoundation 的调用手写在模块里，不引入绑定 crate。名字的检查是纯函数，在所有平台上测试；其他平台只检查名字，不碰窗口。失败时函数自己以 warn 记一条、只带 `kind`，调用方不再记。
- 系统外观（`appearance.rs`）：`system_colors` 用 `NSAppearance` 的 `performAsCurrentDrawingAppearance:` 在给定外观下解析 `NSColor` 的语义色，每个颜色转到 sRGB 后读分量，任一颜色读不到整个结果为 None（颜色值只在 `ui` 的内置表里）；`reduce_motion` 读 `NSWorkspace`；`watch` 在默认通知中心和 `NSWorkspace` 的通知中心各登记一个块观察者，回调在投递线程上同步运行（AppKit 在主线程投递），`Watch` drop 时注销，回调 panic 在 AppKit 的边界上截住。块的 ABI、ObjC 运行时和 AppKit 的符号都手写在模块里，不引入绑定 crate；`extern` 块带 `#[link(name = "AppKit", kind = "framework")]`，测试二进制因此也加载 AppKit。本模块不缓存。
- 剪贴板的写入（`clipboard.rs`）：`write_text` 把写入用 `dispatch_async_f` 排到主队列，在主线程的自动释放池里对 `[NSPasteboard generalPasteboard]` 做 `clearContents`、`setString:forType:`（`NSPasteboardTypeString`，字符串由 `initWithBytes:length:encoding:` 建出），写完在主线程上调用 `done`（panic 被截住）；其他平台立即以 `Unsupported` 调用 `done`。不读剪贴板，不记日志，不记录文字。写入函数（`write_to`）带剪贴板对象作参数，测试只写 `pasteboardWithUniqueName` 建出的私有剪贴板，不碰用户的通用剪贴板。Objective-C 运行时、AppKit、libdispatch 的符号手写在模块里，不引入绑定 crate。
- bench 用的进程、机器信息与线程 QoS（`process.rs`、`host.rs`、`thread.rs`）：普通接口，不在任何 feature 后面；macOS 上是 `libc` 的 `proc_pid_rusage`、`proc_pidinfo`、`proc_listchildpids`、`sysctlbyname`、`pthread_set_qos_class_self_np`，其他平台返回 `ErrorKind::Unsupported`。发布构建里没有调用方。`children` 用 `proc_listchildpids`：空缓冲的第一次调用返回的是估计值，不是子进程数，两次调用的单位都是 pid 的个数，内核给的顺序不是升序（实现自己排序）；它出错时返回 0，所以不存在的进程得到空列表。`host` 与 `system::os_version` 共用 `system::product_version` 检查系统版本。
- 测量构建的方法替换（`frame`，[ADR 0048](../../docs/adr/0048.md)）：代码只在 `#[cfg(all(target_os = "macos", feature = "bench-hooks"))]` 后面，只有 `lectern-bench` 的 `probe` 打开 `bench-hooks`（`scripts/check_architecture.py` 检查），发布构建不含。没有这个 feature 时公开项照样编译，返回 `HookError::Unsupported`。只替换系统框架的类的方法，一个选择器只替换一次、不恢复；替换前核对类、选择器和类型编码，不符为 `Mismatch`，不替换。替换的实现和 block 不分配、不加锁、不 panic，也不记日志。首帧之前只有 `on_first_presented` 的一次替换。`HookError` 在 `hook.rs`（所有平台、有没有 feature 都编译，核对类型编码的 `check_type_encoding` 是纯函数）；`on_first_presented` 在 `frame.rs`：先 `find_method` 核对类、选择器和类型编码（`CAMetalLayer nextDrawable`、`@16@0:8`，只读，`Mismatch` 时什么都没有改，也不占用登记），再登记，然后一个静态的 `AtomicPtr` 槽放泄漏的回调，在 `method_setImplementation` 之前先把原来的实现存进静态变量，两个选择器在安装时登记（`sel_registerName` 在运行时里有锁，替换的实现和 block 里不调用它）。替换后的 `nextDrawable` 先调原来的实现，槽里还有回调时在返回的 drawable 上登记 `addPresentedHandler:`；block 读 `presentedTime`，由 `deliver` 原子取出回调、用 `CACurrentMediaTime` 与 `SystemTime::now` 换算后调用：大于 0 时交出 `presentedTime`（`TimeSource::Presented`）；不大于 0 时，`Fallback::HandlerTime` 交出回调运行的时刻（`TimeSource::Handler`），`Fallback::Wait` 不交出、等下一个 drawable（[ADR 0052](../../docs/adr/0052.md)）；结果是 `PresentedAt`。Objective-C 运行时、block、Metal、QuartzCore、CoreVideo 的符号手写，不引入绑定 crate。`record`（B2）：主线程上从视图取 `CAMetalLayer` 和显示器，第一次时替换命令缓冲类的 `commit`（类从窗口设备的一个临时命令缓冲取得，只替换第一个类），每个显示器建一个 CVDisplayLink、永不释放；配对在 `frame/pairing.rs`（`Store`：8192 个槽、16384 个 tick，第一次 `record` 时分配、永不释放，按代数丢弃过时的回调；`Clock`：刻度到纳秒、到系统时钟），不依赖 Objective-C，所有平台编译。钩子只配对记录线程上的 `nextDrawable` 和 `commit`。升级 GPUI 之后先运行 `just bench baseline/` 和帧基准。
- 登录 shell 的环境（`login_env.rs`，只在 macOS 和 Linux）：`login_env` 运行一次 `<shell> -l -i -c`，`setsid` 后没有控制终端，stdin 和 stderr 是 `/dev/null`；在调用线程上用 `poll` 读 stdout（不另开线程，ADR 0024），期限 5 秒，到期向进程组发 `SIGKILL`；用随机标记和 `env -0` 分开环境与配置文件的其他输出。结果（含失败）在进程内只取一次，阻塞，不在 UI 线程上调用，首帧之前不调用。不记 shell 的路径、变量的名字和值、shell 的输出。
- 实现其他 crate 定义的接口（`fs_watch`、`kernel` 的插件宿主等），由 `app` 注入；不依赖这些 crate 的实现。
- 文件监听后端（`fs_events`，只在 macOS）：`fs_events::backend(executor)` 返回 `lectern_fs_watch::Backend`。`Tree` 目标每个一个 FSEvents 流，都在后端私有的串行 dispatch 队列上；`Entries` 目标共用一个 kqueue 和一个经 `executor.run_dedicated` 启动的线程。CoreServices、CoreFoundation、libdispatch 的绑定手写在 `fs_events/ffi.rs`，不引入绑定 crate。`Armed` 的 drop 返回之后不再调用 `EventSink`（FSEvents 用 `dispatch_sync` 栅栏，kqueue 在同一把锁下交付和移除）。FSEvents 事件的转换是纯函数（`fs_events/convert.rs`），在所有平台上编译和测试。
- 运行日志（[ADR 0046](../../docs/adr/0046.md)）：只经 `lectern-logging` 的宏，不写 stderr、不启用 `sink`。本 crate 的记录只有五处：kqueue 线程停止（`Kqueue::fail`，error，`watches` 与 `Value::io`）、frame autosave 名设置失败（`window`，warn，只带 `kind`）、外观变化回调的 panic（`appearance`，error，只带 `change`）、语言偏好写入失败（`system`，warn，只带 `kind`）和取登录环境的结果（`login_env`，失败 warn，带 `kind`，`Spawn` 时另有 `Value::io`；成功 debug，带 `vars`、`took`），都只在 macOS 上编译，`lectern-logging` 因此只是 macOS 上的依赖；其余模块把错误返回给调用方，不记日志。不记文件内容、监听的目录、具名条目的名字、`io::Error` 的消息和 frame autosave 的名字、语言标签（设计「日志与诊断」）。
- statusline 默认开启：用户已有 statusline 时保留原命令，Lectern 的脚本保存一份输入，再原样转发给原命令，关闭时恢复原配置（[ADR 0014](../../docs/adr/0014.md)）。
- 为 Analyze 调用的 agent 命令行生成 Seatbelt 配置（[ADR 0019](../../docs/adr/0019.md)）：只读本次分析的输入、被审阅版本的只读快照（已提交的文件从 git 对象写出，叠加的工作区改动从 worktree 根目录描述符出发、用 `O_NOFOLLOW_ANY | O_NONBLOCK` 打开的描述符（路径任何一级是符号链接都拒绝）用 `fclonefileat` 克隆，卷不支持时用 `fcopyfile` 复制，符号链接都重建为链接；只含受跟踪文件和本次改动的文件）、该 agent 解析后的可执行文件及其依赖闭包（npm 安装时包括按 Node 解析规则找到的已安装依赖包目录，如 `@openai/codex-darwin-arm64`；版本目录或包目录和解析出的解释器；启动链接先解析到目标，`~/bin`、`~/.local/bin` 这类公共目录里的其他文件不可读）和固定的 macOS 运行时路径（只放行具体子目录，如 `/System/Library`、`/System/Cryptexes`、`/usr/lib`、`/bin`、`/usr/bin`；`/System/Volumes` 整个子树明确拒绝，它经 firmlink 通到 `/Users` 等数据卷目录）；子模块只写成空目录，不复制它的工作区（改动了子模块的分析标为部分内容未提供）；只复用不含工作区改动的基准快照（按树 OID 加处理规则的版本，规则随 agent 命令行版本的自动加载清单变化；先写在暂存目录、完整后原子 `rename` 发布，只读），有工作区改动时每次分析 clonefile 克隆基准目录再叠加，不复用；平铺目录的索引是 `index.jsonl`（路径按 JSON 转义，非 UTF-8 的用 base64）；路径不是合法 UTF-8 的条目也移进保留目录平铺，模型按序号文件名读取；克隆后移除扩展属性、资源分叉和 ACL；只接受普通文件和符号链接（对打开的描述符 `fstat` 判断，检查和读取用同一个描述符，FIFO、socket、设备文件拒绝）；会被 agent 自动加载的配置和 `base/` 里的旧版本文件按序号平铺写出，附原路径索引，保留目录的名字按大小写折叠加 NFC 规范化避开树和叠加路径的并集，保留目录和其中的文件也参加最终的冲突检查；写出前拒绝空名、`.`、`..`、含 `/` 或 NUL 的名字和 `.git`，从快照根目录的描述符出发用 `openat` / `mkdirat` 加 `O_NOFOLLOW` 写出，条目数和路径长度有上限；对叠加之后的最终路径集合（去掉删除和重命名的旧路径）检测只在大小写或 Unicode 规范化上不同的路径，有冲突时不生成快照；快照缓存和临时目录里由 Lectern 写出的部分（`inputs/`、快照克隆）放在有容量上限的稀疏 APFS 数据映像里（`hdiutil`，不需要特权，默认 6 GB，大于全部同时允许的占用之和 4.5 GB 加余量，每次分析开始前在映像里预留 1 GB，写满时内核返回 `ENOSPC`）；`work/` 是每次分析单独创建的 1 GB 工作映像，与输入和快照不在同一个文件系统上，agent 建不了指向它们的硬链接（`EXDEV`），分析结束后强制卸载并删除映像文件，agent 设的标志、ACL 和目录权限不影响清理，平铺目录里的符号链接写成记录链接目标的数据文件，每次分析前要求宿主卷剩余空间不少于所有已挂载映像还能增长的量、新工作映像的 1 GB 与 2 GB 之和；叠加的文件写出后 `fchflags(fd, 0)` 清掉 BSD 标志；可写的只有本次分析临时目录里的 `work/`（工作目录、配置与会话数据、输出），patch 和改动前的版本放在只读的 `inputs/`；凭据文件和钥匙串一律拒绝，拒绝查看其他进程的信息（`process-info*`）；快照里的符号链接不跟随（ADR 0019）；网络只允许连接 `agents` 的凭据转发端点；每次分析的配置允许读本次唯一的临时目录、拒绝一个固定的哨兵路径，并提供 `sandbox_check` 的封装，供 `agents` 按沙箱识别这次分析的全部进程；配置拒绝执行 `/usr/bin/sandbox-exec`，并提供嵌套沙箱自检（探针尝试再应用一份配置，成功时带 shell 的 agent 不可用）；判断会被自动加载的配置路径时按 Unicode 大小写折叠加 NFC 规范化比较。

## 测试

本 crate 不依赖 GPUI，在 Linux 上也能编译：macOS 专属代码放在 `#[cfg(target_os = "macos")]` 后面，Linux 上只编译与平台无关的部分。

```sh
cargo check -p lectern-platform
just test -p lectern-platform   # macOS 上覆盖全部代码
```

- 安全读取的 Linux 实现（`openat2` 与逐级 `openat`）在 Linux CI 上测试，`O_NOFOLLOW_ANY`（`read`、`open_file`）与 `AT_SYMLINK_NOFOLLOW_ANY`（`stat`）的实现在 macOS CI 上测试。范围读取的测试（`open_file_*`、`range_*`、`identity_*`、`read_all_*` 等，见设计文档「范围读取」的「测试」）同样对每个后端各运行一次；合并区间的 `range::plan` 是纯函数，单独测试。原子替换的测试（`replace_file_*`、`race_replace_never_escapes` 等，在 `safe_read/tests/replace.rs`）也对每个后端各运行一次。线程的 CPU 时钟的测试（`thread_cpu_*`）在 Linux 和 macOS 上都运行。应用数据目录和日志目录的测试（`app_data_*`、`logs_*`）在所有平台上覆盖 macOS 和 Linux 两套规则。系统版本的字符集检查（`os_version_*`）在所有平台上运行，读取 `sysctl` 的 `os_version_reads_the_running_macos` 只在 macOS CI 上运行。本地时区的偏移的测试（`utc_offset_*`）在 Linux 和 macOS 上都运行：按时区的表在子进程里运行（`current_exe` 加 `--exact`，`TZ` 只设在子进程上），测试不修改本进程的环境变量。
- 计时：`lectern-bench` 的 `platform/safe_stat`、`platform/safe_read_4k`、`platform/safe_read_range`、`platform/safe_read_page`（`just bench platform/`，Linux 上用 `just bench --measure platform/` 采样），只测 `SafeRoot::open` 选中的生产后端。
- 文件监听后端：`fsevents_convert_*` 在所有平台上运行；`fsevents_*`、`kqueue_*` 只在 macOS CI 上运行，用真实的临时目录，经 `MacBackend::arm_with` 把批次交给记录用的闭包。FSEvents 是异步的：按期限等待（`Recorder::wait_until`，每次等待之间 `flush`），流刚启动时先写探针文件直到报告出现（`wait_live`），不用固定的 sleep 判断结果。`kqueue_stop_is_logged_without_paths` 用 `lectern-logging` 的 `testing::capture()` 检查 kqueue 线程停止的记录和金丝雀，同样只在 macOS 上运行。在 Linux 上至少交叉检查：`cargo clippy -p lectern-platform --target aarch64-apple-darwin --all-features --all-targets -- -D warnings`。
- 窗口 frame 的 autosave 名：`frame_autosave_name_*`、`set_frame_autosave_name_checks_*`、`window_error_*` 在所有平台上运行；`set_frame_autosave_name_without_a_handle_*`、`*_with_a_foreign_handle_*`、`*_off_the_main_thread_*`（用 `testing::capture()` 检查 warn 记录和金丝雀）、`every_failure_is_logged_with_its_kind` 只在 macOS 上运行；`set_frame_autosave_name_does_nothing_elsewhere` 只在其他平台上运行。这些测试都没有真实窗口（测试线程不是主线程）。真实窗口的检查是 `examples/frame_autosave.rs`，手工运行 `cargo run -p lectern-platform --example frame_autosave`（需要窗口服务器会话，退出码 0 为通过），CI 只编译它。
- 系统外观：`appearance_*` 的纯函数部分在所有平台上运行；读颜色、读减弱动态效果和 `watch` 的测试只在 macOS 上运行，在测试线程上、不需要窗口和 `NSApplication`，通知经 `NSNotificationCenter` 手动投递，投递的测试经一把锁串行；`appearance_watch_contains_a_panicking_callback_and_logs_no_payload` 用 `testing::capture()` 检查 panic 的记录和金丝雀。本进程第一次读取的耗时由 `cargo run --release -p lectern-platform --example appearance_first_read` 手工测量（要在主线程上建 `NSApplication` 和窗口）。
- 剪贴板：`clipboard_round_trip_on_a_private_pasteboard` 只在 macOS 上运行，写私有的具名剪贴板（`pasteboardWithUniqueName`）再读回，最后 `releaseGlobally`；`clipboard_is_unsupported_elsewhere` 只在其他平台上运行。排到主队列的那一步要有运行中的主线程，测试进程里没有，由 review_view 的手动检查覆盖。
- 进程、机器信息与线程 QoS：`host_value_*` 在所有平台上运行；`process_*`、`host_describe_reads_this_mac`、`thread_set_user_interactive_sets_the_qos` 只在 macOS 上运行；`*_is_unsupported_elsewhere` 只在其他平台上运行。
- 方法替换：`frame_clock_*`、`frame_pairing_*`、`hook_error_*`、`hook_type_encoding_check` 是纯函数，在所有平台上运行；钩子的测试要 `bench-hooks`，`just test` 带 `--all-features`，所以在 macOS CI 上运行：`frame_first_presented_installs_once`、`hook_mismatch_installs_nothing`、`hook_deliver_*`（槽；大于 0 的 `presentedTime` 为 `Presented`，0、负数、NaN 在 `HandlerTime` 下为 `Handler`、在 `Wait` 下不交付；只调用一次）、`frame_hook_passes_drawables_through_on_an_offscreen_layer`（离屏的 `CAMetalLayer`，本机没有 Metal 设备时直接返回）、`frame_hooks_on_an_offscreen_layer`（经 `record_layer` 在测试线程上记录两种画帧顺序，要 Metal 设备）、`frame_record_off_the_main_thread_is_an_error`；它们共用一个进程里的登记，用一把锁轮流运行，`cargo test` 与 nextest 的结果相同。Linux CI 和 macOS 上不带 feature 运行 `frame_is_unsupported_without_bench_hooks`。真实窗口的检查是 `examples/frame_hooks.rs`（`required-features = ["bench-hooks"]`；11 个冷进程测 `on_first_presented` 的耗时，中位数 ≤ 100 µs；再开窗口等首帧回调并打印来源；锁屏时和托管的 CI runner 上 `presentedTime` 一直为 0，来源为 `handler`），之后由示例自己的 CVDisplayLink 驱动 120 帧不记录、120 帧记录，检查 `problems` 干净、帧数齐全、相邻 `started` 的间隔中位数与 `refresh` 相差不超过 10%，打印每帧的开销），手工运行 `cargo run --release -p lectern-platform --features bench-hooks --example frame_hooks`，CI 只编译它。
- 登录 shell 的环境：`login_env_*`、`pick_shell_*`、`find_program_*` 在 Linux 和 macOS 上都运行，假 shell 是测试写在临时目录里的 `/bin/sh` 脚本，夹具在 `tests/fixtures/login_env/`；`login_env::tests::logs` 的金丝雀测试只在 macOS 上运行。用户真实的 shell 只在 `#[ignore]` 的 `login_env_reads_this_users_shell` 里运行，手工运行，CI 不运行。
- 其余调用系统 API 的行为只能在 macOS CI 上验证；能抽成纯函数的部分（如生成 Seatbelt 配置、合并 statusline 配置）写单元测试和 insta 快照，在任何平台上都能运行。
