# usage（`lectern-usage`）

token 用量去重、按项目和 MR 归属与聚合（入 SQLite）、额度快照，不估算费用（[ADR 0022](../../docs/adr/0022.md)）；Claude Code 额度来自 statusline，Codex 额度来自日志（[ADR 0014](../../docs/adr/0014.md)、[ADR 0020](../../docs/adr/0020.md)）。

- 层：领域层。可以依赖领域、基础设施和 kernel 层；不得直接或间接依赖 GPUI（架构规则 2）。
- 设计文档：[docs/design/usage.md](../../docs/design/usage.md)
- issue：[#31](https://github.com/SoloJiang/lectern-app/issues/31)、[#32](https://github.com/SoloJiang/lectern-app/issues/32)
- ADR：[0014](../../docs/adr/0014.md)、[0019](../../docs/adr/0019.md)、[0020](../../docs/adr/0020.md)、[0022](../../docs/adr/0022.md)、[0027](../../docs/adr/0027.md)、[0044](../../docs/adr/0044.md)、[0047](../../docs/adr/0047.md)

## 边界

- 统计分项目和 MR 两级（ADR 0020）：git 仓库按 git 公共目录的规范绝对路径识别，每个项目另有 Lectern 分配的固定标识写进每条观察，打开已知路径或别名路径时重新比对根提交 OID，根提交一致也比对完整标识（有代码平台仓库 ID 时以它为准（平台主机 + 仓库 ID，ID 只在同一主机上唯一；已知项目有 ID、这次取不到时按未知处理，无论根提交是否一致都先给临时项目，取到 ID 后再比对），没有时比对主远端（默认分支上游所在的远端，通常是 `origin`；都没有时唯一的远端，多个远端则比较完整集合；第一次识别时选定并记下，之后沿用，新增的远端不影响，被删掉或改名才重选）的地址，或两边都没有远端；fork 常把原仓库加成 `upstream`，只看集合交集会误合并），根提交不一致但仓库 ID 相同（没有仓库 ID 时主远端地址相同）时视为改写历史，对不上（路径被无关仓库或 fork 占用）时为它分配新项目，两边都没有远端和仓库 ID、根提交变了的本地仓库先用临时项目并在 Usage 页请用户确认，还没有提交的仓库先用临时项目、第一个提交出现后按同一套完整标识（不只根提交）比对，再并入或转为新项目，同一仓库的所有 worktree 是同一个项目，仓库移动或改名后，根提交 OID 和远端地址集合都一致、远端地址集合非空且只有一个候选时，或两边的代码平台仓库 ID 相同且只有一个候选时（此时根提交和远端变过也算），才记下旧路径到新路径的别名（fork 不合并，有歧义时由用户在 Usage 页手动合并，合并与撤销都记为别名）；不是 git 仓库的文件夹以打开的根目录为准，也是项目，只是没有 MR 这一级，项目合计按时间窗口统计，包含它的全部 MR、未开 MR 的分支、不属于任何 MR 的用量和 Lectern 自己的分析；有改动的轮次按改动所在的项目判断（跨项目时按改动权重分摊，不看 cwd），没有改动的轮次跟随最近的有改动轮次（项目和分支一起跟随），会话里没有改动时才按 cwd 判断，两者都不在任何已打开项目里时才暂时归入「其他」，之后打开对应项目时自动归入。MR 的归属规则：有改动的轮次按改动所在 worktree 的分支归属，一轮改了多个分支时按「改动行数 + 改动文件数」分摊；没有改动的轮次跟随同一会话里最近的有改动轮次（先找之前、再找之后；跟踪中的会话里有两个例外：命令明确进入了某个 worktree（从 `agents` 交来的命令文本解析出的 `cd`、`pushd`、`git -C`），或读文件、搜索工具的目标路径在某个 worktree 里时，或这一轮写过文件但没有留下改动、写文件的目标在某个 worktree 里时，按进入的 worktree 当时的分支和项目归属，进入几个就平均分摊，优先于跟随；这一轮确定观察到 cwd 所在 worktree 换了分支、而最近的改动就在这个 worktree 时，按这一轮自己的分支），会话里没有改动时按每一轮结束时（及可能切换分支的工具调用之后）观察到的 cwd 分支，一轮里观察到几个分支（包括一次调用期间 HEAD 确定停留过的分支）时平均分摊，导入的旧会话才用日志记录的分支；子 agent 先按自己的改动归属再计入父会话（子 agent 里没有改动的轮次先跟随它自己会话里最近的有改动轮次，整个子 agent 会话都没有改动才跟随父轮次），整棵子树都没有改动时按普通的没有改动的轮次处理（跟踪中的会话用每一轮观察到的分支）；分支按「一次使用」区分，观察里写固定的片段标识，哪些片段属于同一次使用在汇总时计算（`forge` 之后证明边界发生时开着 MR 的，或边界时关闭、之后同一个 MR 在边界之后的片段上重新打开的，前后片段合并；stash 恢复到另一个分支上时（按改动块认定：stash 的每个改动块按恢复后的工作区文件判断，加上的行都在、删掉的行已不在，目标分支 HEAD 已有一部分也算满足，且至少有一行出现在工作区相对 HEAD 的改动里，二进制和只改模式的改动按 blob OID 与模式比较，三方合并后也能认出，`-u` / `-a` 存下的文件取自 stash 提交的第三个父提交；还要有恢复的证据：这个 worktree 上执行过的 `git stash apply` / `pop` 命令，或这条 stash 从 `refs/stash` 的 reflog 消失的时刻与改动出现的时刻相差不超过 5 秒；匹配的改动至少有一处要在恢复时（命令证据含结果之后 5 秒）被文件监听记到变化（工作区本来就有同样改动时 apply 会中止），命令里的 `stash@{n}`、OID 或默认的 `stash@{0}` 按执行前的 reflog 解析，只认它指向的那一条，解析不出来时内容匹配的候选要恰好一条），产生改动的轮次随之转到那个分支），改名按 reflog 的改名记录沿用同一标识（删除后重建、没有开着的 MR 时用 `reset`、`branch -f`、`checkout -B` 丢弃了分支独有的提交（按新旧位置的提交关系判断：新位置包含旧的独有提交即连续，不包含时要有改写的证据（命令里的 rebase / amend，或旧的每个独有提交都按 patch-id 在新位置一一对应）才算连续，不只看 reflog 说明文字）、或只有未提交改动的分支回到起点且工作区干净（`git stash` 只是挂起，stash 被删掉且改动没有恢复时才结束），才算新的一次；`forge` 仍把分支对应到开着的 MR 时，本地删除重建也留在同一次），MR 区间在同一次使用之内，起点是它开出之前最近一次合并或关闭事件的时刻（之后别的 MR 重新打开不改变它），包含开 MR 之前的工作，以最后一次合并或关闭为准（关闭后重新打开时，关闭期间的工作并入；`forge` 提供状态时间线）；`forge` 有对应 MR 时优先于默认分支的规则；「审阅」的用量来自 `agents` 为每次 Lectern 分析交来的计量记录（转发前落盘为「已准备」，请求体写入上游后改为「已转发」，随用量更新，非 2xx 且没有用量的「被拒绝」记为 0，重启时只把「已接受」的按估算结算，其余作废；token 按输入、输出、缓存读取、缓存写入分类保存，保存前按服务商规范化成互不重叠的类别（Codex / OpenAI 的输入包含缓存命中，先减去缓存部分；Anthropic 的输入不含缓存，原样保存）；时间戳、agent 与模型、token、估算标记、项目与 MR 或分支上下文），日志里没有这些调用；一次分析覆盖多个分支时按改动权重分摊，「审阅」不受 MR 区间限制。每个可能产生改动或切换分支的工具调用（写文件、执行命令）执行之后按工具结果的时间戳，从 worktree 的 HEAD reflog 还原那一刻的分支和 HEAD（每个工具调用的观察和 reflog 亚秒时刻在到达时就写入 SQLite，一轮结束时才做分摊；不读解析时的当前状态；用文件监听记下的每条 reflog 的亚秒时刻和序号排序，排不出先后时标为「不确定」（例外：确定在结果之前、只是不确定是否在开始之后的切换只有一条时，它的目标计入；连续有几条时这次调用标为不确定），按改动内容的去向归属），一次调用里多次切换分支时按调用期间各分支 reflog 新增的提交归属（未提交的改动归调用结束时的分支），每条观察带仓库的稳定标识（git 公共目录、代码平台给仓库的不变 ID，不用会随改名变化的 owner/name），一轮结束后把这些观察连同 cwd、改动路径与按「文件 × 分支观察」记录的改动行数和是否为默认分支写入 SQLite，重建以这份记录为准（之后打开的普通文件夹也能据 cwd 认领以前的用量）；时间窗口按每条用量记录的时间戳、用户本地时区的自然日划分；MR 详情显示自己区间内的用量，共用分支时其中一个关闭后，之后的用量只计入还开着的 MR；Usage 页里同一次使用上统计区间互相重叠的几个 MR 合为一行（不同分支的 MR 不合并；同一次使用里先后开出、区间不重叠的 MR 各占一行），只含这些 MR 区间内的用量，区间之外的同一次使用单独显示为未开 MR 的分支，「不属于任何 MR」单独一行（在默认分支或 detached HEAD 上开始、随后由 `switch -c` 带进新分支的工作，按 reflog 的创建记录归到新分支，切到已有分支时随工作区带过去的未提交改动同样转移；reftable 仓库监视 `reftable/` 取时刻、用 `git reflog` 一类接口读记录；会话简报发起的分析在发起时解析出被分析轮次所属的 MR（含已关闭的）并随计量记录保存；detached 上的提交经 `git push <远端> HEAD:<分支>` 成功推到某个 MR 的源分支（远端跟踪分支在调用期间更新到它），或之后成为 `forge` 报告的 MR head 的一部分而 MR 的目标分支不包含它们，且只有一个 MR 符合时，随之转到这个 MR；cherry-pick 到新分支的提交先按命令里的提交 OID、没有命令时按 `git::Repo::patch_id`（`git patch-id --stable` 的口径，见 git 设计「usage 用的读取」）找到原提交（候选要恰好一个），原提交不属于任何 MR 时改出它的轮次随之转移），所有项目的列表里有「其他」一行；无法确定分支的旧会话标为「无法归属」。会话和轮次是 MR 之下的明细，一轮被分摊到多个 MR 时，每个 MR 的明细显示分到它的那一份。分摊结果按分数保存，显示时用最大余数法取整，各行相加等于合计；普通文件夹没有分支和 MR 明细，按 agent 和模型的明细照常有。归属规则逐条有 fixtures 覆盖，包括跨 worktree 改动和同名分支复用。
- 去重与解析规则以 ADR 0014 为准（Claude Code 按 `message.id` + `requestId` 去重，Codex 子 agent 只计 `task_started` 之后），每条规则都有 fixtures 覆盖；ccusage 的 `--json` 输出只在测试里做对照。
- 除了会话日志，`agents` 会交来 Analyze 调用的原始用量记录（[ADR 0019](../../docs/adr/0019.md)）：凭据转发端点每个模型请求一条，带分析 ID，转发之前就落盘为按上限估算的待定记录，收到用量后替换，取消和失败的分析也有；没收到用量就中断（包括 Lectern 崩溃）的请求保留为「估算（上限）」。辅助会话不写入用户的会话目录，所以不会与日志重复。
- 聚合结果写入 Lectern 自己的 SQLite（Claude Code 默认删除 30 天前的会话文件）：本 crate 自己的数据库，放在应用数据目录下，不在 `cache` 的目录里、不能删除重建，经 rusqlite，页缓存 ≤ 2 MB（[ADR 0027](../../docs/adr/0027.md)）；statusline 的安装在 `platform`，本 crate 只解析它存下的 JSON。

## 测试

不依赖 GPUI，在任何平台上都能编译和测试：

```sh
cargo check -p lectern-usage     # 只改本 crate 时最快的反馈
just test -p lectern-usage
```

- 单元测试写在模块旁的 `#[cfg(test)] mod tests`；结构化输出（解析结果、归因、diff）用 insta 快照验收，快照改动要在 PR 里逐个看过。
- fixtures 放 `tests/fixtures/`，全部是合成数据：按 agents 设计「外部格式」、ADR 0014 和公开文档描述的格式构造，不取自本机的会话日志和 agent 的配置目录；格式随上游版本变化的，每个版本留一份样本。
