# usage（`lectern-usage`）

token 用量去重、按项目和 MR 归属与聚合（入 SQLite）、价格表、额度快照；Claude Code 额度来自 statusline，Codex 额度来自日志（[ADR 0014](../../docs/adr/0014.md)、[ADR 0020](../../docs/adr/0020.md)）。

- 层：领域层。可以依赖领域、基础设施和 kernel 层；不得直接或间接依赖 GPUI（架构规则 2）。
- 设计文档：`docs/design/usage.md`，尚未编写。先按[模板](../../docs/design/TEMPLATE.md)编写，设计文档 PR 合并后再写代码。
- issue：[#31](https://github.com/SoloJiang/lectern-app/issues/31)、[#32](https://github.com/SoloJiang/lectern-app/issues/32)
- ADR：[0014](../../docs/adr/0014.md)、[0020](../../docs/adr/0020.md)

## 边界

- 统计分项目和 MR 两级（ADR 0020）：git 仓库按 git 公共目录的规范绝对路径识别，每个项目另有 Lectern 分配的固定标识写进每条观察，打开已知路径或别名路径时重新比对根提交 OID，根提交一致也比对完整标识（有代码平台仓库 ID 时以它为准，没有时要求远端集合有交集），根提交不一致但仓库 ID 相同（或远端有交集）时视为改写历史，对不上（路径被无关仓库或 fork 占用）时为它分配新项目，还没有提交的仓库先用临时项目、第一个提交出现后再并入或转为新项目，同一仓库的所有 worktree 是同一个项目，仓库移动或改名后，根提交 OID 和远端地址集合都一致、远端地址集合非空（或有代码平台仓库 ID）且只有一个候选时才记下旧路径到新路径的别名（fork 不合并，有歧义时由用户在 Usage 页手动合并，合并与撤销都记为别名）；不是 git 仓库的文件夹以打开的根目录为准，也是项目，只是没有 MR 这一级，项目合计按时间窗口统计，包含它的全部 MR、未开 MR 的分支、不属于任何 MR 的用量和 Lectern 自己的分析；有改动的轮次按改动所在的项目判断（跨项目时按改动权重分摊，不看 cwd），没有改动的轮次跟随最近的有改动轮次（项目和分支一起跟随），会话里没有改动时才按 cwd 判断，两者都不在任何已打开项目里时才暂时归入「其他」，之后打开对应项目时自动归入。MR 的归属规则：有改动的轮次按改动所在 worktree 的分支归属，一轮改了多个分支时按「改动行数 + 改动文件数」分摊；没有改动的轮次跟随同一会话里最近的有改动轮次（先找之前、再找之后；跟踪中的会话里，这一轮确定观察到 cwd 所在 worktree 换了分支、而最近的改动就在这个 worktree 时，按这一轮自己的分支），会话里没有改动时按每一轮结束时（及可能切换分支的工具调用之后）观察到的 cwd 分支，一轮里观察到几个分支（包括一次调用期间 HEAD 确定停留过的分支）时平均分摊，导入的旧会话才用日志记录的分支；子 agent 先按自己的改动归属再计入父会话（子 agent 里没有改动的轮次先跟随它自己会话里最近的有改动轮次，整个子 agent 会话都没有改动才跟随父轮次），整棵子树都没有改动时按普通的没有改动的轮次处理（跟踪中的会话用每一轮观察到的分支）；分支按「一次使用」区分，每次使用有固定标识，改名按 reflog 的改名记录沿用同一标识（删除后重建、没有开着的 MR 时用 `reset`、`branch -f`、`checkout -B` 丢弃了分支独有的提交（按 reflog 的动作判断，rebase 无论是否删改提交都算连续）、或只有未提交改动的分支回到起点且工作区干净（`git stash` 只是挂起，stash 被删掉且改动没有恢复时才结束），才算新的一次；`forge` 仍把分支对应到开着的 MR 时，本地删除重建也留在同一次），MR 区间在同一次使用之内，起点是它开出之前最近一次合并或关闭事件的时刻（之后别的 MR 重新打开不改变它），包含开 MR 之前的工作，以最后一次合并或关闭为准（关闭后重新打开时，关闭期间的工作并入；`forge` 提供状态时间线）；`forge` 有对应 MR 时优先于默认分支的规则；「审阅」的用量来自 `agents` 为每次 Lectern 分析交来的计量记录（转发前落盘为「已准备」，请求体写入上游后改为「已转发」，随用量更新，重启时只把「已转发」的按估算结算，「已准备」的作废；token 按输入、输出、缓存读取、缓存写入分类保存；时间戳、agent 与模型、token、估算标记、项目与 MR 或分支上下文），日志里没有这些调用；一次分析覆盖多个分支时按改动权重分摊，「审阅」不受 MR 区间限制。每个可能产生改动或切换分支的工具调用（写文件、执行命令）执行之后按工具结果的时间戳，从 worktree 的 HEAD reflog 还原那一刻的分支和 HEAD（不读解析时的当前状态；用文件监听记下的每条 reflog 的亚秒时刻和序号排序，排不出先后时标为「不确定」，按改动内容的去向归属），一次调用里多次切换分支时按调用期间各分支 reflog 新增的提交归属（未提交的改动归调用结束时的分支），每条观察带仓库的稳定标识（git 公共目录、代码平台给仓库的不变 ID，不用会随改名变化的 owner/name），一轮结束后把这些观察连同 cwd、改动路径与按「文件 × 分支观察」记录的改动行数和是否为默认分支写入 SQLite，重建以这份记录为准（之后打开的普通文件夹也能据 cwd 认领以前的用量）；时间窗口按每条用量记录的时间戳、用户本地时区的自然日划分；MR 详情显示自己区间内的用量，共用分支时其中一个关闭后，之后的用量只计入还开着的 MR；Usage 页里统计区间互相重叠的几个 MR 合为一行（同一次使用里先后开出、区间不重叠的 MR 各占一行），只含这些 MR 区间内的用量，区间之外的同一次使用单独显示为未开 MR 的分支，「不属于任何 MR」单独一行，所有项目的列表里有「其他」一行；无法确定分支的旧会话标为「无法归属」。会话和轮次是 MR 之下的明细，一轮被分摊到多个 MR 时，每个 MR 的明细显示分到它的那一份。分摊结果按分数保存，显示时用最大余数法取整，各行相加等于合计；普通文件夹没有分支和 MR 明细，按 agent 和模型的明细照常有。归属规则逐条有 fixtures 覆盖，包括跨 worktree 改动和同名分支复用。
- 去重与解析规则以 ADR 0014 为准（Claude Code 按 `message.id` + `requestId` 去重，Codex 子 agent 只计 `task_started` 之后），每条规则都有 fixtures 覆盖；ccusage 的 `--json` 输出只在测试里做对照。
- 聚合结果写入 Lectern 自己的 SQLite（Claude Code 默认删除 30 天前的会话文件）；statusline 的安装在 `platform`，本 crate 只解析它存下的 JSON。

## 测试

不依赖 GPUI，在任何平台上都能编译和测试：

```sh
cargo check -p lectern-usage     # 只改本 crate 时最快的反馈
just test -p lectern-usage
```

- 单元测试写在模块旁的 `#[cfg(test)] mod tests`；结构化输出（解析结果、归因、diff）用 insta 快照验收，快照改动要在 PR 里逐个看过。
- 真实数据放 `tests/fixtures/`，先脱敏；格式随上游版本变化的，每个版本留一份样本。
